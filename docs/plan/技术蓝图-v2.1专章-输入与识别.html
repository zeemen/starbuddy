密级内部
一摘要

三条原则

原则一：少识别。识别出错的概率接近百分之百，最有效的对策是减少需要识别的内容。题干靠题库匹配而不是 OCR；填空、方程式、辅助线、受力图做成结构化输入；只有学生的手写作答区真正需要识别。

原则二：错误不进学习者模型。识别错误最多让一次批改出错，不能让星误亮或熄灭。所有作答证据按来源分为 A、B、C 三级，只有 A 级（平台内独立作答）能点亮星；低置信度、未确认的证据不写入掌握概率。

原则三：说出不确定。会影响判分的不确定之处，向学生展示"我可能没看清 / 没听清"，请学生确认；不影响判分的不确定不打扰学生。确认次数本身是一个受控指标。

合规前提（沿用 v2.0 第 6、8 章）：国内可商用服务优先，不默认调用境外 API；不满 14 周岁未成年人的个人信息属于敏感个人信息，照片、手写笔迹、语音都按此处理；原始素材最小化保存，不提取声纹，未经监护人单独同意不用于模型训练。

三条通道，一种"作答证据"

2.1 证据等级

等级来源对学习者模型的作用
A平台内独立作答：键盘、点选、画布经回显确认、语音经复述确认更新掌握概率；可参与掌握门槛判定，可点亮星
B拍照题库题，识别高置信或经学生确认更新掌握概率（权重低于 A），更新错因统计；不点亮星，但可触发"去平台内验证这颗星"的任务
C低置信未确认；外部题（题库未匹配）；学生申诉中的条目只展示批改结果，不写入学习者模型

这一分级让"拍照批改"与"星图可信"彻底解耦：拍照是一个方便的入口，但星只认平台内的独立作答。

三拍照通道

八道工序，每一道都可以拒收

图 1 · 拍照通道流水线。蓝色为识别前处理，绿色为"少识别"的关键工序，金色为防止错误级联的两道工序。

3.1 拍摄引导与质量闸门

  • 取景时端侧实时检测清晰度、倾斜、反光与阴影，显示取景框；满足条件自动拍摄。
  • 上传后自动裁切、透视矫正、去阴影；仍不合格的，返回具体原因（"右下角反光""太倾斜"）并请重拍，不在不合格图片上强行识别。
  • 多页作业按页处理，某页不合格只重拍该页。

3.2 题目匹配：题干不靠识别

先用版面特征与印刷体关键词，把整道题匹配到题库（平台题库、南京真题、常用教辅的已授权题目）。匹配成功后，题干、图形、标准答案、Rubric 全部取自题库，图形扭曲、题干模糊的问题在这一步消失，后续只识别作答区。匹配失败的"外部题"照常批改，但证据等级封顶为 C；同一外部题被多名学生上传后，进入题库入库队列，经教研审核后转为题库题。

3.3 作答识别

  • 涂改：检测划线、涂黑、叉号覆盖区域，标为 struck，不参与判分，也不送去校正。
  • 缺损：被遮挡、出框、撕损的区域标为 missing；系统不猜测缺失内容，该步按"未见"处理并提示学生。
  • 公式区：检测为公式的区域走公式专用识别，输出 LaTeX；多行推导按行关联，保留行序。
  • 多引擎：默认单引擎；只对"解答题且低置信度"的区域调用第二引擎交叉比对，两者不一致即视为低置信。不对全量内容双跑。

3.4 约束校正：五条规则

  1. 只改低置信字符。高置信字符一律不动。
  2. 只在视觉易混集合内改。首版集合：1 / 7 / l / I、0 / o / O、2 / z / Z、5 / s / S、x / × / χ、− / = / —、+ / t、6 / b、9 / q / g、· / .、( / 1 / )；化学加入 l / 1（Cl）、0 / O（CO₂）。集合由教研维护，版本化。
  3. 依据上下文，不依据"正确答案"。校正模型看得到题目和学生前后步骤，看不到标准答案。这是防止"把学生的错改成对"最直接的办法。
  4. 原始输出永不覆盖。raw 与 corrected 并存，每一处改动写入 correction_log。
  5. 判分翻转必须确认。若按 raw 与按 corrected 判分结果不同（无论错变对还是对变错），该条目必须请学生确认后才能判分。

3.5 确认策略：只打扰必要的地方

情形处理
高置信，且不影响判分直接判分
低置信，但不影响判分（如过程中与结果无关的笔误）直接判分，报告中该处浅色显示，不请求确认
低置信且影响判分；或判分翻转请学生确认：原图切片与识别结果并排，一键"对 / 改"
单次上传需确认条目 > 3不逐条确认，改为提示重拍该页；连续两次仍超出，该页按 C 级只给参考批改

确认由学生完成，不要求家长参与。另一种确认方式是请学生口头说出这一步（走语音通道的复述确认），这也是苏格拉底式追问的自然入口。

3.6 个人混淆表，而不是个人模型

不为单个用户训练识别模型。学生每次确认中"改"的记录，累计形成一张小表（例：该生的 7 常被识别为 1），作为该生后续识别的先验。表只存字符对与次数，不存图像；学生注销即删除。

4.1 学科键盘

  • 数学：分式、根号（含 n 次）、上下标、绝对值、括号成对、±、≥ ≤ ≠、∠ △ ⊥ ∥ ≌ ∽、π、°、方程组大括号、区间。输入即结构，存储为 LaTeX 与表达式树，判分用符号引擎做等价判定（如 2(x+1) 与 2x+2），不比对字符串；数值题带容差与有效数字规则。
  • 化学：化学式中数字自动下标；离子电荷上标；↑ ↓ △、可逆号、"点燃 / 高温 / 催化剂"等条件写在箭头上方；存为 mhchem，直接送配平与守恒校验器。
  • 物理：数值与单位分开输入，单位从当前题型相关的单位表中选择，送量纲检查；矢量用箭头标记。

4.2 手写画布

  • 采集笔迹矢量（笔顺、时序），按行识别；每写完一行，在行尾实时回显"我读到的是……"，学生当场点改。
  • 提交前全部行都已被学生看过，提交的即是确认后的内容，证据等级为 A。
  • 设备策略：平板 + 笔为主力；手机上的画布只用于一两行的短步骤，长篇证明引导为纸写拍照。

4.3 几何作图：画线即语义

学生在题图（来自题库的矢量图）上作图，端点自动吸附到已有点、边上任意点或交点；新点提示命名。每一笔输出结构化语义，而不是像素：

[{ "op": "connect", "from": "A", "to": "D" },
 { "op": "perpendicular", "through": "A", "to": "BC", "foot": "H" },
 { "op": "parallel", "through": "E", "to": "AB", "meets": "BC", "at": "F" },
 { "op": "midpoint", "of": "BC", "name": "M" },
 { "op": "extend", "segment": "CB", "beyond": "B", "to": "G" }]

声明优先：中考数学答题规范本就要求用文字声明辅助线（"作 AH⊥BC 于 H"）。判分以文字声明为准，作图语义用于校验声明与图是否一致，并驱动讲评时的白板重放。纸面上的辅助线因此无需图形识别，只识别那句声明。

4.4 物理作图：组件，不是手绘

  • 受力分析：力箭头工具，作用点吸附到物体重心或接触点，方向可按 15° 步进或自由，标签从 G / F / N / f / F浮 中选；产出力列表，校验"受力完整、方向正确、作用点正确"。
  • 电路：元件库（电源、开关、灯泡、电阻、滑动变阻器、电流表、电压表），连线吸附到端子；产出网表，送串并联与电表接法规则校验。
  • 光路：面与法线自动生成，入射 / 反射 / 折射光线吸附到入射点；产出角度关系。

组件选型：手写数学识别首选评估 MyScript iink（商业授权；需确认移动端是否端侧识别、授权费用、React Native 原生桥接工作量——须使用 Expo dev client，不能用 Expo Go）。作图与键盘为自研组件，与舞台层白板共用 SVG 渲染与 KaTeX。

五语音通道

级联架构：中间必须有一层文本

老师角色采用"识别 → 文本 → 引擎 / 模型 → 合成"的级联架构，不用端到端语音模型。原因是平台红线：判分可追溯、禁语检测、人设治理、内容审核，全部依赖中间的文本层。端到端实时语音只在阶段 2 以后于点点闲聊、英语自由对话中试点，且保留完整文字记录。

图 2 · 语音通道。金色文本层是不可省略的环节；绿色旁路为英语评测；右下的预合成缓存对应 v1.2 借鉴 OpenMAIC 的"播放态 / 直播态"。

5.1 延迟预算

"即时"定义为：学生说完到听到回应第一个字，p95 ≤ 1.5 秒；说话过程中文字实时出现。

环节预算手段
端点判定400–600ms答题用"按住说话"，松手即结束，省掉这一段；对话用自动检测，思考停顿阈值放宽
识别最终结果100–200ms流式识别，部分结果实时上屏
模型首字300–700ms快模型先从审核短句库选一句接话（不即兴生成），强模型随后接讲解

5.2 准确：热词、归一、复述

  • 热词：从知识图谱按"学科 × 当前章节"导出术语表（勾股定理、欧姆定律、摩尔质量、《孟子》人名等），会话开始时注入识别服务；热词表随图谱版本发布。
  • 口述数学归一：规则优先、模型兜底，把口语表达转为 LaTeX；转换后的式子上屏展示。
  • 复述确认：会被判分的口头答案，一律复述确认（"你说的是 x=3，对吗？"），确认后证据等级为 A；闲聊与提问不复述。

5.4 英语口语评测：先对齐考场口径

  1. 查清南京听说考试所用的评测技术供应商，优先接入同一家；平台给的分与考场给的分偏差最小，是这一科最硬的可信度。
  2. 朗读、跟读：发音评测接口，要求音素级错误定位。
  3. 情景问答、话题简述：转写后按采分点 Rubric 评内容（方法同知行），叠加评测接口的发音与流利度分。
  4. 校准研究：用南京题型的真实学生录音，由两位英语教师与引擎三方独立评分，计算一致性后再上线评分；不达标的题型只给练习反馈，不给分数。
  5. 开口成章现有的 Gemini 对话链路经模型路由保留，评测引擎单独接入国内服务。

5.5 语音合成与角色声音

国内流式合成服务。七位老师与点点各有一套声音设定，写入《角色视觉家族规范》的"声"层（与线、形、色、动并列）；更换供应商时以同一试音文本做 A/B 对比，保证角色声音一致。英语示范朗读单独选用母语级音色。

八验收

先建样本集，再定门槛

厂商公布的准确率不能代表南京初中生的作业本。阶段 0 须建立南京真实作业样本集（授权采集，覆盖七科、光线、角度、潦草、涂改、缺损、公式与作图）和学生录音样本集（普通话与英语、家庭环境噪声），所有选型与版本升级都在同一样本集上回归。

需要拍板的五件事

  1. 拍照批改是否对免费用户开放。OCR 与视觉模型成本在各类调用中最高，需与五级会员的上传次数额度一并定。
  2. B 级证据的权重：拍照证据对掌握概率的影响系数，建议由数学先定经验值，样本集验证后调整。
  3. MyScript 是否采购：取决于授权报价与 RN 桥接工作量；备选是自研画布 + 渲染成图后送公式识别（损失笔顺信息）。
  4. 作业原图保存期限：30 天为建议值，需法务确认。
  5. 样本集的采集方式：合作学校授权采集，或招募试点家庭，需要监护人同意书模板。

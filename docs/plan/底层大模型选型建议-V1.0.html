结论先行：StarBuddy 不应押注"一个最强模型"，而应按任务分层选型、双云部署、用验证器兜底。生产环境只使用境内已备案的大模型服务；首期以 API 调用 + 应用登记上线、不做微调；判分类任务的正确性由规则验证器和交叉复核保证，而不是寄托于某一家模型的能力。

主平台阿里云百炼

千问 Qwen3.8 全家（Max / Flash / Omni 实时语音）＋ 托管 DeepSeek ＋ 向量、ASR、内容安全，一份合同覆盖大部分任务。

豆包 2.1 Pro / Turbo ＋ 豆包语音全套（实时语音、TTS 2.0、声音复刻）＋ 托管 DeepSeek，承担语音与容灾。

01硬约束：先划掉不能用的

约束来源对选型的影响
备案与登记《生成式人工智能服务管理暂行办法》：直接调用已备案模型能力的应用，由地方网信办登记；上线后须在显著位置公示所用模型名称与备案号 / 上线编号只能调用境内已备案的模型服务；首期走"登记"路径（周期明显短于"备案"）；APP 与网站设置"AI 服务信息公示"页
未成年人个人信息不出境个人信息保护法、未成年人网络保护条例；蓝图 V2.0 合规章节境外 API 在生产链路中出局；模型服务区域选境内（如华北 2 北京）
拟人化互动《人工智能拟人化互动服务管理暂行办法》，2026 年 7 月 15 日起施行七位 AI 老师与点点都有人格化设定，需按此办法做服务属性自查：禁止向未成年人提供虚拟亲密关系；不满 14 周岁须监护人同意；须有未成年人模式、使用时长提醒、防沉迷与情感依赖识别。模型要能稳定守住人设边界，这是人设类任务的首要评测项
不微调（首期）对模型做实质性训练优化会从"登记"转为"备案"路径，审查更重、周期更长首期能力全部靠提示工程、知识库检索（RAG）、规则验证器实现；自部署开源模型与微调放到第二阶段评估
判分可追溯蓝图 V2.0：讲解不能覆盖验证器或 Rubric 结果数学、物理、化学判分必须有符号计算验证；作文判分须多次采样 + 校准，不能单次调用定分

02任务分层与模型推荐（核心表）

StarBuddy 的 AI 调用可分成九类任务，它们对"智能、速度、价格、稳定性"的要求差别很大。每类只给主选 + 备选两个模型，主备分属不同厂商或不同平台，便于容灾。

#任务关键要求主选备选兜底 / 验证
T1AI 老师教学对话
讲解、苏格拉底式追问、错因引导		中文表达、指令遵循、人设稳定、流式首字快、价格低（调用量最大）Qwen3.8-Flash（非思考模式）豆包 2.1 Turbo人设回归测试集；需要推理时升级到 T2
T2解题与判分推理
数学、物理、化学计算与推导		推理正确率优先，延迟可放宽Qwen3.8-Max（思考模式，按难度调推理强度）DeepSeek V4.1-Flash（思考模式）SymPy / 几何规则验证器定分；模考判分主备双模型交叉，不一致转人工复核
T3拍照识题与手写识别
错题、试卷、手写作答		公式、图形、手写体识别；版面理解Qwen3.8-Flash（原生多模态）DeepSeek V4.1-Flash（原生视觉）专用 OCR 模型作兜底候选；识别置信度低时请学生确认题面

朗读、情景问答、复述		音素级发音、流利度、与中考听说口径一致科大讯飞语音评测—大模型只负责评语与改进建议，不负责打分
T6语音交互
识别、合成、实时对话		七位老师 + 点点的专属音色；低延迟识别：豆包 Seed-ASR；合成：豆包 Seed-TTS 2.0（配声音复刻 2.0 定制角色音色）百炼语音识别与合成教学场景用"识别 → 大模型 → 合成"三段式，可控可审；端到端实时语音（豆包实时语音 / qwen3.8-omni-flash-realtime）只用于英语口语陪练与点点闲聊
T7知识库检索
向量化与重排		中文教材与题目语义匹配；版本长期稳定百炼文本向量模型 + 重排模型豆包 Seed-Embedding（支持图文）向量模型一经选定即锁版本，更换需全量重建索引，不做主备切换
T8后台批量生产
变式题、预生成讲解、题目标注、知识图谱		价格最低，可离线、可夜间DeepSeek V4.1-Flash（闲时价格 + 上下文缓存）Qwen3.8-Flash 批量调用全部产出进入教研审核流水线，未审核内容不出现在学生端
T9内容安全与人设守卫输入输出审核；危机信号识别；情感依赖识别平台内容安全服务（与主平台同云）+ 自建规则与关键词库另一云的内容安全服务危机信号直接转人工与监护人通知流程，不交给模型自由回应
为什么点点不单独用"更聪明"的模型？点点是调用频次最高、最需要守边界的角色。拟人化办法要求避免过度迎合、诱导情感依赖，这更依赖人设提示、守卫规则和回归测试，而不是模型的智力上限。所以点点跑 T1 档的快速模型，外面套 T9 守卫。

03双云策略与模型路由

之所以选百炼 + 方舟，还有一个工程上的好处：两家都托管 DeepSeek。同一个模型在两朵云上都可调用，一家限流或故障时可以切到另一家，而输出口径不变，回归测试不用重跑。

    R --> L[调用账本
任务 · 模型版本 · token · 成本 · 学生权益扣减]
  • 路由按任务，不按学科：学科插件只声明"我要一次 T2 推理"，由路由层决定调用哪个模型、哪个版本。换模型只改路由配置。
  • 锁定快照版本：生产只调用带日期的快照模型名（如千问的日期快照），不调用会自动漂移的"最新版"别名。模型升级走"评测集回归 → 灰度 5% → 全量"。
  • 调用账本：每次调用记录模型、版本、token、成本，并关联到《用户系统规格书》的 usage_ledger。这样才能按会员档位核算单位经济。
  • 各档会员同一教学质量：路由不按会员等级给不同的判分模型。Max 用户多的是服务量，不是"更准的模型"。

04成本量级估算

以 T1 主力模型 Qwen3.8-Flash 当前公开价（输入约 0.8 元 / 百万 token、输出约 2.7 元 / 百万 token）粗算。以下假设均为估算口径，需用真实会话替换：

项目假设每小时有效学时成本
T1 教学对话每小时约 120 轮；每轮输入 6k token（系统提示 + 知识库 + 历史，其中约 80% 命中缓存），输出 400 token约 0.3 元
T2 推理判分约占调用量 15%，思考模式输出量为 T1 的 5–10 倍约 0.3–0.8 元
T6 语音合成取决于语音占比与音色计费方式待实测，可能是最大单项
合计（不含语音）约 0.6–1.1 元 / 小时

按《用户系统规格书》额度换算，Plus 档每月 20 小时，文本类模型成本约 12–22 元 / 学生；Max 档 66 小时的公平使用上限约 40–75 元。这意味着模型费用不太可能是单位经济的主要矛盾，语音、教研审核与获客成本更值得盯。价格近几个月变动频繁（涨降都有），估算每季度更新一次。

阶段模型使用方式合规动作备注
0 基座（现在起）API 调用已备案模型；无微调算法备案 + 生成式 AI 应用登记同步启动；拟人化服务属性自查；AI 服务信息公示页登记周期以月计，应与开发并行启动，不要等产品做完再办

2 规模化（约 50 万用户后）评估自部署开源模型（Qwen3.8-27B、DeepSeek V4.1-Flash 等开放权重模型）以降本；评估针对南京考情的微调自部署或微调后对外服务，需评估是否转为自行大模型备案届时用阶段 1 积累的真实数据判断是否值得

06现有四科从 Anthropic API 迁移

文砺、阿鸦、知行、开口成章目前在开发测试阶段使用 Anthropic API（英语另有 Google AI 链路）。迁移原则仍是蓝图的"不重写、适配接入"：

  1. 接口层：各产品的模型调用统一改为调路由层。Qwen3.8-Flash 同时兼容 OpenAI 与 Anthropic 接口协议，现有基于 Anthropic SDK 的调用代码可以先以最小改动接到百炼，降低切换门槛。
  2. 提示词层：为 Claude 调好的提示词不一定在千问、豆包上等效。每个老师的人设提示与判分提示，都要在新模型上用评测集重跑并调整，这是迁移的主要工作量。
  3. 开发工具链不受影响：Claude Code 继续作为开发工具使用，这与生产环境调用哪个模型是两回事。
  4. 数据与部署同步迁移：模型换到境内后，学生数据若仍存放在境外托管的数据库与服务上，数据出境问题依然存在。生产环境的数据库、对象存储与后端服务也需要部署在境内云。

07用数据定型：南京中考评测集

本文的"主选"是基于公开信息的初始推荐，最终选型要用自己的评测集定。国产模型迭代以月计，公开榜单与教学场景之间的差距很大，只有自己的评测集能回答"哪个模型判南京中考作文最准"。

评测集规模（建议）衡量指标
判分一致性每科 200 份真实作答，含人工阅卷分与人工分的一致率、平均分差、极端误判数
解题正确率数理化各 300 题，覆盖南京中考难度结构最终答案正确率、过程正确率（验证器判定）
拍照识题500 张真实学生拍摄（含手写、倾斜、阴影）题面还原准确率、公式识别准确率
人设与安全每位老师与点点各 100 条对抗对话人设漂移率、越界率（含亲密关系、依赖诱导）、危机信号识别率
体验与成本真实会话回放首字延迟 p95、每小时成本

第一轮建议每类任务比较 3 个候选（本表主选、备选，再加一个 GLM 或 Kimi 系列模型作为对照），两周内出结论。此后每次模型升级都跑这套回归。

08待拍板决策

  1. 主平台选百炼还是方舟？本文推荐百炼为主（千问全家 + 托管 DeepSeek），方舟为辅（语音强项）。若语音在产品中占比很高，可反过来。
  2. 英语口语评测是否采购讯飞？它的打分口径最接近中考，但有采购成本与商务谈判周期；替代方案是用通用语音模型自建，打分可信度会明显下降。
  3. 七位老师与点点的音色：用平台预置音色，还是用声音复刻定制专属音色（涉及配音演员授权）。
  4. 算法备案与应用登记的启动时间：建议本月即启动，与阶段 0 开发并行。
  5. 数据与后端迁移境内：现有境外托管的数据库与服务的迁移时点，需在第一个真实学生注册前完成。

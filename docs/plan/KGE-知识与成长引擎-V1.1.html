〇结论

六条决断

二十份方案在大方向上高度一致：课标为锚、多版本投影、图谱引导检索、题目与作答分离、审核后才成长。分歧集中在存储选型、粒度、层级数、检索方式和更新节奏上。本文逐项裁定，并把三科已有的知识资产接进同一副骨架。

  1. 建"知识与成长引擎"（KGE），不另起一个知识库产品它是蓝图 V2.0 中"学习者模型 / 诊断 / 内容检索"三块共享引擎的具体实现，七科与点点共用。上线测试前不追求"完整的动态成长系统"，而是建一个范围收窄、成长通道已经接好的最小引擎，带着它进入封测；成长本身在测试中发生。
  2. 一副骨架、四层内容、一个个人层知识地图骨架负责 ID、关系、投影与版本；内容按原始层 → 原子层 → 编译层 → 服务层组织。借用 LLM Wiki 的"编译"思路，但做四项改造：原子为准、页面为用、骨架定结构、教研控发布。
  3. 知识地图分三种学科型，不让语文、道法照搬数学结构型（数学、物理、化学）用前置依赖 DAG；能力阶梯＋素材型（语文、英语）用能力节点加独立素材网；观点定位型（道法、历史）用"大概念 → 观点 → 教材原句投影"加采分点。
  4. 三科既有资产映射接入，不重写阿鸦的知识图谱做数学主干，100 能力点降为能力视图；文砺 28 点下钻为"能力×文本类型×题型"，85 篇必背等素材独立成网；知行的采分点 Rubric 直接成为原子层核心资产，30 个大概念下钻为观点节点。检查发现的 21 项问题见第七章。
  5. 沿用现有技术栈，首期不引入专用图库、向量库和流式计算Supabase Postgres + pgvector + Storage、Python Worker、Git 页面仓库即可支撑单学科数千节点的规模；Neo4j、Milvus、Elasticsearch、Flink 只在出现可测量瓶颈时引入。学生数据生产环境部署境内。
  6. 30 周、15 个双周冲刺，按门验收第 8 周数学切片底座验收，第 12 周三科切片达到封测准入，第 18 周形成内测结论，第 28 周成长机制常态化后进入公测准入评审。周数是估算，是否过门以指标为准。

分歧与裁定

议题各方案主张裁定理由
图谱存储Neo4j（dp、gpt）、NebulaGraph（qw、docx、db）、Postgres 关系表（cc、中台、gpt V2）Postgres单学科节点在数千量级，前置追溯用递归查询足够；图、题、画像同库便于事务与行级隔离。多跳查询 p95 超标时再引入 Neo4j。
向量检索Milvus（qw、docx、db、gg）、pgvector（cc、中台、gpt V2、蓝图）pgvector向量只用于知识点识别、相似题与兜底检索（第四章），不是主检索路径，规模不需要独立向量库。
检索方式切块 RAG（多数）、GraphRAG（gpt V2、ds、gg、dp）、LLM Wiki 页面（cc v1.1、ds）页面优先讲解、方法、易错、考情是高复用综合知识，预编译为审核过的页面，讲法一致、可审、可缓存。原子补充事实，向量兜底。
知识点粒度一节课 40–45 分钟（dp）、10–20 分钟可讲清（cc）10–20 分钟与蓝图"每次 10–20 分钟微闭环"一致；40 分钟单元内错因不同质，诊断无法指导行动。
层级数四层（dp、docx）、五层（中台）、六级 L1–L6（gpt）四层 + 细目领域 → 主题/单元 → 知识节点 → 细目。gpt 的 L6"技能"大多是同一知识点的不同掌握层次，用认知层次表达，不另建节点。
认知层次Bloom 六级（docx）、课标行为动词四级（cc）、阿鸦能力五层级课标四级知道 / 理解 / 运用 / 综合，与课标"了解、理解、掌握、运用"一一对应，教研可直接判定。Bloom 高三级在初中题目上难以稳定区分。
地图更新节奏Flink/Kafka 分钟级更新边权（qw）、定期版本发布（cc、gpt V2）否决实时改图学生画像可以实时，公共骨架不行。分钟级自动改边权绕过审核闸门，也让同一学生的诊断前后不可比。修订周发、次版本月发、主版本学期发。
个人资料升权学生上传经多人确认后升至 L1 甚至 L0（qw）否决只有去标识化的题目经审核后可进入原子层；作答、笔记、错因记录永不进入公共层。群体数据只以聚合统计回流，且设最小人数门槛。
主要信号入口拍照上传试卷为主（多数方案）原生测评为主文砺已在实践中验证整卷 OCR 不够可靠，改为原生自适应测评为主、结构化自报为辅、单题拍照带置信门为第三通道。平台沿用这一结论。
上传贡献换积分docx暂缓涉及未成年人激励与试卷版权，待法律意见后再议。
用户修正每周自动微调 OCRdocx暂缓训练数据含学生笔迹，需单独授权与合规评估；先用第三方 OCR 加人工核对。
深度知识追踪（DKT）gg暂缓起步用可解释的规则加简化 BKT，数据足够后试点 IRT；DKT 只在预测明显更准且仍能给证据解释时评估。
二总体架构

一副骨架、四层内容、一个个人层

六条设计原则

原则含义与约束
题目与作答分离一张上传试卷拆成试卷、题目、作答三类实体。前两类去标识、审核后可复用；作答只属于学生本人。知识库只在题目层成长，画像只在作答层成长。
原子为准，页面为用判分与诊断依据来自原子层；讲解与理解的载体是编译页。两者冲突以原子为准。页面可以重建，这是纠错与回滚的底线；重建分两种，见第四章。
骨架定结构节点 ID、关系、投影、版本只由骨架维护。页面挂在节点上，"前置与后续""在你的教材中""地区考情"等结构段由系统渲染，模型只写叙述段。
成长必经闸门自动化负责发现与提议，人负责确认与发布。新题入原子层、新节点入骨架、关系调整都走"候选 → 证据包 → 审核 → 版本发布"。
结论可追溯每个掌握判断、每条建议都能追溯到具体题目、步骤、时间与地图版本。系统必须能回答"为什么你认为我的二次函数薄弱"。
讲解不覆盖判分继承蓝图与角色规范：老师人设只包装呈现，对错来自验证器或 Rubric，掌握与星亮只由引擎判定。
三知识地图

统一骨架，三种学科型

所有学科共用同一套节点表、关系表、投影表和版本机制；差别在于每科以哪类节点作为诊断主单元，以及用哪些关系组织它们。

层级与节点类型

层级统一为 学科 → 领域 → 主题/单元 → 知识节点 → 细目。知识节点是诊断主单元，进入掌握度计算；领域与主题由下层聚合得出，用于导航和报告；细目只作证据标签（例如"平移时 h 的符号判断"），通常由易错点承担，不单独计算掌握度。

节点类型说明主要学科是否计掌握度
知识点 kp概念、法则或可操作技能；10–20 分钟可讲清数学、物理、化学是（× 认知层次）
能力点 ability_kp能力 × 文本类型 × 题型，如"记叙文中人物形象分析"语文、英语是（× 认知层次）
观点 viewpoint教材中可被引用作答的核心观点，绑定教材原句投影道法、历史是（× 认知层次）
素材 material必背篇目、文言实词虚词、字音字形、名著要素、词汇语文、英语用记忆曲线单独追踪
方法 method跨知识点复用的思想方法，如配方法、数形结合、证据定位全部否，记录迁移证据
易错 pitfall必须写"在作答中表现为什么样子"的识别特征，并标注错因类型全部否，作为错因证据
考点 exam_point综合题的组合考法，关联多个已有节点；不为综合题新建知识点全部否，用于出题与考情

三根轴，不能混用

此前三科各自发明了"层级""梯度""门槛"，名称重叠（数学里"理解""迁移"同时出现在能力五层级和五道门槛里）。最终方案把它们拆成三根独立的轴：

轴描述的对象取值用途
认知层次题目与节点要求知道 · 理解 · 运用 · 综合（对应课标动词）打标、出题递进；诊断单元是"节点 × 层次"
掌握状态某学生在某节点上理解 → 执行 → 稳定 → 迁移 → 保持（五道门槛）星亮 = 进入"迁移"；门槛条件由各科教研配置
能力视图学科能力坐标阿鸦 100 点、文砺 28 点、知行五维等（skill_node）由节点证据按标签聚合；星图与家长报告的呈现层

粒度与边界规则

候选节点逐条过六条标准：可独立诊断（能出至少 3 道以它为主考点的题）、可独立教学（10–20 分钟讲清）、有明确分界、错因同质、证据可支撑（学习期间自然产生不少于 5 次作答）、教师共识。前三条定性必过，后三条用试标注与数据校验。每个节点入库必须写清包含什么、不包含什么、典型题例。

先问"这是不是同一知识的不同掌握程度"，是就用认知层次表达，不拆节点。前置关系用必要性检验（不会 A 是否一定做不对 B 的某一步），只连直接前置，传递关系由图计算。每个节点标注范围属性：课标必修、课标选学、版本拓展、考情拓展、拓展提高；拓展提高默认不出现在学习计划和出题中。

四知识库

原子层与编译层

原子层存"经过校验的事实"，编译层存"组织好的讲法"。题库留在原子层，因为数量大、需要精确过滤；讲解、方法、易错、考情这些综合知识编译成页面，替代此前方案中"讲解库、方法库、易错库、考情库"四个切块检索分区。

页面体系

页面挂载节点编译来源主要读者
知识点页kp / ability_kp课标条目、教材投影、例题、评分点、考情统计讲解、错题精解、出题

每个页面有三种段落：锁定段（定义、课标要求，教研确认后重编不可改写）、渲染段（前置与后续、教材位置与教材原句、地区权重，由骨架和投影生成）、叙述段（讲解要点、类比、高频设问与答题结构，由模型编译、教研审核）。一个页面服务所有版本与地区，读取时按学生的教材和地区渲染视图，而不是为每个版本各编一份。

V1.1 修订 · 教材原句不锁在页面里。教材原句与页码随版次和印次变化，一律存在教材投影表，按学生所用版次渲染进页面。锁定与核对发生在投影记录上（quote_text + verified_by），而不是页面正文。道法观点页因此可以跨版次复用，换版只需更新投影。

V1.1 修订 · 页面人设中立。同一个页面会被阿鸦、妙笔、点点、方圆等不同角色读取。页面一律使用中性的教研口吻，不写任何角色的比喻体系、口头禅或称呼；人设话术只在讲解生成时由各角色的外层加上。编纂规范中的文风规则只约束适龄性（用词、句长、禁用表述），不引用角色规范。

审核界面的核心是差异对比：教研看到的是"改了哪几句、依据哪些新原子、体检结果如何"，不是整页新稿。

检索路径

① 识别节点（规则 + 向量）→ ② 读已发布页面，按教材与地区渲染 → ③ 沿骨架扩展前置、方法、易错页 → ④ 按需查原子（题目族、评分点、采分点）→ ⑤ 读学情档案页 → 生成带页面与原子引用的回答。所有检索都先经过"学科 + 教材版本 + 年级 + 地区 + 地图版本 + 权限"结构化过滤。向量检索只用于第①步和找不到页面时兜底，兜底命中记为"应补页面"信号进入编入队列。

不回写查询结果。原始 LLM Wiki 会把查询答案存成新页面；本方案中学生对话与 Agent 回答一律不写入公共层，只以"兜底命中""诊断不准确反馈"等信号进入编入队列，由教研决定是否补页。

证据、掌握与学情档案

学习事件

所有影响画像的行为统一为不可覆盖的学习事件（evidence_event），记录题目版本、地图版本、步骤级判定、错因、提示等级、耗时和来源。画像由事件计算得出，模型升级后可重放重算。事件区分四类证据：独立答对、提示后答对、迁移成功（同题目族跨情境或跨章）、延迟复测；来源权重为正式考试 > 平台诊断 > 日常练习 > 对话表现，作为参数上线后校准。

学情档案页

每个学生每科一页，内容包括当前阶段、已稳定掌握、正在攻克、根因线索、最近进步、下一步。它是《学生洞察引擎》判断账本的可读视图，自身不产生新结论。V1.1 对它的生成方式做了三项修订：

修订做法原因
模板渲染为主每条结论句由判断账本中的判断按模板直接生成；模型只负责排序、分组与衔接语，不写结论自由撰写可能"引用了但写歪了"，把"尚不稳定"写成"不会"，或夹带语气推断
引用判断 ID每条陈述引用判断 ID（判断再引用证据），不直接引用证据事件与洞察引擎统一，一处可追溯、可撤回
惰性编译会话开始时若档案页落后于判断账本才重编；周报生成时编一次；两次之间 Agent 直接读判断账本的上下文包按每次作答触发重编，成本与规模不匹配，且大部分重编无人读取

体检增加"陈述—判断一致性"检查：逐句比对衔接语与所引判断的状态和数值，出现程度升级（如"不稳定"变"薄弱"）或新增结论即阻断。只写学习事实，不写性格、情绪、家庭推断，不写"你不擅长数学"式的定性判断。Agent 读完整版，学生看到"星图旁的成长手记"，家长看到蓝图规定的证据与建议视图。档案页只存在数据库个人层，永不进入 Git 页面仓库，编译只用境内已备案模型。

知识服务接口

各科 Agent 与点点只通过知识服务访问知识，不直连数据库。知识服务同时以 MCP 工具暴露给编排层，并作为蓝图"统一学科插件 API"的下层依赖。

工具返回被哪个插件方法使用
node.resolve(text | image)候选节点 + 置信度diagnose、grade
node.get(id, edition, region)节点、投影视图、范围属性teach、plan
node.path(id, direction)前置链 / 后续链（仅强前置）diagnose、plan
page.get(id, view)已发布页面，按学生教材与地区渲染teach、report
item.search / item.similar审核过的题目、题目族变式generate_variation、plan
rubric.get(item_id)评分点 / 采分点结构 + 版本grade
evidence.write(event)事件 ID（画像由成长引擎计算，Agent 不直接改掌握度）grade、teach
mastery.get / mastery.explain掌握状态与证据链plan、report、点点复盘

所有返回统一带 result · evidence_ids · confidence · source_version · model_version · human_review_required，与融合方案一致；human_review_required 为真时进入共用的教研复核队列。

部署与数据流向

开发环境沿用 Supabase、Railway、Vercel，只放公共知识、合成数据和授权样本。内测与生产部署在境内云。公共知识从构建环境经版本发布单向同步到生产；生产中的个人数据不回流开发环境，聚合统计以脱敏报表回流教研。

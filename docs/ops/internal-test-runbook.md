## 0. 开放前的前置条件

逐项打勾，缺一项不开放：

1. 迁移 0058、0059 已在副本演练并在主实例执行（`deploy/runbooks/staging-first-deploy.md` 第 3 节；0059 是草稿，必停项，须人批准）。
2. 合规顾问提供的同意书与隐私政策文本已定稿，版本号已登记到 BFF 的 `BFF_CONSENT_VERSIONS` 与前端的
   `STARBUDDY_CONSENT_VERSION_PRIVACY` / `STARBUDDY_CONSENT_VERSION_GUARDIAN`（两边一致）。文本须覆盖：学生也可以提交问题反馈、反馈文本
   只用于处理问题、退出后数据保留到测试结束统一删除（spec 决定记录第 2、3 条）。
3. 开关：BFF、前端的 `STARBUDDY_INTERNAL_TEST` 与审核台后端的 `REVIEW_CONSOLE_INTERNAL_TEST` **三处一起**设为 `internal_test`，并改
   `deploy/flags/staging.yaml`（去掉 `migration_0059`，`state` 改 `"on"`；另起 PR）。只开一处的后果：前端有入口而 BFF 回 404，或审核台看不到反馈。
4. 白名单 HMAC 密钥文件已在跳板上就位：一行十六进制、与 `BFF_LOG_HMAC_KEY` **同一把**（工具用它核对 BFF 审计文件的哈希链与手机号 HMAC；
   台账里的手机号 HMAC 用从它派生的子密钥 `HMAC(密钥, "starbuddy-internal-test-ledger-v1")` 计算，与日志、审计里的摘要不能互相对照）；
   权限 0600，只放在跳板的加密盘上，不进仓库、不进聊天与工单。
5. 审核台有至少两名在职 staff 账号（值守用），能登录 `/review/feedback`。**待人确认**：目前没有单独的“值守”角色，反馈与退出两页对
   **全部在职 staff** 只读可见（改反馈状态也是全部在职 staff 可做）；两页给的学生指针是 `it-` 开头的独立指针，与复核队列的指针不能互相对照。
   需要只给值守看时，新增角色要走必停流程（权限策略）。
6. 值守表已排好（第 5 节），值守群已建（群里不发号码、验证码、孩子的任何信息）。
7. **真实数据门槛（LT-03 决定记录第 15 条）**：已买 KMS 实例，RDS 已换自建密钥、ACK 已开 Secret 落盘加密，开关矩阵 `internal_test_ops` 的
   `kms_instance` 已解除，并经用户另行确认。没解除之前 staging 只放合成数据：不招募、不发码，家长注册、孩子档案、作答、照片与语音一律不用真人
   （`deploy/runbooks/staging-first-deploy.md` 3.3）。

## 1. 招募口径

对内发布招募时只用下面的口径（措辞由测试负责人定稿，待人确认）：

- **完全自愿**：报名与否、参加多久都由家庭自己决定；不报名、中途退出都不需要说明理由。
- **可随时退出**：家长在孩子页点“退出内部测试”即可（第 6 节）；也可以联系测试负责人代为安排。
- **不影响员工考核**：是否参加、反馈多少、何时退出，与绩效、晋升、评优**没有任何关系**；任何人不得以此询问或施压。
  测试团队不向员工的上级提供参与名单。
- **范围**：staging 测试环境，只开放矩阵里打开的学科与功能；内容可能有错，这正是要请大家反馈的。
- **数据**：只收产品使用中产生的数据（不收摄像头、面部、声纹等）；测试结束统一删除（第 7 节）。孩子与家长的说法分开记录。
- 不对外招募（spec“不做”）；不招募非员工家庭的未成年人。

报名信息（家长手机号、孩子年级）只由测试负责人在跳板上保管，**不进仓库、不进工单、不进值守群**。

## 2. 签署

1. 家长在登录后按产品里的同意流程签署：隐私政策与监护人同意（14 岁以下必须监护人同意）。内测开关打开时，两份都签了才能打开学生模式
   进入学习（BFF 在打开学生模式时核对两份的最新一条都是“同意”，否则回 409 `CONSENT_REQUIRED`）；开关关闭时沿用原规则（只对 14 岁以下
   核对监护人同意，见 `services/bff/openapi/shell.v0.yaml` 的学生模式说明）。
   另有库层处理判据（迁移 0059 `platform.student_processing_allowed`）：没有有效隐私政策同意（14 岁以下另需监护人同意）、已删除或已退出的
   学生，学习服务的写入与模型处理入口一律拒绝、批量任务（掌握对账、判分抽检、中圈指标、周报）跳过——与开关无关，迁移执行后即生效。
2. 版本号与签署时间入库（`platform.consent_record`：同意类型、文本版本、决定、时间；只追加）。核对方法：审核台“退出状态”页之外，
   由 DBA 在只读副本上按学生指针查询（不导出、不截图）。
3. **待人确认**：学生本人单独确认（spec 范围第 2 条“监护人与学生分别确认”）目前没有库与接口支持——同意记录只记家长；
   补上需要新的迁移与接口（必停项），本手册之前先由家长在签署时当面向孩子说明，测试负责人记录“已说明”（不记孩子信息）。

## 3. 发码（白名单固定码）

staging 不发短信；登录用的是管理员一次性下发的固定验证码（白名单条目）。条目文件含号码与码，按密钥对待。

**输出含号码或码的命令（3.1 的 generate、3.2 的 revoke）一律在 `umask 077` 的子 shell 里执行，优先用管道直接导入凭据管家，不落盘。**
下面的 `<导入凭据管家>` 指凭据管家从标准输入读入并覆盖 `BFF_STAGING_OTP_FILE` 对应密钥的命令（按所用凭据管家填写，不在本手册写死）。
确实需要中转文件时用工具的 `--out <新文件>`：只新建不覆盖（文件已存在即拒绝）、强制 0600（不受 umask 影响）；导入后立即删除，
不要用 shell 重定向（`>` 建出的文件权限取决于 umask，且会覆盖已有文件）。

### 3.1 生成一个批次

在跳板机上、仓库根目录执行。号码从标准输入读入（每行一个 E.164，例如 `+8613800000000`），**不要写进任何文件**：

```sh
( umask 077
  node tools/internal-test/src/main.ts generate --batch dec-wave1 --hours 24 \
    --ledger /secure/internal-test/ledger.jsonl --key-file /secure/internal-test/hmac.key \
    --existing /secure/internal-test/current-entries.json --audit /secure/internal-test/bff-otp-audit.jsonl \
  | <导入凭据管家> )
# 不能用管道时：把最后一行换成 --out /dev/shm/new-entries.json（只新建、0600），导入后立即删除该文件
```

- `--hours` 1–24（与 BFF 的 24 小时上限一致）；`--issued-at` 可指定生效时间（必须带时区）。
- `--existing` 是当前生效的条目文件（权限必须 0600）；输出是**合并后**的完整条目文件。`--audit` 是从 BFF 审计卷取回的副本，
  用来避开已经用过或作废过的条目 ID。
- 标准错误只打印条数与窗口；台账追加 `generated` 事件（条目 ID、批次、时间、手机号 HMAC——用派生子密钥算，见第 0 节第 4 条），不含码与号码。
- 导入凭据管家后，BFF 每次签发与核验都会重读条目文件，同步后无需重启。
- 把各自的验证码当面或电话一对一告知家长（不发群、不发邮件）；告诉家长窗口结束时间。
- **待人确认**：`--existing` 指向的“当前条目文件”长期存放在跳板加密盘上（含全部有效号码与码）。是否改为每次从凭据管家临时取出、
  用完即删，由测试负责人与安全负责人决定；决定前至少保证 0600、只在加密盘、不进备份。

### 3.2 作废一个批次

```sh
( umask 077
  node tools/internal-test/src/main.ts revoke --batch dec-wave1 --existing /secure/internal-test/current-entries.json \
    --ledger /secure/internal-test/ledger.jsonl --key-file /secure/internal-test/hmac.key \
  | <导入凭据管家> )
```

输出是去掉该批次后的完整条目文件，同样导入凭据管家（或 `--out` 新文件，同上）；台账追加 `revoked`。作废的条目 ID 永不复用。

**已签发的验证码最多再有效 5 分钟**：作废（工具按批次作废、或家长退出时 BFF 按账号作废）只让条目不再签发；作废之前已经签发出去、
还在库里等待核验的那一次验证码，在它自己的有效期内（`services/bff/config/auth.json` 的 `otp.ttl_seconds`，300 秒）仍可能登录成功。
需要立刻切断时，作废后再等 5 分钟确认没有新的登录，或由 DBA 经必停流程处理。

### 3.3 审计摘要

```sh
node tools/internal-test/src/main.ts summary --ledger /secure/internal-test/ledger.jsonl \
  --audit /secure/internal-test/bff-otp-audit.jsonl --key-file /secure/internal-test/hmac.key --for-ticket
```

输出 JSON：每条只有条目 ID、事件与时间（不加 `--for-ticket` 时另有手机号 HMAC，只在跳板上核对用）。给了密钥时核对 BFF 审计文件的
哈希链（断链即失败；新旧两种审计行——带不带账号摘要 `account_hmac`——都认）。工具作废（台账）与家长退出时 BFF 的作废（审计文件）
都记为 `revoked`，口径相同：该条目不再签发。**贴进工单的只能是 `--for-ticket` 的输出**；号码与码永远不贴。

退出码：0 成功；1 输入或校验失败；2 参数不对。报错只带原因，不带号码与码。

## 4. 测试期间：问题反馈

- 学生（学生壳顶栏）与家长（孩子页）各有“问题反馈”入口：固定分类 + 不超过 500 字的说明，可选附上当前页面类型（只是路由模板）。
  输入框提示“不要填写姓名、电话等个人信息”。不附截图、不采集设备信息。每个账号每天最多 20 条（`services/bff/config/auth.json`，待人确认）。
- 学生的反馈记为“学生自述”，家长的记为“家长观察”，分开存、不合并（规则 6）。反馈文本**只用于处理问题**：不进判断账本、画像与任何
  关于学生的陈述（规则 11、12），不进访问日志、SLS 与指标。
- 值守在审核台 `/review/feedback` 查看（只显示学生的不透明指针），处理时把状态从“新到”改为“已分拣”，修好或答复后改为“已关闭”。
  改状态的人与时间由库记录。
- 反馈里如果出现了姓名、电话等个人信息：值守不得转发、截图；记一个“个人信息误填”的 P2 工单（只写反馈 ID），测试结束随删除流程一并删除。
  需要提前删除的，按第 7 节对该家庭单独走删除流程（待人确认是否需要单条删除的工具）。
- 需要转成研发工单时，只抄分类、页面类型与复现步骤的概括，不抄原文。
- **数据库错误日志**：Postgres 在 CHECK 约束失败时会把“失败的那一行”（`Failing row contains (...)`）写进错误日志，RDS 的错误日志因此
  可能含有反馈原文或其他个人层字段（BFF 先做长度与分类校验，正常请求走不到库的 CHECK，但不能排除）。RDS 错误日志按含个人信息对待：
  只有 DBA 能看，不转发、不导出、不截图；访问范围与留存期限待人确认（与 LT-05 的待人确认同一项）。

### 5.1 告警：退出作废的审计写失败（`StarbuddyStagingOtpRevokeAuditFailed`）

含义：家长退出测试后，BFF 已在内存里作废了这位家长的白名单条目，但写审计文件失败（指标 `starbuddy_staging_otp_revoke_audit_failed_total`，
`deploy/observability/alerts.yaml` 的 `starbuddy-internal-test` 组）。BFF 重启后会从审计文件重放状态，**这次作废会丢失**，条目可能重新可用。
按 P1 处理：

1. 先查审计卷（`BFF_STAGING_OTP_AUDIT_FILE` 所在卷）是否写满、只读或权限被改，修好后确认 BFF 的审计写入恢复（新的登录会写 `issued` / `consumed`）。
2. 在 BFF 重启之前，按第 3.2 节把这位家长所在批次整体作废并导入凭据管家（工具作废写台账、并从条目文件里删掉条目，不依赖 BFF 的审计文件）；
   同批次的其他家长按第 3.1 节重新发码。值守从审核台 `/review/internal-test` 的退出时间对应批次，不按号码查。
3. 用第 3.3 节的摘要核对：该批次的条目都是 `revoked`。工单只写告警时间与批次名。

## 6. 问题分级与响应时限

| 级别 | 判定 | 首次响应 | 处置目标 |
|---|---|---|---|
| P0 | 数据泄露或疑似越权（看到别人家的数据）、判分或掌握结果错误地展示给孩子、禁语或不当内容出现在孩子面前、全站不可用 | 15 分钟 | 1 小时内止损（关开关、下线功能或暂停测试），当天复盘 |
| P1 | 核心功能不可用（登录、今日计划、某科判分）、计量或额度明显错误 | 1 小时 | 当天修复或给出绕行办法 |
| P2 | 部分功能出错、内容有误、显示问题、个人信息误填进反馈 | 当天 | 3 个工作日内 |
| P3 | 卡顿、建议、体验问题 | 2 个工作日 | 排期 |

（时限为默认，待人确认。）P0 先止损再定位：可以由主值守直接把相关开关改回关（`deploy/flags/staging.yaml` 对应项），事后补 PR。
**注意：库里已经有退出记录时，关内测开关不能止损也不会“解除”退出**——迁移 0059 执行后，BFF 的退出守卫（409 `TEST_EXITED`）、学习服务与
洞察服务的处理判据、库里“已退出不能再签同意、不能签发学生会话”的守卫都与开关无关，一直生效；关开关只会去掉反馈与退出的入口。
涉及已退出学生的 P0（例如退出后仍有新数据或仍被处理）只能定位修复，不能靠开关回退。
涉及未成年人安全或心理状况的反馈，按 `docs/personas` 的转介话术由教研负责人处理，值守不自行答复。

## 7. 退出测试

家长随时可以发起：

1. 家长在孩子页点“退出内部测试”，进入确认页，页面列出退出会发生什么；勾选“我已了解”后提交（第二次确认）。
2. 系统在一个事务里：撤回该学生全部仍有效的同意（同意记录追加“撤回”，版本沿用原来那条）、作废孩子账号的全部会话、写一条退出记录，
   并返回需要作废白名单的**家长账号**：该学生的有效绑定家长中，**没有别的在测孩子**（未删除、未退出）的那些（不返回号码或号码摘要）。
   提交成功后 BFF 按账号作废：找到这些账号用固定码登录成功时用过的号码（BFF 在登录成功时把条目与账号对应，记进内存与审计文件的
   `account_hmac`，重启时按同一规则重放），作废这些号码的全部条目（审计记 `revoked`）。重复提交不会重复写。
   - 从没用固定码登录过的家长没有账号对应，不在作废范围内（他名下若有条目，由管理员按第 3.2 节按批次作废）；
   - 还有别的孩子在测试中的家长不作废，可以继续登录照看另一个孩子；
   - 作废之前已签发的那一次验证码最多再有效 5 分钟（第 3.2 节）。
3. 退出之后：BFF 对该档案拒绝一切新写入、读取与触发模型处理的请求（409 `TEST_EXITED`），只保留退出状态、数据查看导出与删除请求；
   学习服务、洞察服务按库层处理判据拒绝或跳过（第 2 节）；库里拒绝为该档案再签“同意”（撤回照常）、拒绝为孩子账号签发新会话，
   孩子不能再打开学生模式。这些守卫在迁移 0059 执行后**与内测开关无关**，关开关不会解除（第 6 节）。
   **已有数据保留到测试结束统一删除**（spec 决定记录第 3 条）。
4. 值守在审核台 `/review/internal-test` 核对：退出时间、撤回的同意类型、“仍有有效同意”应为“否”、作废的会话数。
5. 家长希望立即删除的：在退出后仍可在“数据查看与删除”页直接发起删除请求（第 8 节第 3–5 步），不必等测试结束。
6. **退出的家长可以新建档案**：退出只针对那一个档案；家长（若仍能登录）可以为孩子新建一个档案，新档案没有退出记录，签署后照常处理。
   想重新参加的家庭这样做；不想继续的，值守在答复时说明“退出后请不要新建档案”，并按第 3.2 节作废这位家长剩余的条目。

注意：已退出的档案不能“恢复”——库里没有撤销退出的路径（需要时走必停流程）。

## 8. 测试结束后的数据处置（统一删除）

测试结束日由测试负责人宣布（待人确认）。删除走现有删除流程（迁移 0035），不另写删除脚本、不手工删库。

1. **停止新增**：宣布当天把三处 `internal_test` 开关之外的学习功能按矩阵关闭（或整体暂停测试入口），并停止发放新的白名单条目。
2. **为每个家庭准备一次登录**：退出过的家庭（没有别的在测孩子的家长）白名单条目已作废，按第 3.1 节为每位需要操作的家长生成一个新批次（窗口 ≤ 24 小时，批次名如 `final-erase`），
   一对一告知。
3. **家长发起删除**：家长登录 → 孩子页“数据查看与删除” → 发起删除请求 → 24 小时内二次确认。之后进入 7 天冷静期（可撤回）。
4. **执行**：冷静期满后调度器的 `erasures` 任务调 `platform.execute_due_erasures`：锁住档案、按个人层表清单删除该学生的全部数据
   （含问题反馈 `platform.feedback`）、逐表复核为零、停用学生账号、档案标记已删除、写回执（只有表名与行数）。
   同意记录与退出记录按清单豁免留存（期限待合规确认）。
5. **核对**：在审核台 `/review/internal-test` 看每个退出档案的“删除请求”为“已执行”、“已删除”为“是”；没退出的家庭由 DBA 在只读副本上按回执核对。
6. **收尾**：所有家庭完成后，按第 3.2 节作废 `final-erase` 批次及其余全部批次；生成第 3.3 节审计摘要存档（不含号码与码）；
   跳板上的台账、密钥文件与报名信息按测试负责人的指令销毁，销毁记录写进工单。
7. 联系不上的家长、或不愿登录的家庭：目前没有“管理员代为删除”的入口（删除请求只能由有效绑定家长发起），**待人确认**处置办法（例如由合规顾问认可的线下确认后、经必停流程新增管理员发起的删除路径）。

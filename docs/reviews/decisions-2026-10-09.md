## 二、ADR 01–15：采纳的默认项

编号沿用【评审包】：0 = 总体选项；ADR 09、10 的 #1 即总体选项；ADR 04 分“正文 n”“增补 n”。只列有默认建议的条目；没有默认的条目见第四节。

### ADR 09 · 数据驻留
- #1：采纳选项 C 分环境（pilot 与生产全链路境内；dev、staging 只放合成数据），另加 6 条硬约束；生产与试点“数据不出境（含 L0、L1）”按用户 2026-09-28 的决定执行。
- #4：境内托管选型按 ADR 10 草案：W2 定评估负责人，W4 前定厂商（评估负责人仍需指定）。

### ADR 04 · 模型路由（含 2026-09-28 增补）
- #0：采纳正文选项 A（按数据级别强制路由、统一入口、违规拒绝）与增补 10 条；正文第 2 条“L0、L1 可路由到境外”由增补的“生产与试点不出境”取代（属“按增补修改正文”，正文文字不改）。
- 正文 1：境内首批候选为 DeepSeek、DashScope（仍须先在 `docs/compliance/vendors.md` 登记、签数据处理协议后才能接入）。
- 增补 1：九类任务的主备供应商由技术负责人与产品负责人在白名单流程里定（采纳的是流程，具体厂商未定）。
- 增补 3：任务类型由编排层按插件方法推出，插件不声明（不改插件 API）。

### ADR 10 · 境内托管选型
- #1：采纳选项 B（境内托管 Postgres + 托管对象存储 + 容器服务，认证由 BFF 自建）。
- #2：W2 决策会定评估负责人，W4 前定厂商（负责人仍需指定）。
- #4：dev 是否切到境内托管（选项 C）留到冲刺 2 复核。

### ADR 01 · BFF 与学习服务分工
- #0：采纳选项 A（TS BFF + Python 学习服务；学习者模型只有学习服务能写；适配器独立 HTTP 服务）。
- #3：前端一律经过 BFF，不直调学习服务只读接口。

### ADR 02 · Postgres 共库分 schema
- #0：采纳选项 A（单库分 schema；单一迁移序列、每个迁移只改一个 schema；RLS 归平台）。
- #1：认证方案并入 ADR 10（BFF 自建认证）。
- #4：个人层表留在 `platform.*`。
- #8：insight 增补：学生自述、家长观察、考试记录、建档进度四张表放 `insight.*`。
- 注：kge 增补（#5）、policy 增补（#6）在【评审包】中“无单列默认”，跨 schema 例外（#7）“无默认，需讨论”，三者都列在第四节，**本次未采纳**；对应迁移草稿仍随各自 PR 评审。

### ADR 03 · 编排显式状态机
- #0：采纳选项 A（主流程与涉及判分、计量、写学习者模型的步骤用显式状态机；LangGraph 只限单个状态内部的生成类子任务）。
- #1：队列与 Worker 选型放 ADR 10（阶段 0–1 优先用 Postgres 自带能力）。

### ADR 05 · 事件表分区
- #0：采纳选项 A（证据事件、作答、审计事件、计量流水从第一版按月分区；幂等唯一约束带分区键；冲刺 5 压测后复核粒度）。

### ADR 06 · 计量账本一致性
- #0：采纳选项 A（Postgres 单库事务 + 只追加流水；预留 → 结算 / 释放 / 过期；不分区的幂等表；6 类测试是 Gate 0 硬条件）。
- #1：额度挂在家庭层。
- #3：预留默认过期时间按资源类型处理时长的 2 倍（例如诊断 10 分钟）。
- #4：阶段 1 试点虚拟额度仍全量走账本。

### ADR 07 · OpenMAIC 范围与许可证
- #0：采纳选项 A（只引渲染层包，锁定 MIT 版本 ≥ v0.3.0、建议 v0.3.2 起；不引入 LGPL 的 `mathml2omml`；许可证扫描进 CI）。
- #1：现在签，不因讲评课原型可能后移而推迟。

### ADR 08 · 英语模型与语音链路
- #0：采纳选项 A（境内模型 + 境内语音供应商，语音层归平台；分阶段 0 / 1；点点跨模型一致性改为境内两家以上模型之间）。英语适配器仍处于搁置状态。
- #2：语音适配层做成单独服务。

### ADR 13 · 判断账本唯一写入方
- #0：采纳选项 2（库层强制：只有 `starbuddy_insight` 能写 `insight.claim`；状态机、白名单、只追加历史由触发器与约束保证）。迁移 0010 仍是草稿，演练与执行由人做。
- #4：首批模板（数学“知识掌握”“知识迁移”）由 SIE-02 提交，人审核后登记。
- #5：各类判断的默认有效期由产品与教研在 SIE-02 前给出，写进洞察服务配置。
- #6：渗透测试环境是否加只继承 `starbuddy_insight` 的登录角色，第二轮渗透测试时决定。

### ADR 11 · 星图统一定义
- #0：采纳选项 2（星 = 已发布地图版本里的知识节点；能力坐标只作能力视图；只有 A 级证据能让星亮）。
- #1：能力视图在学生端与家长端都显示为侧栏，只有分布，没有“亮”。
- #2：地图升级时按 `kge.id_migration` 类型：改名、合并继承“亮”；拆分出的新节点重新判定。
- #3：阿鸦能力坐标与知识节点的挂接随 KGE-01 导入阿鸦图谱时由数学教研审核。
- #4：“地图建设中”的学科不显示旧能力坐标星图。
- 注：星图“待验证虚线”以 ADR 13 #2 为准；该项无默认（见第四节），签字前仍不实现虚线。

### ADR 12 · 编译层 Git 试点
- #0：采纳选项 2（单独的境内 Git 仓库；主分支只经合并请求、CI 体检、至少一名教研审核；规模上来后迁入数据库）。

### ADR 15 · 输入通道与作答证据
- #0：采纳选项 2（三条输入通道产出统一的平台侧作答证据；A / B / C 三级；插件 grade 只收归一化内容；第三方识别服务只列准入条件，不选型）。
- #1：合为一份，不拆分。
- #3（部分）：作业原图保存期限按建议 30 天（【评审包】注明需法务确认）；其余素材无默认，见第四节。

### ADR 14 · 任务包与人审点
- #0：采纳选项 1（沿用 `specs/<任务>/`，模板补“输入契约”“禁止修改的范围”两节）。
- #1：人审点以 CLAUDE.md 为准。
- #2：已有 spec 不补两节，只对新任务与改写中的冲刺 4 spec 生效。
- #3：不要求附审查 agent 原始输出，只在 lessons 里记处理结果。
- #4：PR 审批即签字；`[NEEDS-HUMAN]` 的 PR 至少一名对应领域负责人审批。
- #5：数据保存与删除策略、监护人同意书模板、模型路由主备切换、页面仓库分支保护与 CI 变更四类纳入人审点；随 CLAUDE.md 修订另开 PR（CLAUDE.md 由人修订）。

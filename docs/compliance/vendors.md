# 供应商登记（ADR 09 第 6 条、ADR 04 第 3 条、ADR 15）

状态：**草稿**。LT-02（`specs/launch-lt02-model-provider`，决定记录 2026-10-21）起登记两家模型供应商，状态均为“待开通 / 待登记”：
条目由 Claude 按《底层大模型选型建议 V1.0》起草，**开通、协议、备案依据、接入主机名、批准**由合规负责人填写，技术负责人与产品负责人确认
（CLAUDE.md 必停项：新增第三方服务、模型供应商或数据出境路径）。目前**没有任何已批准的真实供应商**。

模型路由（`services/learning/config/model_routes.yaml`）的 staging、pilot、prod 三节只能引用本表里登记的供应商，且两边状态一致
（`services/learning/tests/test_model_router_staging.py` 核对）：

| 路由表 `whitelist` | 本表“状态” |
|---|---|
| `pending` | 待开通 / 待登记、待审 |
| `approved` | 已批准 |
| （不能出现在路由表） | 停用 |

staging、pilot、prod 启动时校验：境内、已批准、锁定快照（带日期或版本号的 `api_name`）、必须登记 `allowed_hosts`、不带占位、主备不同厂商或平台
（`specs/model-router-sprint1/spec.md`，staging 加严到同一口径见 LT-02 决定记录第 3 条）。仓库里的 dev、test 只有本地假供应商。
路由表里已批准供应商的 `allowed_hosts` 必须与本表“允许的主机名”一致（同一组主机名）。

## 其他数据处理方（非模型；不进模型路由表）

LT-05（`specs/launch-lt05-observability`，安全审查 C）起登记监控与日志两项云服务。它们处理的是指标与结构化日志：指标只有白名单内的低基数标签
（服务、路由模板、方法、状态码类别、学科、任务类型、供应商、结果），日志只有登记的元数据字段（字段白名单、集中脱敏；学生与账号只有带密钥
HMAC 截断），不含作答、内容与标识原文——但日志里仍有路由、时间与带密钥哈希，按**个人信息相关的运维数据**从严登记。

# 攻击面清单（家庭隔离 · 第 1 轮 + 第 2 轮）

来源：A–M 类为 `specs/household-pentest-sprint3/spec.md` 第 2 节（第 1 轮）；N–S 类为 `specs/household-pentest-round2/spec.md` 第 2 节（第 2 轮，编号接续，4-H H6 登记）。
编号稳定，报告、`findings.csv`、`coverage.md` 都按编号引用。`docs/security/check_attack_surface.py` 同时读两份 spec 的条目编号。

## 怎么读这张表

- **层**：
  - 1 = 数据库授权层；
  - 2 = 服务间接口；
  - 3 = 用户入口。第 1 轮不测第 3 层，标“第二轮”的条目等 4-H 与 BFF 鉴权实现后再测；4-H H6 起第 3 层的仓库内回归见 N–Q 类
    （`services/bff/tests/route-matrix.integration.test.ts`：授权矩阵从统一路由表按开关全开的完整集合生成）。
- **已有自动化断言**：写法有三种。`docs/security/check_attack_surface.py`（`make check-fast`）会核对每条引用都真实存在，引用失效时检查失败。
  - `ref:路径#片段`：该文件里含这段文字。SQL、TS / JS、Python、shell 文件里，片段必须落在断言消息、测试名或其他字符串字面量里
    （Python 另认 `def` 的函数名），只出现在注释（含文档注释、文档字符串）或普通代码里的不算；其他文件按全文匹配。规则见检查脚本；
  - `mut:名称`：`db/tests/mutations.sh` 里有这个变异，而且 `make check` 证明它会被测试发现；
  - `mut-bff:名称`：同上，对应 `services/bff/tests/mutations.sh`。
- 没有自动化断言的条目，这一列写“无”，并在“渗透测试要做的”一列标“人工”或“第二轮”。
- `db/tests/mutations.sh` 里名字以“攻击面：”开头的变异，只跑 80（在渗透测试夹具上），而且第一条失败的必须是登记的那条 80 断言，证明是 80 本身发现的，不是别的测试或快照先拦下。
- 渗透测试环境里，80 的可见性矩阵与函数越权矩阵还会在扩展夹具上再跑一遍。扩展夹具有 16 个账号，含兄弟姐妹、禁用账号、已解除的绑定、同号的第二账号（`db/pentest/selftest.sh`，`make pentest-env-test`）。
- **已知遗留**：已登记的风险，报告里单列，不重复计为新发现；执行方认为严重度更高时照常分级。

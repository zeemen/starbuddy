## 1. 背景
学生的作答从三条通道进来：拍照（纸上作业）、屏幕（键盘、点选、画布、作图组件）、语音。识别一定会出错，技术蓝图 v2.1 定了三条原则：
- **少识别**：能结构化输入的就不识别；题干靠题库匹配，不靠 OCR；
- **错误不进学习者模型**：识别错误最多让一次批改出错，不能让星误亮或熄灭；
- **说出不确定**：影响判分的不确定之处请学生确认，不影响的不打扰。

仓库现状：
- 插件 API v0.9 的 `GradeRequest` 直接带作答内容（`response` 可以是文本、选项，或原图与转写的对象存储引用 `image_ref`、`transcript_ref`），没有原始输出、校正后内容、校正日志与确认记录；
- `platform.evidence_event.kind` 已有 `ocr_transcription`、`asr_transcription` 等载荷类型，但没有“证据等级”与“输入通道”；
- KGE 的 `evidence_kind`（独立、提示、迁移、延迟复测）说的是作答情境，与证据等级不是一回事（对照文档第七节 #1）。

## 2. 选项
1. **识别结果直接进插件 grade**（现状）：简单；但适配器要接触原图与识别细节，识别错误会直接写进掌握，校正可能“把学生的错改成对”而无从追查。
2. **平台侧统一的作答证据对象，按等级决定是否进入学习者模型**（本 ADR 推荐）：三条通道都产出同一种作答证据；平台保存原始输出与校正记录；插件只收归一化内容；证据等级决定掌握计算怎么用它。
3. **各科适配器各自处理识别**：各科可按题型定制；但七科重复建设，证据口径不一，第三方识别服务的准入与数据驻留要在每科各审一次。

## 3. 决定（待签字）
选项 2。
- **作答证据是平台侧对象**：
  - 由输入通道服务产出与保存：通道（`keypad` / `canvas` / `voice` / `photo`）、题目匹配结果、各区域的原始输出（永不覆盖）与校正后内容、校正日志、置信度、识别引擎与版本、确认记录、证据等级、用途授权范围；
  - 原图与切片只由平台保存；学科适配器不接触原图、切片与校正日志（规则 1、13）。
- **插件 grade 的输入**：只收归一化内容（LaTeX、mhchem、作图语义、数值与量纲等）加 `answer_evidence_ref` 与 `evidence_level`；在 W4 冻结插件 API v1.0 时一起改（svc-#2、svc-#4），现在只登记：v1.0 删除 `response.image_ref` 与 `response.transcript_ref`（适配器不接触原图与转写原件）；svc-#2 默认采用“证据等级与通道由平台补齐”，插件证据草稿不带这些字段。
- **证据等级**：
  - A：平台内独立作答（键盘、点选、画布经回显确认、语音经复述确认），可更新掌握并参与星亮判定（ADR 11）；
  - B：拍照题库题，识别高置信或经学生确认，可更新掌握（权重低于 A），不点亮星；
  - C：低置信未确认、外部题（题库未匹配）、申诉中的条目，只展示批改，不进入学习者模型；
  - 证据等级、KGE 的 `evidence_kind`、题目准入（`admission`）三者并存，互不替代；`evidence_level` 与 `channel` 随冲刺 1-C 与 `evidence_kind` 一起加到证据上（迁移，必停项）；
  - B 级权重属于掌握计算（必停项），由数学教研给经验值，样本集验证后调整，本 ADR 不写数。
- **校正与确认**：
  - 校正只改低置信字符，只在视觉易混集合内改，依据题目与前后步骤、看不到标准答案；
  - 按原始输出与按校正后内容判分结果不同（判分翻转）时，必须请学生确认后才判分；
  - 确认由学生完成，不要求家长参与；确认次数只作体验与识别质量指标，不作为对学生的判断（规则 12）。
- **申诉与重算**：学生对判分提出异议时回溯到识别片段；识别或评分版本出错时可一键停用并重算受影响的证据与报告。
- **第三方识别服务的准入（不选型）**：
  - 所有识别、评测、合成服务经模型路由层接入（ADR 04 增补），按任务配置主备、限流与熔断，返回引擎与版本并写入作答证据；
  - 数据级别：作业照片与切片、画布笔迹与轨迹、语音按 ADR 09 的 L3（敏感个人信息）处理，不满 14 周岁的按未成年人敏感个人信息处理；识别结果、校正日志、个人混淆表按 L2；
  - 处理前提：处理照片、笔迹、语音本身（不只是用于训练）须取得监护人单独同意，并在上线前完成个人信息保护影响评估；同意范围写进作答证据的 `consent_scope`；
  - 准入条件：数据境内处理（含厂商的备份与分发网络）、不留存或限期留存、不用于其训练、不得再委托第三方处理、安全事件通知；
  - 供应商登记：处理 L2、L3 的识别服务按 ADR 09 第 3 节第 6 条在 `docs/compliance/vendors.md`（待建）登记，数据处理协议签好之前不能接入；
  - 选型只用南京真实作业样本集与学生录音样本集比较，不以厂商宣称指标为准；样本集需授权采集，是人的工作；
  - 选型评测本身就是把 L3 数据交给厂商：评测阶段同样要满足上述准入条件、协议与同意书范围；样本集由人保管，不进本仓，也不进任何测试夹具（规则 8）；
  - 候选（技术蓝图 v2.1 第六章）只作登记，任何一家接入前都要另起 PR 并经人确认（新增第三方服务，必停项）；英语口语评测随英语搁置（对照文档 #1）。
- **原始素材的保存**：按技术蓝图 v2.1 第七章的建议值起草，法务确认保存期限前不建相关表；个人混淆表属于个人层，放 `platform.*`，注销即删；所有素材不用于训练，除非取得监护人单独同意（并入 ADR 09 补充与对照文档待决 #6）。

## 4. 后果
- 好处：
  - 识别错误被证据等级挡在学习者模型之外，星图可信与拍照批改解耦；
  - 适配器只面对归一化内容，七科不用各自处理识别；第三方服务只需审一次；
  - 原始输出与校正日志并存，“这题判错了”可以追到识别片段。
- 代价：
  - 插件 API v1.0 的 `GradeRequest` 要改，四科适配器随之调整；
  - 平台要建输入通道服务、样本集与申诉重算流程，开发计划 v2.0 的上传通道原排在冲刺 5（KGE-05），v2.1 把部分工作提到阶段 0，排期需人确认（对照文档第七节 #12）；
  - 拍照批改的单位成本较高，是否对免费用户开放要与会员额度一起定（技术蓝图 v2.1 待决 1）。
- 需要同步的地方：插件 API v1.0 冻结 spec、冲刺 1-C 证据加列 spec、KGE-04 掌握 spec、计量与权益 spec v2（拍照额度）、ADR 09 补充（保存期限）。

## 5. 待人确认
1. 本 ADR 是否拆成“输入通道架构”与“第三方识别服务准入”两份：起草按默认合为一份，签字时定。
2. B 级证据权重的经验值：数学教研给出（技术蓝图 v2.1 待决 2）。
3. 原始素材保存期限（作业原图建议 30 天）：法务确认（v2.1 待决 4；与规格书 V1.2 的冲突见对照文档第八节 #8）；语音、画布笔迹、识别切片、识别原始输出与校正日志的保存期限一并确认。
4. 手写画布是否采购商业识别组件：取决于授权报价与移动端桥接工作量（v2.1 待决 3）。
5. 拍照批改是否对免费用户开放、额度多少：随计量与权益 spec v2 定（v2.1 待决 1）。
6. 阶段 0 是否提前做拍摄引导、质量闸门与题目匹配（对照文档第七节 #12）。
7. 两个样本集的采集方式（合作学校授权或招募试点家庭）与监护人同意书模板（v2.1 待决 5）。
8. 监护人单独同意书与个人信息保护影响评估由谁出具、何时完成（合规顾问）。

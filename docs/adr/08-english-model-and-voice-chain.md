# ADR 08 · 英语模型与语音链路的接入方式

- 状态：**草稿，待签字**
- 日期：2026-09-25
- 决策人：待定（建议：产品负责人；技术负责人、合规顾问会签）
- 关联：完整方案 v1.0 第 5.1、5.6、5.8、5.9 节；开发计划 冲刺 3-D、冲刺 2–4-I；七项待拍板第 5 项；ADR 04、06、09
- 来源：echo decisions #1、#4、#7、#9、A1、A3；echo inventory §0、§4、§5；echo adapter-design §1、§4

> [NEEDS-HUMAN] 本 ADR 涉及新增 ASR / TTS / 发音评测供应商和语音数据的出境路径，属于必停项。
>
> **标题已改**：开发计划原定标题是“英语保留 Gemini 链路的接入方式”。盘点确认英语没有 Gemini 链路（echo decisions #1），这个前提不成立，所以标题和内容一起重写。

---

## 1. 背景

### 1.1 原来的前提
完整方案 5.1、5.2 写的是：英语“以 Google AI（Gemini）开发；实时语音链（流式 ASR → LLM → 流式 TTS）；第三方音素级评测”，并且“通过模型路由接入，不强制迁移；点点人设层的跨模型一致性是前提验证项”。七项待拍板的第 5 项也是“英语是否保持独立技术栈”。

### 1.2 盘点的实际情况
| 环节 | 实际实现 |
|---|---|
| 主线 | `Ai-english-claude/echo-quest`：React + Vite 前端，零依赖 Node 代理 |
| 对话模型 | Anthropic Messages API，默认 `claude-sonnet-5`，`ANTHROPIC_BASE_URL` 可覆盖；非流式；没有超时和重试 |
| ASR | 浏览器 Web Speech（Chrome 会把音频送到 Google 云端，国内网络大概率不可用） |
| TTS | 浏览器 `speechSynthesis` |
| 发音评测 | **没有** |
| Gemini、流式 ASR、第三方 TTS / 评测 | **全仓库零命中** |
| 延迟 | 没有埋点，推断端到端约 3–8 秒，超过 PRD 目标 ≤ 2 秒、上限 3 秒 |
| 数据库 | 没有，全部在浏览器 localStorage |

另外发现：`/api/*` 没有鉴权和限流，是一个用服务器 key 的开放代理；客户端传来的 history 和 weakPoints 直接拼进 Prompt，是注入面；NPC 人设卡里有否认 AI 身份的指令（echo #9）。

### 1.3 已经做出的决定（echo decisions）
- #1：没有 Gemini 仓库，以 echo-quest 为准。
- #7：Web Speech 不作为生产方案；境内 ASR、TTS、发音评测做三家盲测；盲测用的学生语音要在监护人同意流程上线后、经授权采集。
- A1：阶段 0 实时对话留在原产品，适配器只接异步 grade、diagnose、report。
- A3：发音评测供应商到位前，D 维返回 null，不计入总分，并置 `human_review_required = true`。
- #9：场景 NPC 不豁免 AI 身份披露。

---

## 2. 选项

### 选项 A：境内模型 + 境内语音供应商，语音层归平台
- 对话和判分模型：按 ADR 04 路由到境内模型。
- ASR、TTS、发音评测：选境内供应商，放在**平台层**的语音适配层，按分钟计量、单独资源池（完整方案 5.8）。
- echo 适配器只负责 NPC 回合状态机、Prompt 组装、规则验证器、Rubric A/B/C。

**优点**：与 ADR 09 一致；语音计量、音频保留与删除、出境管控都在平台一处；其他学科以后要语音（例如语文朗读）可以复用。
**缺点**：对话、ASR、TTS、评测四样都要换，是四科里改动最大的；点点和 NPC 在境内模型上的表现要重新验证。

### 选项 B：保留 Anthropic 对话，只把语音换成境内
**缺点**：学生原话（L2）经 Anthropic 出境，违反 ADR 09。**不推荐。**

### 选项 C：英语暂不接入平台，留在原产品独立运行
**优点**：阶段 0 工作量最小。
**缺点**：Gate 0 要求“四科能写入同一学生模型”；而且原产品的开放代理和数据出境问题依然存在。可以作为选项 A 进度不及时的**阶段性后备**，但不能作为结论。

---

## 3. 决定

**待签字。**

**建议采纳选项 A**，分两步走：

**阶段 0（冲刺 3）**
1. 适配器只接异步 `grade`、`diagnose`、`report`（decisions A1）。输入是**文字转写稿**，合成数据测试即可，不需要真实语音。
2. `grade` 的 A/B/C 维由境内模型按 Rubric 判；`scriptedRate` 作为低置信兜底和对照。D 维（发音）返回 null，总分标注“不含发音维”，置 `human_review_required = true`（A3）。
3. NPC 回合的 `task_complete/errors` 只作为 evidence_event，不作为判分（#8）。
4. 语音选型并行启动：境内 ASR、TTS、发音评测各三家候选，盲测方案写进冲刺 4-I。**盲测前必须先上线监护人同意流程**（#7）。

**阶段 1**
5. 语音适配层落在平台（`services/learning` 或独立语音服务，按 ADR 01 的边界）；音频原文件不进入学生模型，只存评测结果与特征（完整方案 5.5）。
6. 实时对话迁入平台时，保持单次调用，走平台模型路由；NPC 人设卡按 #9 改写，删除否认 AI 身份的指令（人设变更，[NEEDS-HUMAN]，需跑 `make eval-persona`）。
7. 评测供应商到位后，D 维改为引擎输出，撤销“不含发音维”标注。

**同时调整的计划口径**
8. 点点跨模型一致性验证（Gate 0 硬条件）的对象，从“Gemini ↔ Anthropic ↔ 国内”改为“**境内两家以上模型之间**”（ADR 04、09）。
9. 七项待拍板第 5 项改为“**英语境内语音供应商选型**”。
10. 完整方案、开发计划、角色规范中关于英语 Gemini 链路的描述，另起文档修订 PR 更正（echo decisions #1，不在本 ADR 范围）。

---

## 4. 后果

### 正面
- 英语的出境问题有了明确的解决路径，Gate 0 的一致性验证也有了可执行的对象。
- 语音层归平台，计量、合规、延迟埋点只做一次。

### 代价
- 英语在阶段 0 只能接“文字转写后的异步批改”，实时口语仍然留在原产品，且原产品的开放代理问题要在原仓库修（或停用线上部署）。
- 语音延迟 p95 达标（完整方案 5.9）要等阶段 1 境内语音链到位后才能测量。
- 三家语音供应商盲测需要真实学生语音，时间取决于监护人同意流程的上线时间。

---

## 5. 待人确认

1. 原产品线上是否有可访问的部署？如果有，开放代理问题是否要先停用线上服务？
2. 语音适配层放在 `services/learning` 里，还是单独的语音服务？（音频处理的资源消耗和其他请求差别大，草案倾向于单独服务）
3. 点点跨模型一致性验证改为境内模型之间后，Gate 0 的通过标准（原来是“三家模型通过率差 ≤ 5 个百分点”）是否保持不变？
4. 如果境内模型在英语口语对话上的效果明显不如 Anthropic，是否允许对**去标识化（L1）**的对话做境外处理？这取决于 ADR 09 待人确认 #3 的去标识化标准。

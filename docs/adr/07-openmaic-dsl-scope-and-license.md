## 1. 背景

### 1.1 为什么要用 OpenMAIC
OpenMAIC 借鉴分析 v1.0 的结论：教学需要“舞台”，不只是对话。它的课程 DSL 把内容和渲染解耦，同一份讲解可以回放、导出给家长、被教研审核修改后复用；SVG 白板适合“阿鸦在白板上一步步演算”。完整方案把它的使用范围限定为：验证课程 DSL、白板和“按脚本播放 / 学生插话转实时”的呈现模式，先用“一张试卷生成讲评课”做原型。

### 1.2 许可证事实
| 事实 | 来源 |
|---|---|
| 分析对象是 OpenMAIC v0.3.2，根目录 MIT | OpenMAIC 借鉴分析 v1.0 |
| **v0.3.0 起许可证从 AGPL-3.0 改为 MIT**；更早的版本是 AGPL | 同上，版本表 |
| `packages/mathml2omml` 为 LGPL-3.0 | 同上；完整方案第六章 |
| 五个月七个版本，156 个开放 issue，主干变化快 | 同上 |

### 1.3 盘点发现
- 阿鸦已经用 **KaTeX（MIT）** 渲染公式，没有 MathJax，也没有 mathml2omml。
- 文砺、阿鸦、知行都通过 Next.js 间接依赖 sharp/libvips 的平台二进制（LGPL-3.0-or-later，可选依赖，动态链接）。这不属于 OpenMAIC，但同样适用 CLAUDE.md 第 10 条，需要一起登记。

---

## 2. 选项

### 选项 A：只引入渲染层包，锁版本，编排自己写
- 只用 whiteboard、slide-renderer、`@openmaic/*` 的 DSL 渲染器包。
- 编排、多智能体课堂、模型调用都不用 OpenMAIC 的。
- 不引入 `packages/mathml2omml`，也不用依赖它的 pptx 导出链路。

**优点**：拿到最有价值的部分（DSL 和白板），许可证干净，依赖面小。
**缺点**：导出 pptx 的能力没有了；锁版本意味着升级要手动评估。

### 选项 B：fork 整个仓库
**缺点**：要背它的全部依赖和漂移；多智能体课堂与平台的编排（ADR 03）、点点人设冲突；很可能带进 LGPL 包。**不推荐。**

### 选项 C：不用 OpenMAIC，自研 DSL 和白板
**优点**：完全可控。
**缺点**：冲刺 5 的原型工作量大很多。可以作为选项 A 验证失败时的后备。

---

## 3. 决定

**待签字。**

**建议采纳选项 A**，并规定：

1. **版本**：锁定到具体的 MIT 版本（≥ v0.3.0，建议从 v0.3.2 开始），在依赖清单里写明版本号和许可证。**禁止引入 v0.3.0 之前的任何版本**（AGPL）。
2. **范围**：只允许渲染层包（DSL 渲染器、白板、幻灯片渲染）；不引入 `packages/mathml2omml`；不引入它的编排、多智能体课堂、模型调用层。
3. **公式渲染继续用 KaTeX**（与阿鸦一致）。
4. **数据边界**：渲染器只接收已经审核过的讲解 DSL，**不持久化任何学生数据**（完整方案第六章）。讲解 DSL 里如果含学生作答内容，只在内存中渲染。
5. **内容审核**：讲解 DSL 属于用于教学的内容，必须经过发布闸门（完整方案第六章：AI 草稿 → 确定性检查 → 教研审核 → 版本发布）。
6. **依赖许可证检查进 CI**：引入任何依赖都要跑许可证扫描，GPL / AGPL / LGPL 需要人工确认。sharp/libvips 的 LGPL 二进制一并登记，由合规顾问确认是否可以接受。
7. **放在 `packages/stage`**（CLAUDE.md 仓库结构），其他模块只通过 `packages/stage` 的接口使用它。

---

## 4. 后果

### 正面
- 许可证风险可控；以后要换掉 OpenMAIC，只需要替换 `packages/stage` 内部。
- 讲解内容走审核流程，和“判分与讲解分离”（CLAUDE.md 第 3 条）一致。

### 代价
- 放弃 pptx 导出。家长导出改用 HTML 或 PDF。
- 升级 OpenMAIC 要人工评估。

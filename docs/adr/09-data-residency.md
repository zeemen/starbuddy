## 1. 背景

### 1.1 已有原则
完整方案 v1.0 已经写了三条原则：
- "国内可商用模型为首选"
- "不默认调用境外 API 处理个人信息"
- "个人信息跨境另行评估"

第十一章还专门写了："语音为敏感个人信息，发音评测若调用第三方引擎须专项审查出境与共享条款"。

但这些原则**还没有落成可以执行的约束**：
- 存储层写的是"Supabase 首期"，没有写区域。
- 托管层没有写。
- 开发工具链没有写。

### 1.2 盘点发现：四科的现状都不符合上面的原则
四科都还在测试阶段，没有真实用户（四份 decisions #1/#3），所以**下面这些都还没有造成已发生的出境**。但如果按现状上线，出境会发生。

| 数据流 | 现状 | 来源 |
|---|---|---|
| 模型默认路由 | 文砺、知行在 env 里的默认路由是 Anthropic（境外）；开口成章直接调 Anthropic，而且 BaseURL 可以被覆盖 | inventory-wenli §4、inventory-zhixing §4、inventory-echo §4 |
| 语音 | 开口成章用浏览器 Web Speech，Chrome 会把麦克风音频送到 Google 云端 | inventory-echo §5 |
| 学生原话 | 开口成章把识别出的文本、英文名、薄弱点转发给 Anthropic | inventory-echo §5 |
| 手写作答照片 | 阿鸦的照片经过 Vercel 函数，再发给境内视觉模型；Vercel 函数所在区域未知 | inventory-aya §4 |
| 数据库 | 四科都用 Supabase，项目区域都没法从代码里判断 | 四份 inventory §3 |
| 托管 | 文砺、知行、阿鸦部署在 Vercel（自述） | 四份 inventory §1 |
| 字体、静态资源 | 开口成章从 Google Fonts 加载 | inventory-echo §1 |

### 1.3 平台约束
- 这是一个面向境内未成年人（初中生）的产品。
- 我们处理的数据包括：
  - 学习画像
  - 作答原文
  - 手写照片
  - 语音（属于敏感个人信息）
  - 家长联系方式
- 参考法规见完整方案第十一章，包括《个人信息保护法》和《未成年人网络保护条例》。
- 以下三点**需要合规顾问确认**，本 ADR 不下法律结论：
  - 香港算不算境外
  - 出境的条件是什么
  - 需要做哪些备案

## 2. 数据分级

本 ADR 先把平台上的数据分成四级，后面的决定都以这四级为准：

| 级别 | 内容 | 例子 |
|---|---|---|
| **L3 敏感个人信息** | 语音、手写作答照片、心理和危机相关对话、监护关系 | 口语录音、试卷照片、转介记录、guardian_student_link |
| **L2 个人信息** | 能识别到学生或家庭的学习数据 | 学生档案、作答原文、学习者模型、证据事件、对话记录、家长手机号 |
| **L1 去标识化数据** | 已经去掉身份、不能再关联回个人的统计和样本 | 聚合指标、脱敏后的评测样本 |
| **L0 非个人数据** | 内容和代码 | 题库、知识图谱、Rubric、Prompt 模板、**合成**测试数据 |

## 3. 选项

### 选项 A：全链路境内
- 数据库、对象存储、函数和服务托管、模型、ASR/TTS/发音评测、日志和监控，全部放在中国境内。
- 境外服务只允许处理 L0 数据。

**优点**
- 合规路径最清楚。
- 和 ICP 备案、属地监管要求天然一致。

**缺点**
- Supabase 托管版和 Vercel 都没有中国大陆区域。Vercel 可选的区域里最近的是 hkg1（香港）。Supabase 的区域列表还需要核实。
- 所以要把现在的托管栈迁到境内云，工作量影响开发计划冲刺 1。
- 四科原来的部署方式都要改。

### 选项 B：存储境内，计算境外
- 数据库放在境内。
- 前端和函数继续用 Vercel。

**缺点**
- 请求路径还是要经过境外函数，L2 和 L3 数据在传输中出境。
- **没有解决问题，不推荐。**

### 选项 C：分环境
- **pilot 和生产环境**：执行选项 A，全链路境内。
- **dev 和 staging 环境**：可以继续用 Supabase 托管版、Vercel、Anthropic 这类境外服务，但**只能处理 L0 数据**，也就是合成数据。
- 开发计划已经规定了"pilot 环境只有经闸门发布的内容；生产数据不进入 dev 仓库"，本选项和它一致。

**优点**
- 开发效率不受影响。
- 合规边界落在"第一个真实用户进入的环境"上。

**缺点**
- 要维护两套部署拓扑。
- 必须有可靠的办法防止真实数据进入 dev 和 staging 环境。

## 4. 决定

**待签字。**

**建议采纳选项 C**，并加上以下硬约束：

1. **L2 和 L3 数据只能在境内存储和处理。** 数据库、对象存储、队列、缓存、服务端计算、日志和追踪系统，都部署在中国大陆区域。
2. **模型路由（ADR 04）从"国内首选"改为"L2 及以上数据只能路由到境内模型"。** 模型路由必须根据请求的数据级别选供应商。要调用境外模型，请求必须满足下面三条之一：
   - 只含 L0 数据
   - 只含 L1 数据
   - 已经走完单独的出境评估，并且留有记录
3. **语音链全部放在境内**：ASR、TTS、发音评测都选境内供应商，并做三家盲测（开口成章 decisions #7）。浏览器 Web Speech 不能用在 pilot 和生产环境。
4. **学生端不加载境外静态资源**，比如 Google Fonts 和境外 CDN。字体和资源一律自托管。
5. **dev 和 staging 环境只允许放合成数据**（CLAUDE.md 第 8 条）。这两个环境可以用境外服务，但禁止接入真实学生账号。
6. **供应商数据协议**：每个处理 L2 或 L3 数据的供应商，都要在 `docs/compliance/vendors.md`（待建）登记四项信息，数据处理协议签好之前不能接入：
   - 数据区域
   - 保留期
   - 是否用于训练
   - 删除方式

### 需要一起决定的事项
- **境内托管选型**：
  - 数据库：自建 Supabase，还是托管 Postgres
  - 对象存储
  - 函数和服务运行环境

  另起选型 ADR，编号待定。
- **ADR 02 的措辞**："Supabase 共库分 schema"要改成"Postgres 共库分 schema，pilot 和生产在境内"。
- **ADR 08 重写**：开口成章 decisions #1 已经确认英语没有 Gemini 链路。英语要改成"境内语音供应商 + 境内模型"。

## 5. 后果

### 正面
- 四科盘点里所有出境相关的阻断项有了统一的处理口径。
- 出境问题在架构层面被挡住，不用靠每科自觉。

### 代价
- 冲刺 1 就要有境内环境。至少是 pilot 环境，dev 环境可以先用境外托管。
- 要做的事：
  - 托管栈选型和迁移
  - 语音供应商选型和盲测
  - 境内模型能力评估：判分一致性、人设一致性需要重新测
- 点点的跨模型一致性验证，前提从"Anthropic 与 Gemini"改为"境内模型之间"。

### 对各科的影响

| 学科 | 影响 |
|---|---|
| 文砺 | 默认路由改为境内模型；OCR 用境内视觉模型（legacy 声称线上已用 Qwen-VL，需要核实） |
| 知行 | 默认路由改为境内模型；线上实际模型不详，接入时按本 ADR 配置 |
| 开口成章 | 影响最大：模型、ASR、TTS、评测全部要换；Google Fonts 改为自托管 |
| 阿鸦 | 模型本来就是境内的（DeepSeek、DashScope）；托管要从 Vercel 迁到境内，手写照片存储在境内 |

### 需要的验证手段（进入冲刺验收）
- **数据流清单**：`docs/compliance/data-flows.md`（待建），逐条列出每个 L2 和 L3 数据流的来源、处理方和区域。
- **出口白名单**：pilot 和生产环境的服务端出网流量走白名单，名单里只允许境内供应商的域名。发布流程里要有一项检查，确认白名单外的出网请求会被拦截。
- **模型路由测试**：契约测试里构造 L2 请求，断言它不会路由到境外供应商。
- **前端资源检查**：构建产物里不能引用境外资源域名。

## 6. 待人确认

1. 采纳选项 C，还是选项 A？
2. 合规顾问确认以下几点：
   - 香港区域（比如 Vercel hkg1）是否算出境
   - 个人信息出境的具体条件
   - 境内托管和 ICP 备案的要求
   - 已备案生成式 AI 模型的调用和登记要求
3. 境外模型处理 L1 去标识化数据时，"去标识化"的认定标准由谁来定？
4. 境内托管选型的负责人和时间点，以及它对冲刺 1 排期的影响。
5. dev 和 staging 环境如何保证不接入真实账号？可选方案有：注册限制在白名单域名、手机号走测试号段，或者其他办法。
6. 这份 ADR 是作为 ADR 09 单独存在，还是并进开发计划原定的 ADR 01–08 体系一起评审？

## 1. 背景

### 1.1 计量规则（已定，本 ADR 不改）
完整方案 5.8 与技术实施蓝图：
- 要计量的动作：分科完整诊断（次）、限时整卷模考（次）、新上传错题深度分析（题）、讲评课堂 / 白板（节）、语音实时互动（分钟）、AI 互动有效时长（分钟）。
- 每次请求带 `usage_id` 与 `idempotency_key`；**开始时预留，成功后按实际单位结算，失败回滚**。
- 同一题 24 小时内复看不重复扣“新题分析”；服务错误重试不扣第二次；学生主动重新发起完整分析计新一次。
- 到上限时保存学习进度，并提供低成本自练题，不强迫续费。
- 英语实时语音按分钟计量，单独建资源池。

### 1.2 盘点发现
四科**完全没有**计量：没有 usage_id、idempotency_key、token 记账或限流。知行和开口成章的模型接口可以匿名调用，等于开放代理。所以不存在要迁移的历史账。

### 1.3 这份 ADR 要回答的问题
预留、结算、回滚在并发、断线、重试下，怎么保证**不多扣、不少扣、不重复扣**？

---

## 2. 选项

### 选项 A：Postgres 单库事务 + 追加式流水
- `platform.entitlement`：每个家庭（或学生）每种资源的额度和周期。
- `platform.usage_ledger`：追加式流水，每行一个状态变化：`reserved → settled` 或 `reserved → released`。
- 余额 = 额度 − 已结算 − 预留中，在同一事务里用行锁（`SELECT … FOR UPDATE` 锁住 entitlement 行）计算和校验。
- 幂等：`idempotency_key` 全局唯一约束；重复请求直接返回第一次的结果。
- 超时预留：预留带过期时间，过期没结算的由定时任务自动释放。

**优点**：强一致，简单，可审计；和学习者模型同库，账和学习记录可以对得上。
**缺点**：高并发下 entitlement 行锁是热点。但按家庭加锁，同一家庭的并发很低，阶段 0–1 的规模不会成为问题。

### 选项 B：Redis 计数 + 异步落库
**优点**：快。
**缺点**：Redis 和数据库之间的一致性要额外保证；故障时可能多扣或少扣。阶段 0–1 不需要这种性能。**不推荐。**

### 选项 C：用第三方计费服务
**缺点**：新增第三方服务（必停项），并且要处理数据出境（ADR 09）。**不推荐。**

---

## 3. 决定

**待签字。**

**建议采纳选项 A**，并规定：

1. **状态机**：`reserved → settled` / `reserved → released` / `reserved → expired`（等同 released）。已结算的不能再改；更正要追加一条反向流水，不能修改原记录。
2. **幂等**：`usage_ledger.idempotency_key` 全局唯一。注意 ADR 05 的事件表分区会把唯一约束限制在分区内，所以**计量账本的幂等由一张不分区的 `usage_idempotency` 表保证**，流水本身可以分区。
3. **24 小时复看不重复扣**：幂等键由 `(家庭, 资源类型, 内容指纹, 24 小时窗口)` 构成。内容指纹的定义（例如错题图片的感知哈希）由各科适配器提供。
4. **服务错误不扣第二次**：失败必须显式 `release`；客户端重试沿用原 `idempotency_key`。
5. **结算按实际单位**：语音、有效时长按分钟向上取整，诊断、模考、题按次。结算单位写在资源类型配置里。
6. **额度可见**：余额查询走只读视图；BFF 不缓存余额。
7. **家长是支付主体**（完整方案第十一章），额度挂在家庭层；学生层只做分配和展示。
8. **必须通过的测试**（Gate 0 硬条件）：并发扣同一额度、预留后断线、同一幂等键重试、结算前失败回滚、预留过期释放、24 小时复看。

---

## 4. 后果

### 正面
- Gate 0 “扣次幂等”有明确、可测试的实现路径。
- 账和学习记录同库，家长查“这次扣了什么”时可以回溯到具体的诊断或批改。

### 代价
- 计量逻辑集中在 BFF（ADR 01），所有学科请求都要先过 BFF 预留。
- 内容指纹需要各科提供，这是适配器的额外工作。
- 预留过期释放需要定时任务（ADR 03 的调度能力）。

---

## 5. 待人确认

1. 额度挂在家庭层还是学生层？草案倾向于家庭层，因为家长是支付主体。
2. “AI 互动有效时长”的计时口径由谁定义？（例如空闲超过多少秒不计）
3. 预留的默认过期时间：草案建议按资源类型的 p99 处理时长的 2 倍，例如诊断 p95 目标是 90 秒，预留过期可以设 10 分钟。
4. 阶段 1 的试点不收费（开发计划 M5：虚拟额度），是否仍然全量走账本？草案建议全量走，这样才能验证单位经济。

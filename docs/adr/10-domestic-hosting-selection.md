## 1. 背景

### 1.1 为什么需要这份 ADR
ADR 09 建议 pilot 和生产全链路境内（选项 C）。现有的托管栈都做不到：
- 文砺、知行部署在 Vercel（自述），阿鸦自述部署在 `ayaheshui.vercel.app`，开口成章没有部署配置。Vercel 最近的区域是香港（hkg1），是否算出境待合规顾问确认（ADR 09 待人确认 #2）。
- 四科都用 Supabase 托管版（开口成章除外），区域都无法从代码判断。Supabase 托管版的区域列表待核实，目前没有已知的中国大陆区域。

所以 pilot 和生产环境要换一套境内托管。

### 1.2 平台需要的能力
| 能力 | 用途 | 依据 |
|---|---|---|
| Postgres（支持声明式分区、RLS、pgvector） | 学习者模型、事件表、计量账本、内容检索 | ADR 02、05、06；完整方案第六章 |
| 认证 | 家庭账号、手机号 OTP、未成年人与监护人关系 | ADR 02 待人确认 #1；完整方案第七章 |
| 对象存储（私有桶） | 手写作答照片、语音、课程资产 | 完整方案第六章 |
| 容器运行环境 | BFF（TS）、学习服务（Python）、适配器 | ADR 01 |
| 队列 / Worker / 定时任务 | 长任务、复测调度、预留过期释放、分区维护 | ADR 03、05、06 |
| 缓存与限流 | 分学科限流 | 完整方案第六章 |
| 出网白名单 | 服务端出网只允许境内供应商 | ADR 09 §5 |
| 可观测性 | OpenTelemetry，敏感日志脱敏 | 完整方案第六章 |

### 1.3 时间压力
开发计划冲刺 1（W3–W4）就要做平台 schema 迁移和 RLS；寒假试点（2027 年 1 月）要在 pilot 环境跑真实用户。**pilot 环境最晚在冲刺 5（W11–W12）之前就绪**。dev 环境可以先用 Supabase 托管版（ADR 09 选项 C 允许，只放合成数据）。

## 2. 选项

### 选项 A：自建 Supabase（开源版）部署在境内云
- 在境内云的容器服务上自建 Supabase（Postgres + Auth + Storage + REST）。

**优点**：dev（托管版）和 pilot（自建版）的接口一致，开发体验不变；Auth、Storage 现成。
**缺点**：自建 Supabase 组件多，运维成本高；升级、备份、高可用都要自己负责；要核实自建版的各组件许可证。

### 选项 B：境内云的托管 Postgres + 托管对象存储 + 容器服务，认证由 BFF 自建
- 数据库用云厂商的托管 Postgres；对象存储用云厂商的；服务跑在云厂商的容器服务上。
- 认证不依赖 Supabase Auth，由 BFF 实现（手机号 OTP 用境内短信服务）。

**优点**：托管服务的备份、高可用、监控是现成的；组件少，运维简单；备案和合规材料更容易准备。
**缺点**：dev 用 Supabase 托管版时，dev 和 pilot 的认证与存储接口不同，需要一层抽象；认证要自己写。

### 选项 C：dev 也不用 Supabase，全部环境统一用选项 B 的托管栈
**优点**：环境一致，最少意外。
**缺点**：dev 也要在境内云上开，成本和开通时间增加；Claude Code 的开发环境要能访问它（开发环境只放合成数据，这一点不变）。

---

## 3. 决定

**待签字。**

**建议采纳选项 B，dev 环境是否跟进（即选项 C）留待冲刺 2 复核**：

1. **数据库**：境内云托管 Postgres。开通前核实：版本、声明式分区、RLS、pgvector 是否支持；分区维护扩展是否可用（ADR 05）。
2. **认证**：BFF 自建，手机号 OTP 用境内短信服务；**不按手机号关联学生数据**，家长访问只能走 `guardian_student_link`（CLAUDE.md 第 5 条）。
3. **对象存储**：私有桶，服务端签名 URL，照片和语音按 ADR 09 的保留期删除。
4. **运行环境**：容器服务，BFF、学习服务、适配器各自一个服务；服务端出网走白名单（ADR 09 §5）。
5. **队列与调度**：阶段 0–1 优先用 Postgres 自带能力（例如基于表的任务队列加定时任务），少引入一个组件；增长阶段再评估专门的队列。
6. **dev 与 pilot 的接口一致性**：认证、存储都通过平台自己的接口访问，底下可以接 Supabase（dev）或境内托管（pilot、生产）。迁移脚本只用标准 Postgres 能力（ADR 02 第 1 条）。
7. **云厂商选择**：本 ADR 不指定具体厂商，只给出评估清单（见下）。厂商确定后补一份决定记录。

**云厂商评估清单**
- 上面第 1–5 条的能力是否齐全；
- ICP 备案、等保要求的支持情况（合规顾问确认）；
- 数据处理协议：数据区域、保留期、是否用于训练、删除方式（ADR 09 第 6 条）；
- 成本：按内测规模（约 1,000 户）估算月成本；
- 开通时间：能否在冲刺 4 之前开好 pilot 环境。

---

## 4. 后果

### 正面
- pilot 和生产的数据驻留有了落地方案，ADR 09 的硬约束可以执行。
- 托管服务降低了运维负担，适合小团队。

### 代价
- 认证要自己实现，并且要做安全审查（security-reviewer）和渗透测试。
- dev（Supabase）和 pilot（境内托管）之间需要一层抽象，多一点工作量。
- 云厂商开通和备案有外部时间，需要尽早启动，否则会影响寒假试点（开发计划风险表“寒假试点窗口错过”）。

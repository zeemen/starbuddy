## 1. 背景
星图是学生和家长最常看的一张图。现在“星”指什么有两种说法：
- **已合并的 3-H 星图**：每颗星是一个 `platform.skill_node`，即各科原有的能力坐标。阿鸦一科就有 959 个，粒度与分类由各科自定，跨学科不可比。
- **完整方案 v1.1 与 KGE V1.1**：星 = 知识节点（`knowledge_node`），由统一知识地图定义、版本化、可与课标和教材对照；各科能力坐标降为“能力视图”，不单独点亮。

两种说法并存会带来三个问题：
- 同一名学生在不同页面看到两套“亮了几颗”，没法解释；
- 能力坐标没有版本与课标承接，星亮了不能回答“亮的是哪条课标”；
- 技术蓝图 v2.1 规定“只有 A 级证据能点亮星”，这条规则需要一个统一的“星”才能落地。

## 2. 选项
1. **维持 3-H 做法，星 = 能力坐标**：不用改代码；但各科粒度不一，星图跨学科不可比，与 KGE 的掌握计算对不上，v2.1 的证据分级也无处挂靠。
2. **星 = 知识节点，能力坐标是能力视图**（本 ADR 推荐）：
   - 每颗星是当前已发布地图版本里的一个 `kge.knowledge_node`；
   - 能力坐标经 `kge.skill_link` 挂到知识节点上，只在侧栏以“能力视图”展示，不单独点亮；
   - 星的状态由 KGE 掌握计算决定，展示时引用判断账本里的判断（规则 11）。
3. **两者并存，学生可切换**：兼容性最好；但两套“亮”的口径同时对外，正是背景里要解决的问题，家长端尤其难解释。

## 3. 决定（待签字）
选项 2。
- **星的对象**：
  - 星 = 已发布地图版本中状态有效的 `kge.knowledge_node`；地图升级时按 `kge.id_migration` 延续，已亮的星不因改版熄灭（迁移规则以 KGE 第三章为准）；
  - 能力坐标（`platform.skill_node`）经 `kge.skill_link` 挂接，作为“能力视图”；能力视图可以显示掌握分布，但没有“亮”这个状态。
- **星亮的口径**：
  - 星亮 = 该节点的掌握进入 KGE 规定的“迁移”门槛；门槛与五道门槛的具体数值属于掌握计算（必停项），以 KGE V1.1 与 KGE-04 掌握 spec 为准，本 ADR 只引用、不写数；
  - 只有 A 级证据（平台内独立作答，技术蓝图 v2.1 2.1）能让星亮；B 级可更新掌握概率、可触发“去平台内验证这颗星”的任务，但不点亮；C 级不进掌握。
- **状态来源与展示**：
  - 星的三态（未亮、半亮、亮）与“保持”外圈沿用 3-H 的视觉，数据来源改为 KGE 掌握状态；
  - 对学生、家长可见的“这颗星亮了”是关于学生的陈述，须引用判断账本里一条“成立”或“假设”的判断（规则 11，ADR 13）；
  - 证据不足、判断处于“待验证”的星画虚线，不作为陈述（ADR 13 待人确认 #2）。
- **范围**：
  - 非学科维度（学习力、家庭维度）不画成星（沿用 3-H）；
  - 英语搁置期间不画英语星空（对照文档 #1）；语文、道法等学科在各自的知识地图发布前，不显示星空，只显示“地图建设中”。
- **过渡**：
  - 3-H 星图的代码在 KGE-01 骨架导入、首个地图版本发布之前保持原样（规则 11 过渡条款）；
  - 之后另开任务：BFF 星图读模块的数据来源换成知识节点与掌握状态，前端加能力视图侧栏与待验证虚线（开发计划 v2.0 冲刺 3-H 的验收项）。

## 4. 后果
- 好处：
  - 各科星图口径一致，跨学科可比；每颗星能回答“对应哪条课标、哪版教材”；
  - v2.1 的“拍照不点亮星”有了落点，拍照批改与星图可信解耦；
  - 星亮与判断账本挂钩，“为什么亮”“我不同意”有依据可查。
- 代价：
  - 3-H 的 BFF 查询、合成种子、视觉回归与 E2E 要改，星的数量与分布会变（阿鸦 959 个能力坐标不再逐个成星）；
  - 在各科知识地图发布前，该科没有星图，上线时间受 KGE-01、KGE-02 进度约束；
  - 已向试用学生展示过的旧星图不迁移成新星亮，只存档（完整方案 v1.1 5.5“不迁移旧结论”）。
- 需要同步的地方：
  - `specs/star-map-sprint3/` 与 4-H 统一壳 spec 的数据来源；
  - KGE-04 掌握 spec 写明“只有 A 级点亮”；
  - 字段字典里星图相关字段的可见范围（SIE-00 下一版）。

## 5. 待人确认
1. 能力视图是否对家长显示？默认：学生端与家长端都显示为侧栏，只有分布，没有“亮”。
2. 地图升级时已亮的星如果被拆分或合并，拆出的新节点是否继承“亮”？默认按 `kge.id_migration` 的类型：改名、合并继承；拆分的新节点重新判定。
3. 阿鸦能力坐标与知识节点的挂接由谁完成、何时完成：默认随 KGE-01 导入阿鸦图谱时由数学教研审核。
4. “地图建设中”的学科是否仍显示旧能力坐标星图作为过渡：默认不显示，避免两套口径。

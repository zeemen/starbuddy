- **7.2 节的前提只满足一部分**：
  - KGE-04 已按“节点 × 认知层次”写 `platform.mastery_estimate`，`star_lit` 按配置 `star_level_rule` 由学习服务计算；
  - 判断生成已能读真实掌握行（`sync_mastery_from_db`），但没有调度入口（KGE-04 lessons 待确认 W）；
  - **ADR 11、ADR 13 都未签字**；数学地图首个版本未经人发布；教研数值未签，星最多到“稳定”。
- **BFF 能读到的**：`kge.map_version`（只限已发布）、`kge.knowledge_node`（0011 授权）；`platform.mastery_estimate`（按 `can_read_student`）；`insight.claim`（`claim_front_read`）。**读不到** `kge.skill_link` 与学习服务的掌握配置，所以 BFF 无法自己判断哪个认知层次决定星亮——7.2 节也要求 BFF 不聚合层次、不算门槛。
- **学习服务** 的 `mastery/get` 能给出 `star_lit` 与各层次门槛，但只认编排层凭据（KGE-04 PR 3），BFF 调不了。
- **3-H 星图**：v0 形状按 `skill_local_id` 读旧行，带“原型 · 合成数据”水印；Gate 0 证据包里的截图就是它。

## 设计要点
### 1. 先上开关，签字后再切换（#1）
- BFF 与前端各加功能开关 `starmap_v1`，默认关闭；关闭时一切保持 3-H v0 原样（规则 11 过渡条款）。
- 开关只在 dev / test 环境可开；生产启用以 ADR 11 签字、数学地图发布、判断生成接入调度三者满足为准，由人决定。

### 2. 节点星态由学习服务给（#2）
- 学习服务新增内部接口 `POST /internal/v1/star-map/nodes`（只认 BFF 凭据），入参学生、学科；返回当前已发布地图版本里每个节点：
  - `node_id`、`state`（按 `star_level_rule` 取星亮层次上的门槛）、`star_lit`、`basis_id`（决定该状态的那条当前掌握记录）；
  - **不返回** `p_mastery`、`confidence`、证据 ID、各层次明细。
- 契约 `learning-internal.v1.yaml` 追加（版本处理同 KGE-04 PR 3/4：在未签字的 1.1.0 草稿内追加，签字范围再扩大）。

### 3. 判断先于展示（7.2 节三条件）
- BFF 在 `withAccount` RLS 事务里读该学科节点上的判断：受众可见、状态为“成立”或“假设”、模板在对外白名单（只含数学“知识掌握”“知识迁移”）、`basis_id` 等于第 2 节给出的当前掌握记录。
- 三条全满足才按 `state` 画（未亮、半亮、亮、“保持”外圈），并带 `claim_id`；否则画**中性底星**（不带任何文字）。
- 文字只取 `insight.explain` 的 `RenderedStatement.text`（单页最多 10 条，超时不显示）；家长端与 `confidence_band` 一起显示。
- **待验证虚线**：开关 `starmap_dashed` 默认关；关时按中性底星；开时只画虚线与下一次验证任务，不带结论文字（ADR 13 #2 签字前保持关闭）。
- **星数说明 / 迁移摘要**：只在有“知识掌握”/“知识迁移”维度的判断时显示其 `RenderedStatement.text`。

### 4. 范围与侧栏
- 只画已发布地图的学科；在读但未发布的学科显示“地图建设中”；英语不画；非学科维度不画。
- 星 = `status = 'active'`、`level = 'node'` 的知识节点，领域与主题只作分组（统一壳 #9）。
- 能力视图侧栏：组件做出来，签字前为空并显示“能力视图即将开放”（字段字典 `inner.g4.skill_view` 只给 agent，统一壳 #8）；不发数据请求。
- 水印：v1 也保留“原型 · 合成数据”，直到教研签字掌握数值（#6）。

### 5. 接口
- BFF 新建 `services/bff/openapi/star-map.v1.yaml`：`GET /students/{id}/star-map?v=1`（或独立路径，按现有路由惯例），v0 保留到切换完成。
- 每颗非中性的星带 `claim_id`；页面每一句关于学生的文字渲染为带 `data-claim-id` 的元素。

## 分 PR
1. **学习服务 + 契约**：`star-map/nodes` 接口、契约追加、测试与变异。
2. **BFF**：v1 读模块（节点、星态、判断匹配、文字）、`star-map.v1.yaml`、开关、路由矩阵与集成测试、变异。
3. **前端**：v1 渲染（中性底星、虚线开关、星数说明位、能力视图侧栏占位、“地图建设中”）、视觉回归、E2E、axe；Gate 0 星图截图在 test 环境用 v1 重截一份附在证据包旁（不替换 v0 截图，#7）。

## 验收标准（可测试，沿用统一壳 spec 第 400 行）
- [ ] 开关关闭时 v0 星图逐像素不变（现有视觉回归与 E2E 不改断言）。
- [ ] 夹具：掌握为亮且有匹配判断 → 画亮并带 `claim_id`；掌握为亮但没有判断 → 中性底星；判断 `basis_id` 不是当前掌握记录 → 中性底星；判断为待验证且虚线开关关 → 中性底星，开 → 虚线且不带结论文字。
- [ ] 家长会话只按 guardian 可见范围取判断，陈述旁有 `confidence_band`；兄妹、另一户、撤销绑定后 404。
- [ ] 地图未发布的在读学科显示“地图建设中”；英语不出现；能力视图侧栏不发数据请求；星数说明与迁移摘要只在有判断时出现。
- [ ] 学习服务接口不返回 `p_mastery`、`confidence`、证据 ID；只认 BFF 凭据。
- [ ] 严格 `make check`、契约审查、安全审查通过；禁用推断与陈述—判断一致性测试覆盖星图文字。

## 待人确认（括号内为默认）
1. **ADR 11 未签字时怎么做**：实现放在开关后，默认关闭，v0 保持原样；签字、地图发布、判断调度三者满足后由人决定切换。另一个选择：等 ADR 11 签字再开工。
2. **节点星态的来源**：学习服务给 BFF 一个只含星态的内部接口（契约追加）。另一个选择：BFF 直接读掌握表并自己按星亮层次取值（要把 `star_level_rule` 暴露给 BFF，形成第二份口径，不推荐）。
3. **契约版本**：继续在未签字的 1.1.0 草稿内追加，签字范围再扩大到 `star-map/nodes`。另一个选择：升 1.2.0。
4. **v1 路径**：同一路径加 `v=1` 参数，还是新路径 `/students/{id}/star-map/v1`。默认按 BFF 现有路由惯例二选一并在 PR 里说明。
5. **领域与主题的分组展示**：默认沿用 3-H 的星座分组视觉，领域为星座、主题为子群；具体排版由设计确认。
6. **水印**：v1 仍保留“原型 · 合成数据”，直到教研签字掌握数值。
7. **Gate 0 截图**：v0 截图不替换；另附一份 v1（开关开、test 环境、合成数据）截图，标“未启用”。
8. **星的数量**：合成地图下每科几十颗；真实数学地图节点数待 KGE-01 发布后核对排版上限（默认单屏 ≤ 120 颗，超出按领域折叠）。
9. **中性底星与“没有证据”同外观**：沿用 7.2 节；是否需要无障碍文字区分（例如读屏读“暂无可展示的结论”）默认需要，文案进统一文案文件。
10. **判断生成调度**：本任务不接；在它接上之前，开关打开时真实环境里的星全是中性底星（合成数据除外）。

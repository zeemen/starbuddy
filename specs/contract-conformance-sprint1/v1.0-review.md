# 契约 v1.0 评审清单（W4 冻结前拍板）

用途：把 v0.9 留下的待定项和冲刺 1 实现中新发现的契约问题汇总到一处。评审会逐项拍板后，按结论产出 `plugin-api.v1.0.yaml`，另开 `[NEEDS-HUMAN]` PR（spec 范围第 6 条）。

每项写明选项、默认建议、是否破坏性变更、影响到的适配器与服务。所有“默认建议”都是起草人的建议，评审可以推翻。

来源缩写：
- **v09-#n**：`specs/contracts-plugin-api-v0.9/spec.md` 的“待人确认”第 n 项
- **v09-评审**：同一文件“留给评审决定”
- **aya-#n**：`specs/adapter-aya-sprint1/lessons.md`
- **learn-#n**：`specs/learning-ingest-sprint1/lessons.md`

> 破坏性变更：v0.x 期间允许，但每项都要列出受影响的适配器；v1.0 之后必须有迁移期（packages/contracts/README.md“版本策略”）。

## 三、v0.9 留给评审决定
| 项 | 建议 |
|---|---|
| 普通提示是否计量 | 同 v09-#2 |
| 分数不超过满分；总分与各维之和一致 | 满分约束已由数据库保证；各维之和见 N6 |

| 文砺“维度 × 难度”的变式参数 | 冲刺 2 文砺接入时定 |
| 英语安全审核 flag 与复核分开 | 冲刺 3 英语接入时定 |
| 各方法的超时约定 | 学习服务已按 grade 10 秒、diagnose 30 秒实现，建议写进契约描述 |

| 一次结果用到两个模型时 `model_version` 怎么写 | 写主模型，其余写进 `source_version` 的 `algo:` / `prompt:` 段 |
| 非消耗类方法不计量的理由 | 补写说明 |

## 冻结流程
1. 评审会前一周：本清单发给技术负责人、四科负责人、教研代表。
2. 评审会：逐项拍板，结论记在本文件每项之后，写明“结论、签字人、日期”。
3. 会后：按结论改契约、反例、变异测试和一致性测试，同步改阿鸦适配器与学习服务。另开 PR，首行写 `[NEEDS-HUMAN]`。
4. 冻结后：破坏性变更必须有迁移期（README“版本策略”）。

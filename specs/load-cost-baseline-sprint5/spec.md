## 现状（调研结论）
- **没有任何压测工具与基线**；没有性能目标（p95 延迟、吞吐）的签字值。
- **降级只到路由层**：路由有熔断与主备切换并有单测，但“某一家模型整体不可用时各科各方法的用户可见行为”（批改排队转人工、讲解降级、诊断暂停）没有端到端验证。
- **成本无从实测**：没有真实会话、没有签字的供应商与价格；调用记录里有 token 数，可作为成本模型的输入。
- 规则 9：不接触生产环境；压测只能在本机或经批准的预发环境。

## 设计要点
### 1. 压测基线（`tools/loadtest/`）
- 场景（按用户旅程，合成家庭与学生）：登录 → 今日计划 → 一次诊断 → 三道批改 → 星图；家长查看孩子页；计量预留 / 结算并发；
- 负载生成器：Python asyncio + httpx（仓库已有依赖，不引入新许可证）；固定种子、可复现的到达过程（泊松）、分阶段加压（10 → 50 → 100 → 200 并发会话）；
- 目标环境：本机一次性栈（学习服务、BFF、三科适配器、一次性 Postgres、假模型供应商按可配置延迟分布返回）；预发环境只在人批准后由执行人跑（执行手册）；
- 指标：各接口 p50 / p95 / p99、错误率、吞吐、数据库连接池与慢查询前十、计量一致性（压测后预留 = 结算 + 回滚，零泄漏，复用计量幂等断言）；
- 报告：Markdown + JSON，只含汇总；标注“本机基线，不代表生产容量”。

### 2. 单模型失效降级（故障注入）
- 假供应商支持注入：整家不可用、超时、5xx 比例、慢响应、限流；
- 端到端断言（每科、每个用到模型的方法）：主模型失效 → 熔断打开 → 切备选且数据级别过滤不放宽（不回落到不允许出境的供应商）；主备都失效 → 用户可见降级行为符合规格（批改：`human_review_required` / 排队，不给分；讲解：固定提示；诊断：暂停可恢复），计量回滚，不扣次；恢复后半开探测恢复；
- 降级行为清单若规格未定义，列待人确认，默认“宁可不答不乱答”。

### 3. 真实会话成本测算（成本模型 + 合成估算）
- 成本模型：`单次会话成本 = Σ（调用次数 × (输入 token × 输入单价 + 输出 token × 输出单价)）+ 语音分钟 × 单价 + 存储与计算摊销（可选）`；
- 输入：调用记录（token 数，按科 × 方法 × 任务）、价格表（**由人填**，按签字供应商；未签字前用明显标注的示例价）、会员档额度与使用分布（0015 各档额度；使用分布默认按额度上限的 30% / 60% / 100% 三档假设）；
- 输出：四科（英语搁置则三科 + 英语占位）× 会员档的 P50 / P90 单月成本表，附敏感性分析（价格 ±50%、token ×1.5）；数据来源标注“合成估算”，真实会话数据到位后同一工具重算；
- 合成 token 分布：来自 C+D 合成回放与人设评测录制的 token 数（不含内容），不足之处用可配置分布并在报告标注。

### 4. 执行手册
- 预发压测的前提（人批准、环境隔离、不连生产）、步骤、停止条件；真实成本重算的数据导出口径（只导 token 数与元数据）。

# PR2 实现记录（“完成 / 先跳过”接入与口径统一）

提交首行 `[NEEDS-HUMAN]`：真实页面开始写 `plan_done` / `plan_skip`，周报客观栏的计划计数口径改变（家长周报自此出现真实数值）。

## 交付
- BFF：学习服务返回 `snapshot` 与 `task_id` 时透出给学生本人（frozen 时每条须带小写 UUID 且互不重复，not_frozen 不许带，否则整表按不可用）；开关关时响应逐字段不变；家长拿不到。只改服务内 OpenAPI。
- 前端：今日计划跨科列表在 frozen 且有 `task_id` 时显示“完成”“先跳过”（`{{TODO_COPY:today.mark.*}}` 占位）；server action 依次核对 CSRF、格式、学生本人，再经 BFF 现有事件接口写入；失败静默。幂等键带渲染时生成、绑定会话的一次性 nonce：同一次渲染内重复点击与重试只记一次，“完成→跳过→完成”三次都入库，统计取最后一次。
- 洞察服务：新增 `plan_tasks.py` 作为指标与周报共用口径（同一任务以最后一次记录为准，按发生时间与记录 ID 排序）；`config/plan-tasks.json` `count_sources: all`；周报算法版本升 `sie-weekly@0.1.1`，口径配置并入版本号。不改判断模板、可见范围、效度门槛。

## 审查意见的处理（按默认）
- 两份审查同一条阻断：幂等键按（任务, 动作）固定，“完成→跳过→完成”最后一次被 409 吞掉却显示已记下，周报与学生最后选择不一致（规则 6）。改为一次性 nonce 方案，补“完成→跳过→完成”的端到端与库上测试。
- 采纳：口径配置进版本号；403、422 与其他 4xx 分开计数（不带 ID）；删除永远相等的令牌比较。

## 与 spec 的偏差
1. 验收“刷新后不重复记”改为：同一次渲染内重复点击与重试不重复记；刷新后再点会多一行，但同任务取最后一次，计数不变。
2. 未做“按来源分项”：洞察服务没有快照表读权限，需授权迁移。
3. 刷新后页面不显示已标记状态（页面不读事件）。

## 待人确认

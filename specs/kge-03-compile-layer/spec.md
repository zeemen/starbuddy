## 设计要点
### 1. 代码位置
- 新建 `services/knowledge/`（Python，FastAPI，沿用学习服务的工程约定），内含 `compiler/`（编译器 Worker）、`lint/`（程序体检）、`service/`（知识服务读工具）、`retrieval/`（页面优先 + 切块兜底）。只读 `kge.*` 公共层，不读写任何个人层表（规则 1、2、13）。
- 页面仓库的 CI 检查以**可安装的命令行**交付（`python -m knowledge.lint <页面目录>`），外加一份页面仓库模板 `tools/kge-pages-template/`（目录结构、CI 配置样例、合并请求模板、分支保护设置清单），由人创建仓库时拷过去（ADR 12 待人确认 #4 默认“复用本仓的检查命令”）。

### 2. 页面格式与编纂规范骨架
- 页面 = Markdown + YAML 头部：`page_id`、`page_type`（首期只做**知识点页 kp**，其他七类留类型不实现）、`subject`、`node_id`、`map_version`、`schema_version`、`page_version`（semver）、`risk_level`、`rebuild_kind`（render / full）、`locked_sections`、`atom_refs`（带原子哈希）。
- 三种段落用固定标记分隔：锁定段（定义、课标要求）、渲染段（前置与后续、教材位置、地区权重，教材原句**不写进页面**，只放投影引用，读取时按学生版次渲染）、叙述段（讲解要点、易错、高频设问）。
- `docs/design/kge/codification-math-v1.md`：**只写结构骨架与机器可检规则**（段落、头部字段、引用格式、公式写法、适龄文风的可测项：句长上限、禁用表述词表引用、人设中立）；教学内容要求由教研填写并签发（待人确认 #2）。

### 3. 编译器（两种重建、编译队列、合并窗口）
- **编入**：按“页面—原子”引用（页面头部 `atom_refs` 汇成的索引）找出受影响页面，生成编译任务（原因、触发原子、优先级 = 风险 × 影响）。
- **渲染重建**：从 `kge.*` 的节点、边、课标、投影重新生成锁定段模板位与渲染段；已审核的叙述段逐字保留；记录所引原子哈希；风险按改动类型判为低或高（定义、课标要求、前置关系表述变更 = 高）。
- **全量重编**：叙述段由模型经模型路由重写（任务类型按“离线公共知识构建”、数据级别 L0，只送公共原子，不送任何学生数据）；一律高风险，必须教研审核；旧版本在新版发布前继续服务。
- **合并窗口**：编译器产出以“一次合并请求”为单位；低风险改动按日聚合，每页每天最多发布一次；中、高风险单独成请求并标注审核人数（高风险两人，类别待 ADR 12 #2）。
- 本环境没有页面仓库：编译器输出到本地目录并生成合并请求说明（差异、依据原子、体检结果），推送到页面仓库由执行人配置（凭据不在仓库）。

### 4. 程序体检（每次编译后 + 每日全量；阻断即不能合并）
- 结构：头部字段齐全与取值合法；节点 ID 存在于指定已发布地图版本（与 `check_node_id.py` 一致）；段落标记齐全；锁定段与上一审核版一致（重编不可改写）。
- 引用：失效链接、孤立页（没有被任何节点挂载）、缺引用（事实性段落每段至少一个原子引用，KGE 第九章“引用完整率 100%”）、引用的原子哈希过期。
- 过期：时政等带有效期的原子过期即阻断（首期数学无时政，检查照做）。
- 公式：LaTeX 可解析；**SymPy 验算**页面中标记为等式 / 恒等变形的式子（`$$ ... $$` 内的 `=` 链，带 `% check` 标记的逐条验），不信模型文本；无法解析的公式报警告，标记了 `% check` 的无法验证则阻断。
- 规则 13：拦截疑似个人信息与学生标识（手机号、身份证号、学号式编号、UUID、姓名 + 学校组合等模式），引用群体统计时必须带人数且不低于门槛（门槛待人确认 #6）。
- 人设中立与适龄：角色名、口头禅、称呼（从 `docs/personas/` 只读抽取词表）、禁语 A–G 类、句长上限；命中即阻断。
- 语义体检（与原子冲突、跨页矛盾、超纲、角色语言混入的语义层）**不在本任务**：阶段 0 没有语义体检，中风险按高风险处理（与 release-gate-sprint4 #7 一致）。
- 体检结果：结构化 JSON（`check_type`、`severity`、`page_id`、`page_version`、定位），对应 KGE 第七章 `lint_issue` 字段，试点期只存于 CI 产物。

### 5. 知识服务读工具与 MCP
- 实现契约 v0.9 中只读的公共层工具：`node.get`、`node.path`、`page.get`、`item.search`、`item.similar`、`rubric.get`；`node.resolve` 用规则 + 全文（向量随 #5）；`evidence.write`、`mastery.get`、`mastery.explain` 属于个人层（KGE-04 / 学习服务），本任务继续回 501。
- `page.get`：从“已发布页面快照”（页面仓库主分支在合并窗口编进来的只读快照目录）读页面，按 `edition`、`region` 渲染投影（教材原句从 `kge.textbook_projection` 取）；`page_version` 与 `source_version` 按 ADR 12 由提交号映射，契约不改。
- MCP：同一组工具以 MCP 工具暴露给编排层（工具名 = operationId），只在服务内网监听；引入 MCP Python SDK（MIT）属新增依赖（待人确认 #4）。
- 契约一致性：接入现有 conformance（知识服务契约），严格模式下全部工具的请求 / 响应按 OpenAPI 校验。

### 6. 页面优先检索 + 切块兜底
- 查阅路径：定位节点 → 读已发布页面 → 按需查原子 → 兜底检索（页面未覆盖或置信度低时）→ 返回带引用的上下文包。
- 兜底首期用**全文检索**（jieba 分词 + Postgres tsvector，或进程内 BM25 实现，二选一见 #5）；向量检索（pgvector + BGE-M3 + bge-reranker）留接口，引入需人确认（新增本地模型与扩展）。
- 兜底命中记录进体检报告（KGE 第四章“兜底检索命中”是补页面的信号）。

### 7. 对照评测（页面优先 vs 切块检索）
- `evals/kge-compile/compare_retrieval.py`：同一套金标问答（教研提供，放仓库外或已脱敏入库），两条路径各跑，评：正确率（按金标答案要点匹配，判定规则可换）、同题讲法一致性（同题多次取回的上下文重合度）、单次上下文成本（token 估算）。
- 报告只含汇总与题目 ID；确定性输出；合成金标下的流程样例明确标注“不是评测结论”。
- M1 结论由人定：未达标则以切块检索为主路径进入封测（KGE 第九章）。

### 8. M1 指标报表
- `tools/kge-coverage` 增加 M1 报表：课标承接率（`curriculum_item` 被节点承接的比例）、知识点页发布率（kp 节点中有已发布页面的比例）、体检阻断数；留出集无处可标率沿用 KGE-02 的 `run_holdout.sh`（由教研负责人在封存环境跑，规则 14）。

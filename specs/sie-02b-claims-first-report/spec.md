## 设计要点
### 1. 洞察服务（新建 `services/insight/`，Python FastAPI，待人确认 #1）
- 只以 `starbuddy_insight` 写 `insight.*`；读 platform 推断与事实只经已授的只读权限；不写任何 platform 表（规则 11：判断只由洞察服务写入）。
- 实现契约 v0.9 的 `insight.claims`、`insight.explain`、`insight.context`（给 Agent 的上下文包）；`insight.record` 接编排层的行为事件（本任务只做契约校验与转存到已有写入路径，不新增来源）；`insight.dispute`、`insight.predict`、`insight.reconcile`、`insight.export`、`insight.erase` 回 501（冲刺 5 及以后）。
- 服务间鉴权沿用学习服务 / 知识服务的令牌做法（调用方绑定、常量时间比较）；只监听内网地址。

### 2. 判断生成（接入掌握状态）
- 输入：KGE 掌握估计（节点 × 认知层次的门槛、p、置信度、证据 ID）。KGE-04 第二步落地前，用**合成掌握行**（夹具）驱动，接口按 KGE-04 spec 第 13 节的形状写，不猜数据库字段。
- 规则：每个“节点 × 层次”一条判断，`basis_kind = mastery_estimate`；证据量与置信度达标（阈值为配置位，SIE 负责人与教研签字，未签字前只能生成“假设”状态）→ 成立；到期（按模板默认有效期，#5）→ 待验证；依据推断行被更正 → 撤回；验证不支持 → 推翻（验证题由 KGE 复测产生）。
- 每次流转在同一事务写原因与证据 ID（0010 守卫要求）；判断的 `value` 只放模板渲染用的少量变量，数值以依据行为准，判断不作任何计算输入（规则 2）。
- 首发只生成数学“知识掌握”“知识迁移”两类可见判断（`visibility` 含 student / guardian）；其他维度只生成 `visibility = {agent}` 的判断或根本不生成（见第 5 节）。

### 3. `insight.explain`
- 输入判断 ID，输出：结论（模板渲染结果）、状态与置信度说明、证据链（证据 ID、种类、等级、时间）、依据推断行版本、模型 / 算法版本；学生端、家长端调用时按可见范围过滤，看不到的判断连存在都不暴露（沿用 0010 前端策略）。
- 不输出任何不在判断账本里的陈述；不含禁用推断（SIE-00 词表检查）。

### 4. 首份画像报告（学生版、家长版）
- 模板渲染为主：报告只由“标题 + 固定衔接短语 + 判断渲染句”组成，每一句都带判断 ID；衔接短语与报告结构由人提供（必停，#3）；不调模型（与 KGE-04 #19 一致）。
- 渲染后跑两道检查：陈述—判断一致性检查（复用 KGE-04 的规则引擎：程度不升级、不新增结论）与禁用推断词表检查；任一不过则不出报告。
- 顶部固定标注“初步判断，两周内会变准”（文案由人确认）；假设状态的判断对学生显示为“初步判断”，对家长附置信度说明（SIE 图 2）。
- 交付形态：洞察服务生成报告的结构化内容（句子数组，每句带判断 ID）；BFF 学生端 / 家长端读接口（学生本人、已绑定家长按判断可见范围读）；页面随 4-H 统一壳，本任务只做开发环境演示页。

### 5. 中圈指标静默计算
- 八个指标按 SIE 第五章定义与最低样本：独立解题率、提示依赖度、迁移差、自评校准（Brier + 偏差方向，来自 2-L 探针与判分）、保持率、计划完成率、审题类错因占比、持续性。
- 结果只写 `visibility = {agent}` 的 metric 判断（或只存计算快照，#6），**不对学生、家长展示**，也不进首份报告；样本不足时不写。
- 不推断智力、性格、情绪、专注力等（规则 12）：指标名与说明过禁用推断词表检查。

### 6. 影子评审比对
- `evals/sie-shadow/`：比对首份报告的判断（节点 × 层次 × 状态）与影子评审教师的判断（金标，教研提供，`evals/**/gold/` 只读），报一致率与分歧清单；合成金标下只证明流程并标注“流程样例”。

### 默认方案
1. **C 授权再核对（迁移 0044 草稿，insight schema）**：新增 `insight.verify_actor(p_actor uuid, p_audience text, p_student uuid) returns boolean`，SECURITY DEFINER、属主 `starbuddy_authz`、只授 `starbuddy_insight`，做法同 0032 `raise_dispute`：学生本人（active 学生账号且 = p_student）或有效 `guardian_student_link`（未撤销、档案授权）才为真；不返回任何其他信息。洞察服务的 `ActorVerifier` 默认实现改调它（BFF 已核对的仍保留，两道都过才放行）。DB 测试（兄妹、另一户、撤销绑定、停用账号、非 insight 角色调用）、变异、快照、攻击面同步。

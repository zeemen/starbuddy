# PLT-14 第 2 步：月度计划生成与落库

2026-10-11 用户确认开始第二步。总 spec 见同目录 spec.md（含用户确认的四项口径）。含迁移、判断模板、套餐开关，提交首行 `[NEEDS-HUMAN]`。
本步只做生成与存储（含服务内读接口），家长端与学生端页面是第 3 步。

## 默认设计（写进 lessons 待人确认，可推翻）
1. **由洞察服务生成并写入**：月度计划里关于学生的陈述必须引用判断（规则 11），判断只由洞察服务写，计划快照也放 `insight.*`（ADR 02 insight 增补）。
   学习服务、BFF 不写计划表。
2. **触发**：洞察服务内部接口 `POST /internal/v1/monthly-plan/generate`（参数：student_id、month；调度角色或 BFF 服务令牌可调），同一学生同一月份幂等（已有快照直接返回，不写新行）。
   调度器（PLT-13）未做之前，由 BFF 在家长打开页面且本月无快照时调用（第 3 步接入）；本步提供接口与测试。
3. **套餐**：迁移新增套餐功能开关 `monthly_plan`，只对 Pro、Max 打开；未开时生成接口返回 `PLAN_NOT_ENTITLED`，不写行、不计量（自动月报不计次）。
4. **输入（只读）**：掌握状态与复测任务（KGE）、近期成绩（`insight.exam_record`）、考情分值权重（policy，无已发布数据时权重全为 1 并在快照里标 `policy_weights: default`）、
   当前有效绑定家长写的当前版诉求（`insight.guardian_goal`，只读关注学科与目标分；补充说明不读、不进计划；已解绑家长的诉求不读）。
5. **快照内容**（结构化 JSON + 模板键，不存渲染后的整段文字）：
   - `student_plan`：本月优先知识点（≤ 配置上限，合成 8 个）按 优先级 = 缺口 × 考情权重 × 频率 × 关注学科系数（合成 1.5）排序；每周建议次数与每次时长（复用今日计划预算配置）；本月到期复测与小复评安排（计数与日期）。
   - `guardian_notes`：从模板库按条件选取 ≤3 条（条件只用计划事实：复测次数、每周天数、是否临近考试等），模板只描述家长可做的安排，不评价孩子。
   - `review`：上月快照的完成情况（事实计数：计划节点中本月新点亮数、复测完成数）；分科目标分与最近一次录入成绩的差（只在两者都有时给出，给分差数值，不给概率、不预测）。
   - 每个关于学生的陈述（优先知识点“待点亮”、上月点亮、成绩差）都带它引用的判断 ID；没有可引用的“成立 / 假设”判断就不出这条。成绩差引用 exam 类判断，没有则不出。
   - `config_version`、`template_version`、`inputs_digest`、`generated_at`，便于重放。
6. **模板库**：`services/insight/templates/monthly_plan.v0.yaml`，所有文字 `{{TODO_COPY:monthly_plan.*}}` 占位，人写人审后才能填；模板与禁用推断词表、“名次 / 概率 / 承诺”词表（本步新增最小版，标草稿）测试通过。
7. **可见范围**：快照表 RLS 强制、无策略；读只经函数：家长视图（全部三段，含 guardian_notes 与 review，只给有效绑定家长）、学生视图（只有 student_plan，且不含任何来自家长诉求的字段或系数说明），第 3 步接 BFF。

## 不做
- 页面（第 3 步）；调度器；模型生成文字；中考总分、分数带、录取相关内容；读家长补充说明。

## 验收
- 同一输入重放结果逐字段一致；同学生同月第二次调用不写新行；非 Pro/Max 不生成。
- 快照中每条关于学生的陈述可追到存在且状态为成立/假设的判断；无判断时不出；禁用推断与新词表测试通过。
- 学生视图不含 guardian_notes、review、家长目标与关注学科系数；已解绑家长诉求不影响计划。
- 迁移在一次性库 up/down/up，RLS 与授权快照、攻击面、字段字典、个人层表清单（删除、导出）、渗透夹具、Gate 0 个人层清单同步；数据库与服务变异测试；严格 `make check` 通过。

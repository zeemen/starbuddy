## 现状（调研结论）
- **M1 报表只覆盖三项**，没有“核心节点内容完整率”：库里没有“核心节点”标记（0011 的 `knowledge_node` 无此列），“各层次均有题目与已发布页面”也没有统一计算。
- **各项指标分散在不同脚本**：kappa / Top-1（kge-tagging）、道法一致率（daofa-grading）、影子评审（sie-shadow）、覆盖矩阵（kge-coverage）各自出报告，没有汇总成“两科各自过门”的一页。
- **真实数据不在本仓**：真实地图、题目、页面、金标、留出集结果都要教研提供；本任务只能做汇总工具与准入检查，用合成数据证明。
- **C 级识别**：上传通道未上线，平台里还没有“识别置信 C 级”的数据来源；“C 级内容不生成结论”目前只能作为洞察服务与学习服务的输入约束写测试。

## 设计要点
### 1. 核心节点内容完整率
- “核心节点”清单：默认由教研在地图版本里用节点标签 `core`（沿用导入模板的 tags 字段，不改 schema）标注（#1）；没有标注时报“不可计算：核心节点未标注”，不推算。
- 完整：核心节点在其“应覆盖的每个认知层次”都有 ≥ 1 道已发布题目，且有与当前地图版本一致的已发布页面；完整率 = 完整的核心节点数 / 核心节点数，门槛 ≥ 95%；缺口清单按节点 × 层次列出（只含 ID）。
- 放在 `services/knowledge`（与 M1 同包，复用快照解析），作为 `knowledge.m2`。

### 2. M2 汇总报表（每科一页，数学、道法各一份）
- 输入（全部是已有脚本的报告文件或快照，报表只汇总不重算）：M1 报告、核心节点完整率、kge-tagging 的 kappa 与 Top-1 报告、daofa-grading 一致率报告（仅道法）、sie-shadow 报告（影子评审就位与比对流程可用）、留出集无处可标率（执行人填入的汇总数字与签名，本仓不读留出集，规则 14）。
- 每项输出：数值、门槛、来源文件哈希、“达到 / 未达到 / 不可计算 / 待填”；不下总结论（过门由人定），但列出所有未达到与不可计算项。
- 确定性输出（同输入逐字节相同）；只含汇总与 ID，不含学生数据。

### 3. 非知识类准入项（引用，不实现）
- 监护人同意与删除可用：引用 SIE-03 删除端到端测试结果与 J 流同意流程状态（未上线则“未达到”）；
- 安全测试通过：引用第二轮渗透测试报告（未执行则“待填”）；
- C 级内容不生成结论：新增约束测试——洞察服务判断生成与学习服务证据写入对带“识别置信 C 级”标记的输入不产生判断（若现有证据结构没有该标记，列待人确认 #4，并在报表中标“不适用：上传通道未上线”）。

### 4. 影子评审就位
- 名册不入仓（教师身份属于人员信息）：报表只收“数学 / 道法影子评审人数与排班覆盖周数”的汇总数字，由教研负责人填入；门槛默认每科 ≥ 2 人、覆盖寒假封测全周期（#3）。

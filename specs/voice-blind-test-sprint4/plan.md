# 冲刺 4-I：国内 ASR 与音素评测三家盲测方案

状态：**第一部分（方案 + 评测框架）已实现，待评审**。依据：本目录 `spec.md`（已确认，待人确认 #1–#5 按默认）、ADR 08（草稿）、ADR 09（草稿）、ADR 04、
完整方案 5.1 / 5.5 / 5.8 / 5.9 与第十一章、CLAUDE.md 规则 8、9、12、13 与必停清单。评测框架在 `evals/voice-blind/`。

> [NEEDS-HUMAN] 本方案涉及新增第三方服务与语音数据（L3 敏感个人信息）的处理路径。本任务**不选定、不接入任何供应商，不采集、不处理任何语音**；
> 候选名单、数据处理协议、第二阶段的启动都由人签字决定。第二部分“语音分钟计量辅助”等 services/bff 空出来后再做（见 lessons）。

## 1. 候选筛选标准

名单由人按 ADR 04 / 08 签字确定，本任务不选。进入盲测的候选必须**先过准入门槛**，再比较**评分项**。

### 1.1 准入门槛（任一项不满足即不进入盲测）
1. **境内处理与存储**：服务部署在中国大陆区域（公有云境内区域或私有化部署）；音频、转写、日志、备份都不出境（ADR 09 第 1、3 条）。
2. **数据处理协议可签**：能在 `docs/compliance/vendors.md` 登记四项——数据区域、保留期、是否用于训练、删除方式（ADR 09 第 6 条），并书面承诺：
   - **不用于训练**：音频与转写不用于任何模型训练、调优或人工质检抽样（含“产品改进”条款）；
   - **保留期**：服务端保留不超过处理所需时间（建议：处理完成即删，最长不超过 24 小时；日志中不含音频与转写）；
   - **删除承诺**：可按请求删除并出具删除确认；合同终止时全部删除；
   - **不做声纹**：不对我方音频提取声纹、说话人特征，不做说话人识别或验证；如产品默认开启此类功能，必须能关闭并写进协议。
3. **资质**：具备面向未成年人服务所需的合规资质（等保、算法 / 大模型备案等，以合规顾问意见为准）。
4. **接口能力**：ASR 支持流式识别（能测首字延迟）与中文、英文；发音评测支持中文与英文朗读、**音素级**对 / 错或分数输出与句级分数。
5. **计量可对齐**：按音频时长计费且能按分钟对账（与 `voice_realtime` 按分钟、向上取整的口径可对齐，迁移 0008 / 0015）。

### 1.2 评分项（盲测报告给数据，人来权衡）
| 维度 | 来源 |
|---|---|
| 准确率：中文 CER、英文 WER，分口音、分噪声 | 盲测报告 |
| 延迟：实时率、首字延迟 p50 / p95 | 盲测报告（端到端延迟另测：完整方案 5.9 要求语音延迟 p95 达标，ADR 08 引用的 PRD 目标是 ≤ 2 秒、上限 3 秒） |
| 发音评测一致性：音素级准确率、错误检出召回 / 精确、句级分数 Pearson / Spearman | 盲测报告 |
| 成本：每分钟单价（阶梯价、并发费、私有化费用） | 报价单，由采购填入第 5 节表格；框架不计算 |
| 合规条款：境内部署、不用于训练、保留期、删除承诺、不做声纹 | 协议条款，由合规顾问逐项核对（第 5 节） |
| 可用性：SLA、限流、故障通报 | 协议 |

## 2. 测试集设计（两阶段）

### 2.1 第一阶段：成人录制 + 授权公开语料（**本任务之后即可由人执行**）
**前提**
- 候选名单与数据处理协议已签字（第 1 节门槛全部满足），供应商已在 `docs/compliance/vendors.md` 登记为“已批准”；
- 录音人只能是**项目成员（成人）**，每人签书面知情同意（用途：本次盲测；保留期；删除方式；可撤回）；成人语音同样是敏感个人信息（L3），
  同样只在境内执行环境处理、评测完删除；
- 公开语料**逐一核对许可证**（允许商用评测、允许在境内处理、是否允许提交给第三方服务）并记录在执行记录里；许可证不清楚的不用；
- **不使用任何原产品留存的学生录音**（spec 待人确认 #3）。

**构成（建议规模，人可调整）**
| 语言 | 口音 | 条数 | 任务 | 噪声 |
|---|---|---|---|---|
| 中文 | 普通话（standard） | ≥ 200 | 朗读（课文、题干）与对话（提问、复述） | quiet / classroom / outdoor 各约三分之一 |
| 中文 | 带南京口音的普通话（nanjing） | ≥ 200 | 同上 | 同上 |
| 中文 | 其他口音（other） | ≥ 50 | 同上 | 同上 |
| 英文 | 标准 / 南京口音 / 其他 | 各 ≥ 100 / 100 / 50 | 初中英语朗读与对话脚本 | 同上 |
| 静音与纯噪声 | — | 约 20 | 参考文本为空，检查“幻听”插入 | 各条件 |

- 脚本由教研从教材风格改写，不含任何个人信息（清单校验会扫手机号、身份证号、邮箱）；口音与噪声是**采集场景标签**（按录音人自述与录音环境记录），不是推断；
- 噪声条件优先用真实环境录制；如用加噪合成，只能叠加许可证清楚的噪声素材，在境内执行环境里完成，记录信噪比；
- 发音评测的专家标注：两名有资质的标注员独立标注音素对 / 错与句级分数（0–100），不一致处第三人裁决；报告标注员间一致性（由人另算，框架暂不计算）；
- 每组（口音 × 语言）不少于 20 条才看分组结论；报告会列出少于 20 条的分组，提示“区间很宽，只作参考”。

### 2.2 第二阶段：学生语音（**前提全部满足后才能启动**）
**前提（缺一不可）**
1. **监护人同意流程已上线**（ADR 08 决定第 4 条：“盲测前必须先上线监护人同意流程”），同意记录进 `platform.consent_record`；
2. **用途分项授权**（`purpose_grant`，等合规方案建表）里“语音盲测”是**单独的一项**：与学习服务、画像、其他研究用途分开勾选，默认不勾，可随时撤回，撤回后该学生的音频立即删除、不再进入后续批次；
3. 学生本人知情（面向初中生的说明），可拒绝；拒绝不影响任何学习功能；
4. ADR 08、ADR 09 已签字，供应商已登记“已批准”，候选名单签字；
5. 境内执行环境就绪（第 6 节），且与 dev / staging 隔离（ADR 09 选项 C：dev / staging 只允许合成数据）。

**处理规则**
- 最小必要：只录朗读或对话脚本，不录自由闲聊；不记录姓名、学号、学校、班级；样本编号随机生成，不由任何身份信息派生；
- 只在境内执行环境处理；**音频原文件不进学生模型**（ADR 08 决定第 5 条、完整方案 5.5），不进任何 platform.* / kge.* / insight.* 表，不进仓库；
- 评测完成、报告定稿后**删除原音频、转写结果文件与清单**（含备份），删除记录写进执行记录；仓库只收**汇总报告**（报告只有汇总、分组指标与样本编号）；
- 口音标签只用于测试集分组，不写进任何学生档案，不用于对任何学生的判断（规则 11、12：不从群体推给个人）；
- 不做任何声纹、音色、情绪、说话人相关的分析；框架不读音频字节，指标只基于转写文本与发音评测输出。

## 3. 指标定义与计算口径（与 `evals/voice-blind` 实现一致）

### 3.1 识别错误率
- **编辑距离**：Levenshtein，替换、删除、插入代价都是 1；回溯优先对角线、再删除、再插入（确定性）。
- **中文 CER（按字）**：规范化后每个汉字一个单位。缺省规则（写进报告，可配置）：
  - 全角转半角（NFKC）开；去标点与符号（Unicode P* / S*）开；夹在中文里的拉丁字母小写开；
  - 中英混排：缺省拉丁字母、数字**逐字符**计（“AI”算 2 个单位）；可配置为连续拉丁串按一个单位计（`--zh-latin-as-word`）；
  - 空白只作分隔，不计入。
- **英文 WER（按词）**：空白分词。缺省：NFKC 开、大小写不敏感、去标点、保留词内撇号（don't 一个词；`--en-drop-apostrophe` 改为 dont）、连字符拆词（well-known → well known）。
- **错误率** =（替换 + 删除 + 插入）/ 参考单位数。
  - **合计口径**：Σ 错误 / Σ 参考单位数（按单位加权，不是逐条错误率的平均）；
  - **空参考**（静音 / 纯噪声样本）：单条错误率无定义，但其插入计入合计的分子；
  - **缺结果**（供应商超时或报错）：按转写为空计（全部删除），另报“缺结果”条数；
  - 错误率可以超过 1（插入多时）。
- 报告同时给替换、删除、插入、参考单位数的计数。

### 3.2 延迟
- 适配器在调用处测量（框架不计时，保证同样的结果文件得到逐字节相同的报告）：
  - **首字延迟**：从开始送音频到收到第一个识别字的秒数（流式接口）；
  - **总耗时**：从开始送音频到拿到最终结果的秒数；
- **实时率（RTF）** = 总耗时 / 音频时长；报告给逐条 RTF 的 p50 / p95 与合计 RTF（Σ 总耗时 / Σ 音频时长）；
- **分位数**：最近秩法（排序后取第 ceil(p·n) 个）；
- 送音频的方式（按实时速度推流还是一次性上传）影响首字延迟：执行时每家用同一种方式（缺省按实时速度推流），写进执行记录。

### 3.3 发音评测与专家标注的一致性
- **对齐**：供应商音素序列与专家音素序列按标签做最长公共子序列对齐（相同标签尽量对上）；
- 专家音素没对上 = 供应商“没判”：不计一致；专家标错时计漏检；供应商多出的音素不计；
- **音素级准确率** = 对 / 错判断一致的音素数 / 专家音素数；
- **错误检出**（正类 = 专家标为发音错误）：召回 = TP /（TP + FN），精确 = TP /（TP + FP）；
- **句级分数**：供应商分数与专家分数（0–100）的 Pearson 相关与 Spearman 相关（平均秩，并列取平均）；不足 2 条或方差为 0 时无定义；
- 供应商的音素集与专家标注规范不同时，由执行人在适配器里映射到专家规范（映射表写进执行记录，评测前冻结）。

### 3.4 分组与区间
- 分组：ASR 按 语言、语言 × 口音、语言 × 噪声；延迟按 全部、语言；发音评测按 语言、语言 × 口音；
- **置信区间**：按样本有放回重抽的自助法，1000 次，百分位法（最近秩）取 2.5% 与 97.5%；种子是固定字符串（缺省 `voice-blind/1`，
  每个指标、分组、编号派生子种子），同样输入逐次相同；某次重抽统计量无定义就丢掉那一次；
- 比较两家时看区间是否重叠只是粗略参考；是否需要配对检验由人决定（lessons 待人确认）。

## 4. 盲测流程与随机编号

### 4.1 角色分离
| 角色 | 职责 | 看得到什么 |
|---|---|---|
| **执行人**（工程，1 人） | 在境内执行环境里调用各家、收集结果文件、跑 `score` 生成报告 | 供应商身份（必须知道才能调用）；**不参与评分与选型讨论** |
| **揭盲人**（产品负责人指定，1 人，不是执行人、不是评分人） | 持有编号种子与编号表，报告定稿后揭盲 | 编号表 |
| **评分人 / 评审**（教研、产品、技术） | 只看报告（VA、VB、VC），写选型建议初稿 | 只有盲测编号 |
| **专家标注员** | 标注音素与句级分数 | 只有音频与参考文本，**不知道**任何供应商结果 |

### 4.2 编号
- **供应商编号**：`blind.assign_codes(供应商 ID, 编号种子)`——排序后按种子洗牌，得到 VA、VB、VC…；编号种子由揭盲人生成并保管，不写进仓库、不写进报告；
  报告只记编号表的 sha256（`--key-sha256`），揭盲时核对；
- **条目编号**：提交给供应商的是随机条目编号（`I-` + 随机十六进制），供应商看不到样本编号、口音、噪声标签；**ASR 请求不含参考文本**；
- **同一批音频**：每家收到完全相同的音频集合；**提交顺序每家各自随机**（避免时段、顺序效应）；
- 执行期间各家交错进行（同一时段内轮流），避免某家只在网络好的时段测。

### 4.3 流程
1. 揭盲人生成编号种子，把编号表（供应商 ID → 编号）交给执行人用于命名结果文件，自己留存编号表的 sha256；
2. 执行人按编号跑各家，结果文件命名为 `VA.asr.jsonl`、`VA.pron.jsonl`…（只放执行环境）；
3. 执行人跑 `score` 生成报告，把报告（只有汇总）提交到仓库；
4. 评审只看报告写选型建议初稿（第一轮，不知道供应商）；
5. 选型建议初稿定稿后，揭盲人公布编号表，评审核对 sha256，再结合成本与合规条款写最终建议（第二轮）；
6. 执行人按第 2.2 / 6 节删除音频、结果文件与清单，删除记录进执行记录。

## 6. 执行手册

| 项 | 要求 |
|---|---|
| 执行人 | 工程 1 人（技术负责人指定）；不是揭盲人、不是评分人；签保密与删除承诺 |
| 机器 | 境内云的专用评测主机或容器：中国大陆区域、磁盘加密、无公网入站、出站只放行已批准供应商的主机名；与 pilot / prod、dev / staging 隔离；**不是开发者本机** |
| 软件 | 仓库当前提交的 `evals/voice-blind`（记录提交号）；Python 3.11 + PyYAML；适配器在候选签字后另起任务实现（实现 `AsrVendor` / `PronunciationVendor`，自行测量延迟） |
| 密钥 | 由执行环境的密钥管理注入适配器；框架不读环境变量与密钥；密钥不进仓库、日志、报告 |

**步骤**
1. **准备**：核对第 5 节 C1–C12 全部通过（第一阶段不需要 C9）；记录仓库提交号、适配器版本、各家接口版本；
2. **清单**：在执行环境里写清单（`format: voice-blind-manifest/1`，`synthetic: false`，音频引用用 `store://` 键），跑一次 `score` 的前置校验（清单错误退出码 2，消息只有字段名与编号）；
3. **编号**：揭盲人交付编号表；执行人按编号命名结果文件；
4. **执行**：每家同一批音频、各自随机顺序（`vendor.run_asr` / `run_pron`），交错进行；结果写到执行环境里的仓库外目录（`vendor.write_results`）；
   非合成清单的结果目录放在仓库里会被拒绝；
5. **生成报告**：
   ```bash
   python evals/voice-blind/run_blind.py score --manifest <清单> --results <结果目录> \
     --out <报告目录> --key-sha256 <揭盲人给的编号表 sha256>
   ```
   规范化规则如需改动（例如标点计入），全部供应商用同一套参数，并写进执行记录；
6. **提交位置**：只把报告目录（`voice-blind.md`、`voice-blind.json`）提交到 `evals/voice-blind/reports/<阶段>-<日期>/`
   （例如 `reports/phase1-2026-11-20/`），PR 首行 `[NEEDS-HUMAN]`；**不得**写进任何 `gold/` 目录（框架拒绝）；
   执行记录（提交号、版本、许可证核对、同意书编号、删除记录）放在合规负责人指定的内部位置，不进仓库；
7. **评审与揭盲**：按第 4.3 节两轮进行；选型建议另起文档，由人签字；
8. **删除**：报告合入后 7 天内删除音频、结果文件、清单与备份，删除记录留档；第二阶段按监护人授权里写明的保留期执行，以较短者为准。

**合成样例**（任何人都可以在仓库里跑，只证明流程）：
```bash
services/learning/.venv/bin/python evals/voice-blind/run_blind.py sample \
  --manifest evals/voice-blind/fixtures/manifest-synthetic.yaml --out evals/voice-blind/reports/sample-synthetic
```
样例报告头标“流程样例，不是评测结论”。

## 7. 风险与待人确认
见 `lessons.md` 的“待人确认”。主要风险：第二阶段时间取决于监护人同意流程与 `purpose_grant` 上线；南京口音样本量不足会让分组区间很宽；
供应商音素集与专家规范不一致时映射本身会引入误差；首字延迟受执行环境网络影响，只能在同一环境内横向比较。

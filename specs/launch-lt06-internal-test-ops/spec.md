# LT-06 内部成员测试运营支撑（W6–W7，specs/launch-test-2026）

2026-10-24 起由 Claude 推进。目标：12 月内部成员（团队、教研、员工自愿家庭）在 staging 上测试时，能**受控邀请、留存同意、收集问题、按人撤出**，且全程可审计。仓库内不含任何真实人员信息。

## 现状
- 登录：staging 白名单固定码 OTP（LT-01），条目由管理员以挂载文件下发，无管理界面。
- 同意：BFF 只收由人登记的真实同意书版本；同意书文本由合规顾问提供（未到）。
- 反馈：没有问题反馈入口；审核台只服务教研复核。
- 撤出：家长删除请求已有（数据权利，5-H），但没有“退出测试”的整套流程。

## 范围（默认，待人确认）
1. **邀请与白名单运营**：命令行工具 `tools/internal-test/`：生成白名单 OTP 条目（批次、有效窗口 ≤ 24 小时）、按批次作废、导出审计摘要（只含条目 ID、事件、时间与手机号 HMAC，不含码与号码），供管理员在跳板执行；手机号只在执行机内存中出现。
2. **同意书签署流程核对**：走查 BFF 与前端现有同意写入路径，确保：未签两份文书不能进入学习；监护人与学生分别确认；14 岁以下必须监护人同意；版本号与签署时间入库可查；补缺口与测试（不写同意书文本）。
3. **问题反馈入口**：学生端与家长端一个“反馈问题”入口（固定分类 + 自由文本 ≤ 500 字，可选附当前页面路由模板，不自动附截图、不采集设备指纹）；反馈经 BFF 写入新表（迁移草稿，必停）或先写结构化日志 + 审核台只读列表（二选一）；自由文本按日志白名单原则不进 SLS，只进库；审核台增“反馈”只读页（员工登录）。
4. **退出测试**：家长发起“退出测试” = 撤回同意 + 走现有删除流程 + 作废其白名单条目；结果可在审核台核对。
5. **测试运营手册**：`docs/ops/internal-test-runbook.md`：招募口径（自愿、可随时退出、不影响员工考核）、签署、发码、值守、问题分级与响应时限、退出、测试结束后的数据处置。

## 不做
- 同意书与隐私政策文本（合规顾问）；短信厂商；对外招募；任何关于学生的新陈述（规则 11）。

## 验收
- 工具与流程有测试；反馈不含禁止字段、不进日志；退出流程端到端测试；严格 `make check` 通过。

## 待人确认
1. 反馈存储：新表（迁移草稿，待人执行）还是只进审核台可读的结构化存储。
2. 反馈是否允许学生（未成年人）直接提交，还是只允许家长与员工提交。
3. 退出测试后的数据处置：立即删除，还是保留到测试结束统一删除（按同意书约定）。

## 决定记录（2026-10-24，用户）
1. 反馈存新表：迁移草稿 `platform.feedback`（RLS；只 BFF 写；审核台员工只读；来源列标“学生自述 / 家长观察 / 员工”，规则 6），草稿待人在副本演练后执行（必停）。
2. 学生也可以提交反馈（固定分类 + 短文本 ≤ 500 字）：自由文本只作反馈处理，**不得进入判断账本、画像或任何关于学生的陈述**（规则 11、12），不进日志与 SLS；同意书须覆盖（合规顾问提供文本时确认）。
3. 退出测试：撤回同意 + 作废白名单条目 + 停止一切新数据写入与模型处理；已有数据保留到测试结束统一删除（按同意书约定），审核台可核对状态；测试结束统一删除走现有删除流程并有手册步骤。

## 决定记录（续，2026-10-24，用户；来自安全与契约审查）
4. 退出判据下沉到库层并全服务过滤：0059 增加不依赖调用者身份的 `platform.student_processing_allowed(student)`（未退出、未删除、有有效同意），授权学习、洞察、调度角色；各批量任务（周报、档案页编译、指标判断、掌握对账、判分抽检）与学习服务写入 / 模型处理入口统一过滤或拒绝；BFF 判据不再挂 internal_test 开关（开关只控制反馈 / 退出路由）；库层拒绝已退出档案重新签同意与签发学生会话；补跨服务测试。属迁移与权限变更，必停。
5. 退出作废白名单条目改为按账号：库函数只返回账号 ID，不返回手机号摘要；白名单条目在固定码登录成功时与账号对应（记入状态与审计）；只在该家长已无其他在测孩子时作废其条目。
6. 学生模式“两份同意书均须已签”核对只在内测开关下生效（pilot 等保持原口径：14 岁以下才要求监护人同意）；同步改 shell.v0 描述。

## 一、现状
- BFF 的再练、复测列表条目只有 `node_id`（公共知识层的 ID），前端在“知识点”列原样显示编号。
- 今日计划（`/today`）的条目同时给 `node_id` 和 `node_name`：BFF 在 RLS 下查已发布、未停用的地图节点名，查不到时为空，界面显示中性标题。
- 两张列表用 `.trust-table`。窄屏只缩小了内边距（`globals.css` 的 `@media (max-width: 767px)`），没有改排列方式。

## 二、默认做法
1. **BFF 加 `node_name`**：再练、复测列表的每个条目加 `node_name: string | null`。查询与今日计划同一句（已发布地图、`status = 'active'`、在 `withAccount` 下读），一次列表只查一次（按去重后的节点 ID 批量查）。
   - 查不到名称（节点没发布、已停用、查询失败）时为 `null`，**列表照常返回**，不因为拿不到名称而失败。
   - 两份接口定义加这个字段（可空）；`tests/shell-openapi.test.ts` 的响应核对随之更新。
   - 学习服务、契约、迁移都不改：名称只由 BFF 从公共知识层读，不进个人层。
2. **前端显示名称**：“知识点”列有 `node_name` 时显示名称；没有时显示编号（与现在一样），编号仍放在 `data-value="node"`、名称另放 `data-value="node-name"`，测试与爬取规则照常能定位。
3. **手机上改卡片排列**（只在 `max-width: 767px` 下，桌面不变）：
   - 每一行显示成一张卡片，每个格子前面带列名，列名取自已有的表头文案（经 `data-label` 属性，用 CSS `::before` 显示，不新增文案）。
   - 表头在窄屏上视觉隐藏，但仍留给读屏软件。
   - 为了保住读屏软件的表格语义（`display: block` 会让部分浏览器丢掉表格角色），表格各层显式加 `role`（table / rowgroup / row / columnheader / cell）。
   - “再练一道同类题”“开始”等按钮仍满足 44px 触控目标。
4. **测试**：
   - BFF 单测：名称查得到、查不到（未发布、已停用）、查询抛错三种情况；列表都正常返回，后两种 `node_name` 为 `null`。
   - BFF 变异：去掉“只取已发布”的条件、查询失败时让列表失败，各一条。
   - 前端静态检查：两页的“知识点”格子优先用 `node_name`；窄屏样式存在且只在 767px 以下生效。
   - 端到端（practice-on 那一套）：桌面宽度下有名称的条目显示名称；390 宽下没有横向滚动、每张卡片的格子带列名、axe 无障碍检查不退化。
   - 合成数据：端到端里再练、复测列表来自合成学习服务桩（`apps/web/scripts/fake-learning-practice.ts`），它给的节点 ID（`MATH.SYN.P1.*`）
     不在任何地图里，名称会全为空。让桩里一部分条目改用合成种子里已发布地图的节点 ID（星图合成种子里已有），“有名称”“没名称”两种情况都能测到；
     不改种子、不改迁移。

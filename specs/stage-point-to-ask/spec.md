# 讲解白板上“指着元素提问”：结构化的提问对象与白板选取 · 规格草稿

- 状态：**草稿，待用户确认第五节**。
- 来源：OpenMAIC 借鉴分析 v1.1 第八节第 4 条（用户 2026-11-25“已合并，按建议起草指着元素提问的规格”）。
  - 借鉴 OpenMAIC 1.1.0 的做法：学生可以指着幻灯片、白板或互动组件上的某个元素提问，提问的上下文是结构化的“指的是哪个元素”，而不是一段自由描述。
  - 借鉴分析里我们的落法是：学生点白板上的某一步或题图上的某个点，问“这一步为什么”，上下文结构化、少自由输入、便于审核；回答需要直播态，随讲评课第二步。
  - 只借交互思路，不引入代码或依赖。
- 依据：
  - ADR 07 决定 4：渲染器只接收已审核 DSL，学生作答只在内存渲染；
  - `specs/stage-dsl-v0.2`（`point`、槽位、台词稿）、`specs/stage-dsl-versioning`；
  - 插件契约 `TeachRequest` / `TeachSegment`（`packages/contracts/openapi/plugin-api.v1.1.yaml`）；
  - CLAUDE.md 规则 3、7、11、12、13。
- 必停项判断：**本任务只做第一阶段，不涉及必停项**。
  - 范围：`packages/stage` 与 `/dev/stage` 样张页，零新依赖。
  - 第二阶段（回答）同时碰契约、人设话术、计量、模型调用，全是必停，本规格只列出边界，见第三节。
  - 菜单与提示的文字是面向学生的新文案，按惯例只放 `{{TODO_COPY:...}}` 占位，人写人审。

## 一、现状（2026-11-25 核对）
- **没有直播态**：
  - 播放器（`packages/stage/src/player.ts`）只有播放、暂停、逐步前进后退与跳转，文件头写明“不做 live（学生插话转实时需要模型，另起）”；
  - 阿鸦的 `teach` v0 是确定性的：提示阶梯 + 知识页面直出，不调模型，不读对话。
- **契约里提问只能是自由文字**：`TeachRequest.conversation` 是 `{ role, content ≤ 4000 字 }` 的对话历史，没有“学生指的是哪个元素”的结构化字段。
- **前端没有讲评课页面**：白板只在开发样张页 `/dev/stage` 上播放一份合成样例，元素不可点。
- **能复用的现成结构**：
  - DSL v0.2 的元素都有 id；
  - 文档顶层声明了题图、学生作答两种槽位；
  - `boardAt(dsl, cursor)` 能算出任一时刻白板上有哪些元素。
  “指着什么”所需的定位信息，已有结构都能表达。

## 二、默认做法（第一阶段：只做“指”和“问什么”，不做“答”）
1. **提问对象**（新文件 `packages/stage/src/question.ts`）：
   `StageQuestion = { dsl_version, cursor, anchor: { kind, id }, intent }`
   - `anchor.kind`：
     - `element`：白板上的元素；
     - `slot`：题图或学生作答槽位；
     - `step`：整一步，用于指着字幕或步骤条问。
   - `intent` 是固定的四个编码，**不收自由文字**：

     | 编码 | 意思 | 处理 |
     |---|---|---|
     | `why_step` | 这一步为什么这样做 | 交给回答通道（第二阶段） |
     | `what_is` | 这里是什么意思 | 同上 |
     | `where_from` | 这个是从哪来的 | 同上 |
     | `again` | 再讲一遍这一步 | **本地处理**：跳回该元素所在那一步的开头重放，不出提问对象 |

   - 提问对象只含 DSL 里的 id、步数与编码，**不含任何学生数据**：
     - 指着学生作答槽位时，只带槽位 id；
     - 槽位里的内容运行时在内存里，不进提问对象。
2. **校验**：新函数 `validateStageQuestion(dsl, q)`，只收校验过的 DSL，规则是“只能指已经出现的东西”，不能借提问提前看后面的讲解：
   - `element`：必须在 `boardAt(dsl, cursor)` 的白板上；高亮框不能单独被指，要指它高亮的那个元素；
   - `slot`：必须是文档声明过的槽位；
   - `step`：必须是已经播放过的步（序号 < cursor）；
   - 其他检查：版本必须等于当前 `DSL_VERSION`；字段白名单；`cursor` 在 1..总步数之间。
   - 错误码：`not_visible`、`unknown_anchor`、`bad_intent`、`bad_version`、`bad_cursor`、`unknown_field`。
3. **元素来自哪一步**：
   - `boardAt` 的结果给每个元素记上它是第几步写上去的（`origin_step`）。“再讲一遍”跳回这一步；第二阶段把这一步的台词编号带给回答通道作上下文。
   - 这只是渲染侧的内部结构，**不改 DSL 序列化格式**，不升版本（`specs/stage-dsl-versioning` 第二节第 1 条）。
4. **白板的“可提问”模式**：`Whiteboard` 新增可选属性 `askable`，缺省关闭。关闭时输出与现在逐字节相同，快照不变。打开时：
   - **可选取的东西**：
     - 白板上每个元素（高亮框除外）和每个槽位，各盖一层透明的点击区；
     - 点击区四周留白，换算到屏幕不小于 44 × 44 CSS 像素；
     - 每个点击区都是 `role="button"`、可 Tab 聚焦，回车或空格选中。
   - **读屏标签**：只说“第 n 步 · 第 k 项”，用占位文案，不念 DSL 里的文字与公式原文，因为公式原文对读屏没有意义。
   - **选中的样式**：虚线细框，与老师的“指”区分。老师的聚光是实线粗框，激光笔是小三角。**只用形状与线宽区分，不靠颜色**。
   - **正在播放时选中**：先暂停，播放器发一次 `pause`，避免学生还在挑问题时讲解继续往下走。
   - **选中后的菜单**：弹出四个按钮，用占位文案；Esc 或点空白处取消，焦点回到原元素。
   - **选完问题之后**：
     - `again` → 播放器跳到 `origin_step` 的开头；
     - 其他三种 → 组件调用方传入的 `onAsk(question)`，组件自己不联网、不存储。
5. **样张页 `/dev/stage`**：
   - 打开可提问模式；
   - `onAsk` 只在白板下方显示一行合成占位，例如“（合成）已收到：第 3 步 · 为什么”，说明回答要等第二阶段；
   - 不发任何请求，不写任何存储。
6. **测试**：
   - 校验：每个错误码的正反例；“未来的元素”（还没播放到）一律 `not_visible`；高亮框不能被指；槽位只认已声明的。
   - `boardAt` 的 `origin_step`：每个元素记的步正确；清屏后再写，记新的步。
   - 渲染：
     - 不开可提问模式时快照逐字节不变；
     - 开启时的 SSR 快照：点击区、`role` 与 `tabindex`、选中虚线框；
     - 点击区的最小尺寸；
     - 不渲染任何 DSL 以外的文字。
   - 端到端（`/dev/stage`）：
     - 键盘 Tab 到元素、回车选中，出现菜单；
     - 选“再讲一遍”跳回对应那一步；
     - 选“为什么”出现合成占位；
     - 播放中选中会暂停；Esc 取消后焦点回到原元素；
     - axe 不退化。
   - 变异：校验放过未来元素、放过高亮框、版本不核对、`again` 跳错步、播放中选中不暂停、不开模式时也输出点击区等。
   - 要通过：`make stage-test`、`make stage-mutation`、`make check-fast`、`make web-test`；零新依赖。

## 三、不做（第二阶段：回答。全部必停，等讲评课第二步另起）
- **契约**：
  - `TeachRequest` 增加结构化的 `question` 字段：锚点、意图编码、所在讲解段与台词编号，取代把“指的是哪里”写进自由文字；
  - 讲评课的 `TeachSegment` 怎么携带台词稿（`specs/stage-dsl-v0.2` 第三节已列）。
- **模型回答与人设**：
  - 回答由常驻老师或点点主持，Prompt 与话术走人设流程，跑人设回归；
  - 回答只讲内容，不写关于学生的判断（契约 `TeachSegment` 的约束、规则 11）；
  - 回答要过禁用推断词表，并复用 `specs/quote-verbatim-guard` 的引语规则：引用学生作答必须逐字。
- **提示等级**：作答提交之前，回答不得给出超过 `allowed_hint_level` 的内容（阿鸦 teach 的答案守门同一口径）。
- **数据边界**：
  - 指着学生作答槽位提问时，上下文含学生作答，属个人层：只用境内已备案模型（规则 13），不进公共知识层；
  - 指着白板元素或题图，上下文只有已审核的公共内容。
- **计量**：每次提问按什么资源扣（`lesson_whiteboard` 按节、`ai_active_time` 按时长，还是单列），必停。
- **提问记录**：默认**不作证据**，不按学生存、不进画像。“问得多”不代表不会，用来推断属规则 12 的边界。
  只考虑以“某一步被问了多少次”的聚合统计回流给教研改讲解，设最小人数门槛（规则 13）。见第五节第 4 条。
- **自由文字提问、语音插话、实时语音**（`voice_realtime` 另计）；直播态的打断与续播。

## 四、验收
- 样张页上能用鼠标和键盘指着白板元素、槽位或某一步，选四种问题之一：
  - “再讲一遍”跳回对应那一步；
  - 其余三种得到一个通过校验的提问对象，页面上显示合成占位。
- 只能指已经出现的东西；提问对象不含学生数据；不联网、不落库。
- 不开可提问模式时，白板输出逐字节不变。
- 第二节第 6 条列的检查全部通过；零新依赖；契约、BFF、学习服务、计量无改动。

## 五、待人确认（括号里是默认）
1. **能问哪几种问题**：`why_step` / `what_is` / `where_from` / `again` 四种（默认），按钮文字由产品与人设定；还是先只做“为什么”和“再讲一遍”两种？
2. **要不要自由文字**：第一阶段不收（默认）；第二阶段要不要允许一句短文字补充，等审核与人设流程就绪后再议。
3. **能指什么**：白板元素、题图槽位、学生作答槽位、整一步，都能指（默认）。指学生作答时，第二阶段只能走境内模型；还是第一阶段先不让指学生作答？
4. **提问记录**：不作证据、不按学生存，只考虑以后按步骤做最小人数门槛的聚合统计（默认）；还是第二阶段要把提问记成行为事件？记成行为事件要另过 SIE 字段字典与禁用推断评审。
5. **播放中选中**：自动暂停（默认）；还是不暂停，等这一步讲完再弹菜单？

## 一、范围（三部分，按顺序做；B 是必停项）

### A. 节点表导出（给中台打标用；不涉及必停项）
- 新命令：知识服务里加一个只读导出（暂定 `python -m knowledge.export.node_table`），从**已发布地图版本的公共层快照**（`knowledge.atoms` 格式，与对照评测同一来源）导出中台需求单附录 A.2 的节点表：
  - 每行：`node_id`、`map_version`、`subject`、`name`、`parent_node_id`、`level`、`kind`，以及教材投影（版本编码、版次年份、册、章、起止页码、核对状态；可以多条）；
  - 与需求单附录 A.2 的差异（快照里没有，如实说明，不编造）：节点没有“别名”字段，`aliases` 输出空数组；投影没有单独的“出版社”字段，只有版本编码（如 `bubian-2024`）。见待人确认第 6 条；
  - 格式：JSON Lines 与 CSV 各一份，UTF-8，同样输入逐字节相同；附一个清单文件（地图版本、行数、sha256）。
- 新命令：两个地图版本之间的 **ID 迁移表**（`old_node_id`、`new_node_id`、`map_version_from`、`map_version_to`，外加拆分 / 合并 / 退役规则）。来源是 `kge.id_migration`（迁移草稿 0011）——它不在公共层快照里，所以这个命令用知识服务的只读角色读库；导出工具不自己推断。测试用一次性 Postgres 与合成数据。
- 只导出已发布版本；草稿版本、被扣下的节点不导出。不含任何个人数据（公共层，规则 13）。
- 测试用合成地图（`MATH.SYN.*`），不碰真实教研数据。

### B. 知识服务契约 v0.10 草案（**必停**：契约变更，PR 首行 `[NEEDS-HUMAN]`）
- 新文件 `knowledge-service.v0.10.yaml`，按插件 API v1.1 候选版的做法：**只做增量**，v0.9 的 10 个工具、schema、示例逐项不变，契约测试证明这一点。
- 新增工具 `standard.search`（标准知识检索，ADR 16 第 3.2 节）：
  - 请求：公共层上下文（不带学生标识）+ 查询文本 + **必填过滤维度**（学科、学段年级、省份、出版社、版本、学期；适用时加考试年份、地区、考试类型）+ `content_types`（教材小节、知识点、题目、试卷、编译页）+ `top_k`；
  - 缺必填维度时返回 400，不做全库检索；
  - 响应：命中片段（正文、WeKnora 内容 ID、中台内容 ID、节点 ID、来源字段、分数），沿用统一信封：`evidence_ids` 为空，`source_version` 带 WeKnora 知识库版本与内容 ID，`confidence` 由分数映射；
  - 查询文本可能来自学生：数据级别按 L2，知识服务与 WeKnora 侧都不落库、不留日志（ADR 16 第 3.5 节，待技术验证 V17）。
- `item.search`、`item.similar`：工具名与请求形状保留；实现改由 WeKnora 支撑（第三部分），契约只补必要的可选字段（例如相似题的查询方式）。是否返回题干与解析见待人确认第 3 条。
- 契约测试、一致性测试按现有套件补齐：示例符合 schema、反例被拒、v0.9 不变。

### C. 知识服务的 WeKnora 后端（开关关）
- 知识服务内新增 WeKnora 读取层：
  - 只用 `tools/weknora-probe` 已有的客户端（只读检索密钥，地址与密钥只从环境变量读）；
  - 由开关 `knowledge.weknora_backend` 控制，**默认关**；关时 `item.search`、`item.similar` 仍走现在的 SQL 实现，行为不变；
  - 过滤怎么落到 WeKnora（允许清单、组合标签或分库）做成可替换的策略，**等技术验证 V07 的结论再定默认**；现在先实现“允许清单”一种，并用模拟 WeKnora 测；
  - 结果映射回 StarBuddy 的 ID：WeKnora 内容 ID → 中台内容 ID → `platform.item`（来源字段 `source_ref`，迁移 0039）。
- 测试只用模拟 WeKnora 与合成数据。

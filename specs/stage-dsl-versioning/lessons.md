## 与 spec 的差异
- **合成阶梯用“过去的版本”**（0.0.1 → 0.0.2 → 0.1.0），而不是 spec 写的 0.1.0 → 0.1.9 → 0.2.0：迁移后要过完整校验，校验器只认当前版本 0.1.0，
  所以合成阶梯必须落在 0.1.0 上才能把机制走完。效果相同。
- **文字核对按每一级做，并允许迁移声明旧字段名**（`textKeys`）：spec 只说“迁移前后文字逐字相同”；实现时发现字段改名的迁移（例如 `heading` → `title`）
  按当前字段名取不到旧文字，所以每级迁移可写明 from 版本装文字的字段名，执行器按它核对。声明错了同样拒收（测试覆盖）。
- 指纹只覆盖导出的格式常量；校验器内部的判断（例如文字安全规则的正则）改了不会改变指纹，仍靠评审与现有校验器测试把关。已写进 README 的“版本规则”口径。

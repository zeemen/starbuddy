# 冲刺 1-E：实现记录与待人确认

按 spec“待人确认”的默认方案实现（用户 2026-09-26 指示）：
1. 订阅挂家庭，额度桶按学生席位；
2. 周期滚动 30 天；
3. MAX 公平使用上限到顶硬停（`fair_use_margin` 默认 0）；
4. 预留过期时间、单次上限先填草案值；
5. 幂等键与学习服务共用一个；
6. 选科上限函数放到 2-E；
7. 试点虚拟额度按 PRO 发放，全量走账本（`source = 'pilot_virtual'`）；
8. 流水保留期待合规意见，本迁移不做清理。

## 结果
- **迁移** `0008_platform__metering`：
  - 8 张表、3 个视图、7 个保护触发器函数，外加 1 个锁键函数；
  - 四级额度种子。
  - up → down → up 通过。
- **数据库测试** `db/tests/60_metering.sql`：新增 156 项断言，db-test 共 318 项。覆盖：
  - 种子与第八章逐格比对；
  - 配置生命周期与完整性；
  - 订阅状态机；
  - 额度桶身份与周期；
  - 预留状态机与写入限制；
  - 流水写入核对、只追加、更正规则；
  - 对账视图能发现六类篡改；
  - RLS 与按列授权：两户家长、学生本人、同手机号、未登录、学习服务、复核、授权属主；
  - 授权用 `has_*_privilege` 逐角色检查。
- **测试辅助**：新增 `t.throws_like`，同时核对 SQLSTATE 和错误信息，防止断言被另一条同码规则顶替。
- **变异测试**：新增 51 个，db-mutation 共 118 个。
- **设计文档** `docs/design/metering-schema.md`：
  - ER 图、状态机；
  - 18 条不变式，每条都对应测试和变异；
  - Gate 0 六类场景走读，含 2-E 必须遵守的授权、幂等键、加锁顺序规则；
  - 与学习服务“结果未知”的对接时序；
  - 资源类型、契约方法与 key 的对照；
  - 签字栏。

## 合并前审查（安全审查、契约守护）修复的问题
**阻断项**：
- **对账视图不核对流水的种类和数量**：失败后仍扣费、多扣，两个视图都查不出来。
  - 修复：新增 `guard_ledger_insert`，写入时按预留核对种类、数量、条数；`reservation_ledger_mismatch` 也改成核对种类和数量。
- **24 小时复看的并发方案无效**：advisory 锁在预留提交时就释放了。
  - 修复：设计改为查到仍在处理中的同键记录时返回 409。
- **更正不校验目标**：可以跨额度桶、跨家庭，可以正向多扣，也可以重复退款。
  - 修复：组合自引用外键，外加触发器校验方向和累计量。
- **预留表的 RLS 测试是空转的**：夹具里没有另一户的预留。
  - 修复：补上 S2 的预留和对应断言，加变异“预留对所有登录用户可读”。
- **设计没写 2-E 函数的授权和幂等键归属**：补在设计文档 4.0 节。

**高、中严重度**：
- 过期后同 key 重试的处理：见设计文档场景 5。
- 计量指纹的算法：去掉 `request_id` 和 `usage_id`；`usage_id` 由 key 派生。
- 内容指纹改由 BFF 在调用前计算，不改契约。
- 降级字段：新增 `next_tier`、`next_config_version`。
- `source_method` 收窄为契约里的消耗类方法。
- 错题解析的单次上限改为 1。
- 订阅状态机；额度桶的冻结与不重叠；预留的数量与过期时间上限。
- 所有数量改为整数。
- 按种类限定操作者。
- 配置发布前检查完整性，并用 advisory 锁防并发。
- 禁止 TRUNCATE。
- BFF 对预留表只按列授权。
- 保护函数去掉 SECURITY DEFINER，并 REVOKE PUBLIC。
- 余额视图计入公平使用余量，并按来源分行。

## 待人确认
1. **付费档的 `diagnosis_screen` 改为 1**。第一版填的是 0，契约守护指出那会把付费用户的筛查挡住。第八章只给普通会员写了“1 次筛查”，第三章说入口筛查是免费的，5.8 节的计量清单里也没有筛查。现在按“高档不少于低档”取 1。请产品负责人确认两件事：
   - 筛查是否要计量；
   - 付费档是 1 次还是不限次。
2. **预留过期时间与单次上限都是草案值**（spec #4）：

   | 资源 | 过期时间 | 单次上限 |
   |---|---|---|
   | 筛查、完整诊断、错题解析 | 10 分钟 | 1 |
   | 模考 | 150 分钟 | 1 |
   | 讲评课 | 90 分钟 | 1 |
   | 语音、AI 时长 | 30 分钟 | 30 分钟 |

   完整诊断、模考、讲评课都在**提交时**预留，所以过期时间按处理时长定。
3. **24 小时复看改为按学生去重**（spec 与 ADR 06 第 3 条写的是按家庭）。改的原因：
   - 按家庭去重时，兄弟姐妹的记录会互相引用。只绑定其中一个孩子的家长，可以由此推断另一个孩子的使用情况。
   - 额度桶本来就按学生分。

   代价：兄弟姐妹在 24 小时内看同一道题，会各扣一次。现在由外键强制，如果要改回按家庭，需要删掉 `reservation_dedup_same_student_fk`，并重新评估隐私影响。请产品负责人决定。
4. **过期后迟到的成功不扣费**（设计文档场景 5），宁可少扣不多扣；补记也要人工决定。是否接受？
5. **过期后同 key 重试可能在没有预留的情况下执行一次**：学习服务对之前失败过的同 key 请求会接管并重新执行。要堵住这个缺口，需要学习服务提供“只查询、不执行”的重放接口。这是 `learning-internal` 的契约变更（必停项），建议放进 v1.0 评审清单。
6. **对账视图只给运维**：BFF 没有权限，也还没有专门的运维只读角色。巡检任务用哪个角色跑，要和 ADR 03 调度一起定。
7. **`resource_type`、`plan_config` 的写入没有函数**：只能由迁移或人工（超级用户）写。发布新配置是否要走审批函数、由谁执行，待定。
8. **流水分区只建到 2027-12**（与证据表相同）：续建依赖 ADR 05 的调度任务，目前还不存在。分区本身没有开 RLS，靠“分区不单独授权”保护。要不要让 `ensure_monthly_partitions` 建分区时顺手开 RLS，需要改 0004 的共享函数，本 PR 没有动。
9. **流水与未成年人删除权**：订阅和流水都引用学生档案，没有级联删除，流水又是只追加的。学生档案因此删不掉。要和合规意见（spec #8）一起定：是做匿名化，还是按财务保留期保留。
10. **流水的 `actor` 多了一个 `system`**：spec 只写了“BFF 或人工”。但过期任务、周期授予、升级补差既不是用户请求也不是人工操作，所以单独列出，并按流水种类限定了操作者。
11. **与 spec 的文字差异**：
    - spec 第 6 节写的是 `settled_at`，实现用 `finished_at`（三种终态共用）；
    - spec 第 3 节写“升级追加一条 grant 调整流水”，实现用的种类是 `adjust`。
    - `max_active_subjects` 的上限 7 没有写进种子，`all_launched` 由选科函数（2-E）按已上线学科数解释。
12. **`resource_type.pool` 目前没有地方使用**：语音单独成池，要等语音额度的扣减规则定下来，由 2-E 使用。

## 实现中的发现
- **流水外键需要 `entitlement (id, student_id)` 唯一**：第一版漏了，迁移执行失败。
- **测试曾经空转**：
  - 测试配置只复制了额度、没复制权益，所以“已发布配置的权益不能改”那条 UPDATE 影响 0 行；
  - 预留的 RLS 断言因为夹具里没有另一户的预留，恒为真。

  以后凡是断言“这条语句会被拒绝”或“看不到别人的”，都要先确认：语句确实命中了行；夹具里确实有“别人的”数据。
- **同一个 SQLSTATE 会互相顶替**：改用 `t.throws_like` 后，立刻发现“结算流水不能为负”其实是被新加的数量核对规则拦下的。`ledger_nonnegative` 这条规则原本没有被真正测到。
- **PL/pgSQL 的 `IF` 条件里不能直接写 `CASE … THEN`**：`IF` 解析条件时遇到第一个 `THEN` 就停，会报语法错误。先把 `CASE` 的结果算进变量再比较。
- **分区表的自引用外键**：Postgres 16 支持。副作用是分区被外键引用，不能单独 TRUNCATE，正好补上“分区不受父表 TRUNCATE 触发器保护”的缺口。约束要显式命名，因为自动生成的名字会被截断，而且每个分区各有一份。
- **余额视图必须是 `security_invoker`**：否则视图以属主身份执行，会绕过 RLS。已有变异守着这一条。

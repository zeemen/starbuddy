# LT-05 可观测性：指标、日志、告警与备份恢复演练（W3–W4，specs/launch-test-2026）

2026-10-23 起由 Claude 推进。目标：staging 内部成员测试期间能及时发现故障、计量异常、模型成本超支与个人信息泄漏风险，并能按手册恢复。仓库内不含真实地址、凭据、告警接收人联系方式；开通监控产品、配置接收人由人完成。

## 现状
- 各服务只有日志与新加的 `/healthz`、`/readyz`；没有指标端点、告警规则、仪表盘。
- 模型路由调用记录、成本护栏、计量账本已有元数据（只记日志）。

## 范围（默认，待人确认）
1. **指标**：学习、洞察、知识、调度器、BFF、审核台后端暴露 Prometheus 文本格式 `/metrics`（仅 Pod 内网，单独端口或与健康端点同口径免鉴权但 NetworkPolicy 只放行采集器）。指标只含服务、路由模板、方法、状态码、学科、任务类型等低基数标签，**禁止任何学生 / 家长 / 账号标识、手机号、内容**（有测试与变异）。核心指标：请求数与时延直方图、错误率、库连接池、模型路由调用 / 失败 / 熔断 / 护栏剩余 / 估算成本、计量预留 / 结算 / 回滚 / 409 计数、复核队列积压、调度器任务成败。
2. **日志**：统一结构化 JSON（时间、级别、服务、请求 ID、路由模板、状态、耗时），脱敏规则集中实现（手机号、邮箱、身份证、令牌、作答原文一律不入日志），已有日志调用迁移到统一格式；有测试扫描禁止字段。
3. **告警规则**（`deploy/observability/alerts.yaml`，Prometheus 规则格式）：服务不可用、5xx 率、p95 时延、readyz 失败、模型供应商熔断与护栏将满、计量回滚 / 409 异常升高、复核队列积压、调度器失败、证书与磁盘；阈值为占位缺省，由人签字（SLO 通过线）。规则用 promtool 类离线校验（工具缺失时用 Python 校验结构与表达式引用的指标名都真实存在）。
4. **仪表盘**：Grafana JSON（总览、模型与成本、计量、学习链路），只引用已登记指标。
5. **阿里云接入草案**：ACK 托管 Prometheus（ARMS）采集配置与 SLS 日志采集配置写进 LT-03 的 IaC / k8s 草案；告警通知渠道由人配置。
6. **备份恢复演练**：在 LT-03 演练手册基础上补“每周恢复到副本并校验行数 / 校验和”的脚本（只连副本，复用 mark-replica 限定）。
7. 测试与变异：指标标签白名单、日志脱敏、告警规则引用一致性。

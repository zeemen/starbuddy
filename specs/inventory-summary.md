状态：草稿（2026-09-25）
依据：
- ClaudeCode 执行方案 v1.0 第八章“W1 周三：汇总与疑点”要求的五项；
- 四科盘点 `specs/inventory-{aya,wenli,zhixing,echo}/`，其中 inventory、adapter-design v0.2、decisions 均已于 2026-09-25 由负责人确认；
- 完整方案 v1.0 第 5.2 节（融合工作量三档）、开发计划风险表。

口径：只汇总四份盘点里已有的事实和结论，不补新判断。需要新判断的地方写在“需要人决定”里。

## 结论先说

1. **四科都没有真实用户，也没有任何模块能确认“已上线”**。53 个模块里：可演示 18 个，半成品 21 个，仅方案 14 个（26%）。
2. **开口成章“仅方案”占 42%（10/24），超过了开发计划风险表的 40% 收缩阈值**。知行 36%，接近阈值。按风险表的应对，阶段 1 应先上数学 + 道法，语文和英语延后一个月。这与寒假试点只做“数学 + 道法”的原计划一致，但需要人确认是否正式触发收缩。
3. **适配器工作量**：文砺、阿鸦中；知行中偏重；开口成章重。瓶颈不在代码，而在**内容准入与版权**：四科的题库、范文、材料几乎全部是“来源待核”或未准入，教研过审之前只能以 `practice` 语义运行，不能推动星亮门槛。
4. **Gate 0 契约覆盖率与已定决策有冲突**：开口成章的目标是 ≥ 4/6，但 decisions A1 把阶段 0 的接入范围定为 3 个方法（见第四节）。
5. 编号疑点共 71 条：已关闭 36 条，上线前必须解决 16 条，待人决定或待提供输入 19 条（第五节）。另有 legacy 已知缺陷 32 条，只读不修，由平台侧规避。

## 二、数据建模差异对照

| 维度 | 文砺 | 阿鸦 | 知行 | 开口成章 |
|---|---|---|---|---|
| 存储 | Supabase，35 个迁移，48 张表，全开 RLS | 学习状态以浏览器 localStorage 为准，整份 JSON 同步到 Supabase 一张 `profiles` 表；另有 6 张表代码不用 | 寄宿在文砺库里（迁移 0033–0035），与语文共用同一个 Supabase | **没有数据库**，全部在 localStorage |
| 学生 | `profiles` | `profiles.data`（整份 StudentProfile） | 共用文砺 `profiles` | localStorage 里的 profile |
| 家长关系 | `guardians` + 一次性邀请码，多对多；有越权风险（WENLI-KD-03） | **没有家长实体**，家长与学生共用账号，靠可被学生绕过的“二次密码” | 没有建模，daofa 表没有家长读取策略 | 同一设备上的一次勾选 |
| 是否按手机号关联 | 否 | 否（没有 phone 字段） | 否 | 否 |
| 能力坐标 | 7 域 × 4 级 = 28 点（`ability_state`）+ 知识点级 Beta（`point_mastery`） | 100 个能力点 + 五图谱；32 章 939 个节点 | 五维 running average（`daofa_ability`）；坐标用五维还是“过程四步”待教研定 | 五维雷达，数值是固定增量，不是掌握度估计 |
| 错因 | 六类（`error_t`）；阅读模块 6 大类 15 个标签 | 十二类根因，429 个陷阱码 | 采分点归因四类 | 语法、词汇、达意三维；发音没有引擎 |
| 证据与推断 | 混存，诊断直接写 `ability_state` 和 `error_record` | 混存；猜对也加掌握度 | 判分和能力行学生可写（ZHIXING-KD-04） | 不落库 |

**对平台 Schema 的含义**：平台 `platform.*` 学习者模型（已合并，zeemen/starbuddy#6）是唯一真相源。四科原有的掌握度数据都只作为算法参考，不迁移（四科 decisions）。错因跨科映射见 `docs/mapping/error-taxonomy.md`（已合并，zeemen/starbuddy#7，待教研签字）。

## 四、适配器工作量评估

分档依据完整方案 5.2：数据层最轻（映射即可），角色层中等（按规范迁移），前端与语音最重。

| 学科 | 工作量 | 理由 | 阶段 0 计划接入（adapter-design v0.2） | Gate 0 覆盖率目标 |
|---|---|---|---|---|
| 数学 · 阿鸦 | **中** | diagnose、grade（客观题）、report 是纯函数，可以直接包装；人设不迁移，但 teach 要按规格书 V1.1 重写。难点：学习状态要从 localStorage 改为平台证据；验证器 v0 只覆盖部分题型，边界情况一律复核；721 道题全部是 Q1，其中 693 道来源待核 | 6/6（teach 放在人设重写之后） | 6/6 |
| 语文 · 文砺 | **中** | 代码最成熟（520 个提交、48 张表），六个方法都有对应代码。难点：所有直接写学习者表的路由都要改为经契约写入；特级教师改为妙笔，人设层重写；主观判分一律复核，金标准还没有；教材全文与 Z-Library 教辅有版权问题 | 6/6（先 grade、diagnose、generate_variation） | ≥ 5/6 |
| 道法 · 知行 | **中偏重** | 主体代码在文砺仓库里（`apps/daofa`），F1–F3 可演示，但 F4、F6、F8、F11 仅方案。内置题只有 2 道，都来源待核；时政只能取自白名单源；RLS 漏洞需要在平台侧重建；人设迁移为点点主持、方圆出场，是四科里第一个迁移 | 冲刺 4 覆盖 5/6，plan 放到之后 | ≥ 5/6 |
| 英语 · 开口成章 | **重** | 没有数据库，没有账号，API 是开放代理；语音链要全部换成境内供应商（ADR 08、09）；仅方案占 42%；人设要改（学伴并入点点、考官定名雅典娜、NPC 不得否认 AI 身份） | **3/6**：异步 grade、diagnose、report（decisions A1） | ≥ 4/6 |

### 与 Gate 0 的冲突（需要人决定）
- **开口成章**：Gate 0 软条件要求契约覆盖率 ≥ 4/6，开发计划冲刺 4 写的是“开口成章补 plan”。但 echo decisions A1 与 adapter-design v0.2 把阶段 0 定为只接 3 个方法，plan 放到阶段 1。可选：
  - (a) 冲刺 4 按开发计划补 plan（五步单元闭环模板，只输出前置关系，不做自适应）；
  - (b) 把 Gate 0 这一条改为 3/6。

  软条件不过可以带条件进入阶段 1，但需要在阶段 1 首月关闭。

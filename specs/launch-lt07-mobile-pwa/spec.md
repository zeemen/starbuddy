# LT-07 前端移动端与 PWA 体验打磨（W6，specs/launch-test-2026）

2026-10-24 起由 Claude 推进。目标：12 月内部成员主要用手机（微信内置浏览器、iOS Safari、安卓 Chrome）访问 staging，学生端与家长端核心流程在 360–430px 宽度下可用、可读、可点，能“添加到主屏幕”。不改人设话术（家长端文案改动属必停，单列）。

## 现状
- apps/web（Next.js）已有统一壳、今日计划、星图、诊断 / 再练 / 复测、家长端周报 / 对账卡 / 数据权利、反馈与退出页；有单测、视觉回归、axe、端到端。
- 没有 Web App Manifest、图标、Service Worker；未系统核对移动端布局。

## 范围（默认，待人确认）
1. **移动端布局走查与修复**：核心页面在 360 / 390 / 430 宽度下无横向滚动、触控目标 ≥ 44px、字号 ≥ 16px（输入框避免 iOS 缩放）、安全区（刘海 / 底部横条）适配、软键盘不遮挡输入与提交；星图在小屏的缩放与平移；表格类（对账卡）改卡片式。视觉回归加入三种移动宽度的快照。
2. **PWA**：Manifest（名称、图标占位、`display: standalone`、主题色）；Service Worker **只缓存静态壳与构建产物**，任何 API 响应、学生数据、页面 HTML 都不缓存（network-only），登出时清理缓存；离线时显示固定离线页。不做推送通知。
3. **微信内置浏览器兼容**：识别 UA 后提示“在浏览器中打开”以使用添加到主屏幕；核对 cookie（SameSite / Secure）、OTP 输入（`autocomplete="one-time-code"`）与跳转在微信内正常。
4. **性能**：移动 3G 节流下首屏可交互目标（占位，待签字 SLO）；包体积预算检查进 web-test。
5. **可访问性**：axe 在移动视口重跑；屏幕阅读器标签核对。
6. 测试：Playwright 移动设备配置（iPhone 13、Pixel 7、360 宽）跑端到端与视觉回归；Service Worker 不缓存 API 的测试。

## 不做
- 推送通知、原生 App、小程序；家长端与学生端话术修改（另起必停任务并跑人设回归）；真实图标与品牌视觉（设计提供前用占位）。

## 验收
- 三种移动宽度下核心流程端到端通过、视觉回归基线更新、axe 无严重问题、SW 缓存范围测试通过；严格 `make check` 通过。

## 待人确认
1. PWA 离线策略：只缓存静态壳、不缓存任何数据（默认）。
2. 微信内置浏览器：引导“在浏览器中打开”（默认），还是适配微信内添加到桌面的限制。
3. 图标与主题色：设计提供前用占位。

## 决定记录（2026-10-24，用户）
1. PWA 只缓存静态壳与构建产物；任何 API 响应、学生数据、页面 HTML 不缓存，登出清缓存，离线显示固定页；不做推送。
2. 微信内置浏览器：内部可正常登录使用；添加到主屏幕时提示“在浏览器中打开”。
3. 图标与主题色在设计提供前用占位。

# 学习服务 · 冲刺 1-C：实现记录与待人确认

按 spec“待人确认”八项的默认方案实现（用户 2026-09-25 指示“按默认方案开始实现”）：
1. asyncpg，不用 psycopg 3；
2. 内部接口放在 `packages/contracts/openapi/learning-internal.v0.yaml`（方案 a，必停项）；
3. 两张不分区的表做幂等（迁移 `0007`，必停项）；
4. 不写 `review_task`；
5. 租约 60 秒；
6. 摘要只给 ID、verdict、semantics、human_review_required、跨科大类；
7. 保留期暂不实现（见下）；
8. 只检查内容已登记，不自动登记。

## 待人确认
1. **迁移 `0007` 由人执行**：新增 `platform.ingest_request`、`platform.evidence_registry` 两张表，以及它们的 RLS 和授权。已完成的测试：
   - `db/tests/50_ingest_idempotency.sql` 有 20 条正反向断言；
   - `db/tests/mutations.sh` 新增 5 个变异，全部能被发现。
2. **内部接口 OpenAPI 放进了 `packages/contracts`**（必停项）。它的请求体直接引用 `plugin-api.v0.9.yaml` 的 `GradeRequest` 和 `DiagnoseRequest`，没有另起一份。
3. **certifi 是 MPL-2.0**：它是 httpx 的传递依赖，只提供 CA 证书包。MPL 是文件级弱著佐权，不修改就没有义务。是否接受？
4. **幂等记录的保留期**（spec #7）：默认 30 天，但本冲刺没有实现清理任务。它和证据表的保留期一起，等 ADR 09 与合规顾问意见定了再做。
5. **attempt 必须能区分**：diagnose 里两道作答的题目和作答时间都相同时，直接返回 422。原因是平台靠 item_ref + occurred_at 把作答和作答证据对上（契约守护 N6）。如果以后确有同一时刻的重复作答，需要在契约里给证据加 `attempt_id` 引用，属于契约变更。
6. **数据库约束拦下的结果**一律返回 502 `ADAPTER_RESULT_REJECTED`，detail 只写 SQLSTATE 和约束名。数据库报错原文会带出整行数据，所以不转发。例如“总分超过满分”，契约把它交给平台侧校验，这里就是由数据库约束拦下的。
7. **重放的摘要键顺序**会和第一次不同：jsonb 不保留键顺序。内容相同，BFF 不应按字节比较。
8. **适配器在租约内没有返回时**（租约已从 60 秒改为 90 秒，长于 diagnose 调用的总预算 61 秒），新请求会接管并再调一次适配器，所以适配器可能被调用两次。
   - 结果相同：适配器按 key 和请求体确定性派生证据 ID，平台也沿用同一个 attempt_id。
   - 不会重复扣次：计量不在这里。
   - 迟到的那一次落库时会发现租约已不归自己，于是放弃写入。

9. **验证器 / Rubric 注册表还不存在**（契约守护应修 1）。契约要求平台对照注册表核实 `rule_ref`，不在表里的按模型判分处理，
   但 schema 里还没有注册表。现在 `judged_by = verifier` 配任意 `rule_ref` 都会按非主观、高置信落库。
   建议在冲刺 2-G 或发布闸门（4-G）建表，这属于迁移，是必停项。
10. **总分与维度分之和不做一致性校验**：契约没有规定权重，总分不一定等于维度分之和。
    数据库只保证总分不超过满分、维度分不超过维度满分。是否要在契约里写明计分规则？
11. **可重试错误属于“结果未知”**（安全审查 S7）：已写进 `learning-internal.v0.yaml` 的“计量”一节。
    BFF 遇到 `retryable: true` 或自己超时时，不能直接回滚计量，必须用同一个 key 重试确认。需要在 ADR 06 里一并确认。
12. **同一证据被不同请求引用**：`evidence_registry` 发现同 ID 同内容时跳过写入，但第二个请求的判分与推断照样写入，并挂在第一条证据上。
    这是按“证据只记一次、推断可以多次”的设计，是否接受？
13. **适配器令牌与地址**：非回环地址必须是 https，令牌至少 32 个字符。启动时校验。
14. **Postgres 服务端日志**：应用已经不转发数据库报错原文。但 Postgres 自己的日志默认会记下约束报错的 DETAIL，也就是整行数据，可能含学生作答。
    部署时需要规定服务端的日志级别和保留期，属于运维配置。
15. **学习服务不检查选课和授权状态**：`subject_enrollment`、consent 都由 BFF 在调用前负责，已写进内部 API 文档。

## 合并前审查（安全审查、契约守护）已修复
- **阻断：适配器的错误码可以夹带文本**。`isupper()` 会放过“张三A”这类文本，现在只转发符合 `[A-Z][A-Z0-9_]{0,47}` 的编码；`detail` 一律不转发。
- **阻断：`media_ref` 由适配器随意填写**，可能把别的学生的照片记在这个学生名下。现在只能取本次请求里出现过的引用。
- **阻断：`prior_evidence` 原样信任**。现在按 ID 回查平台库，必须属于同一学生、同一学科，准入状态以平台为准。
- **阻断：同 key 请求可以轮流接管、互相抢占**。接管分支也受总期限约束；租约改为 90 秒，长于适配器调用的总预算；适配器调用整体有 `asyncio.timeout` 上限。有测试：租约故意配得过短时，两个请求都能返回，且至多写一次。
- **阻断：申诉不强制复核**。现在由平台补上 `student_appeal` 并要求复核。
- **核对补齐**：
  - `rubric_version` 必须一致；
  - 含照片或语音的证据要求请求声明为 L3；
  - 作答证据的内容必须等于学生作答；
  - 不能有不属于本次作答的作答证据；
  - 拒绝 NaN 和 Infinity；
  - 时间必须是带时区的 RFC 3339。
- **`attempt_id` 全局唯一**：落库前检查，冲突时返回 409 `ATTEMPT_ID_CONFLICT`。
- **出站请求**：不读代理环境变量，不跟随重定向；适配器响应体限 5 MB；适配器的 401/403 映射为 502。
- **同 key 等待**：改为指数退避加抖动，最多等一个租约，之后返回 503 `BUSY` 并带 `retry-after`。
- **请求体**：边读边限，上限改为 16 MB，因为合法的 200 道作答 diagnose 可能超过 1 MB；`request_id` 按全匹配校验。
- **证据摘要**：不再包含准入状态。题目的准入状态之后变严，同一证据重试也不会被误判为“内容不同”。
- **0007**：撤销触发器函数对 PUBLIC 的执行权；补了 5 条 RLS 断言，覆盖 BFF 写入、复核角色和授权属主读取。

## 实现中的发现
- **asyncpg 按 SQL 里的类型转换推断参数类型**：写 `$1::timestamptz` 时要求传 datetime 对象。现在一律写成 `$1::text::timestamptz` 或 `$1::text::numeric`，由数据库解析文本。
- **数据库报错会泄露数据**：Postgres 的约束报错带 “Failing row contains (...)”，里面可能有学生作答。所以落库异常只取 SQLSTATE 和约束名，日志里只记异常类名。有测试断言。
- **阿鸦适配器的 `persist.ts` 已删除**：端到端测试改为“学习服务 → 阿鸦适配器（真实 HTTP 进程）→ 平台库”，放在 `services/learning/tests/test_e2e_aya.py`。
  原阿鸦 e2e 里有一条断言：内容登记 1 / 959 / 721 / 721，重复执行也不重复登记。它迁到了同一个文件。
- **校验内部接口 OpenAPI**：用 openapi-spec-validator 校验过，合法，但没有接入 `make check`。
  - `contract-test` 目前只检查 `plugin-api.v0.9.yaml`，接入需要改 `check_contract.py`，留给契约评审时一起做。
  - `learning-internal.v0.yaml` 的请求体用相对路径引用 plugin-api。`internal_contract()` 目前只用来校验摘要和 Problem；以后如果拿它校验请求体，要先解析跨文件引用。

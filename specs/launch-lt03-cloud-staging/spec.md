# LT-03 境内云 staging 环境配置与镜像构建（W2–W4，specs/launch-test-2026）

2026-10-21 起由 Claude 推进。目标：把 LT-01 的厂商无关部署草案转为选定境内云厂商的 staging 配置（基础设施即代码草案），并让镜像能在该厂商的构建与镜像仓库中实际构建、扫描；补 HTTP 健康检查端点。**不创建任何真实云资源、不含真实账号 / 密钥 / 地址**；开通、账号、计费、网络与资源创建、执行 IaC 由人完成。

## 依据
- ADR 09 / 10（选项 B 托管栈：托管 Postgres + 对象存储 + 容器，认证由 BFF 自建）；launch-test-2026 决定：12 月前只做境内 staging、不对外、不做 ICP。
- LT-01 lessons 待人确认 1、6；LT-02 lessons 待人确认 1（出网按主机名放行需云厂商出网网关 / FQDN 策略）。
- 选型建议 V1.0：模型主平台阿里云百炼（同云可减少跨云出网与数据流转）。

## 范围（默认，待人确认）
1. **IaC 草案**（`deploy/iac/<厂商>/`，Terraform，不含状态文件与凭据）：VPC 与子网、托管 Postgres（版本与 0001–0058 迁移兼容、境内地域、私网访问、自动备份与 PITR、TLS）、对象存储桶（私有、加密、生命周期）、容器服务（托管 K8s 或 Serverless 容器，按 LT-01 k8s 清单）、镜像仓库、出网网关 / NAT + FQDN 白名单（只放行模型供应商主机）、日志服务（脱敏、留存期）、密钥管理（KMS / 密钥托管，挂载为 secretKeyRef）。`terraform validate` + 静态规则检查（tfsec / checkov 类，若许可证与离线可用）进 `deploy-check`；不执行 `plan / apply`。
2. **k8s 清单厂商化**：存储类、负载均衡（只内网 + 访问受控，例如办公网 / VPN 白名单）、托管 PG 连接（TLS、主机名核对，补 LT-01 待人确认 6 的“只给主机名”的连接核对）、镜像地址模板。
3. **镜像构建流水线**：厂商构建服务或 CI 模板（构建、SBOM、漏洞扫描、签名、推送到私有仓库），基础镜像从厂商镜像仓库按摘要拉取；本机继续只做静态校验。
4. **HTTP 健康检查端点**：五个服务与审核台后端补 `/healthz`（存活）与 `/readyz`（就绪：库连接、关键配置、0058 等启动前置），不暴露版本外的内部信息；探针由 TCP 改 HTTP。涉及各服务内部 OpenAPI（非学科契约）。
5. **备份恢复与回滚演练脚本**：托管 PG 快照恢复到副本、迁移回滚（down）演练步骤（由人执行）。
6. 测试：IaC 静态检查、清单与 env-inventory 一致、健康端点测试与变异。

## 不做
- 创建真实资源、执行 IaC、真实密钥与地址、域名与证书（内网访问）、ICP、等保测评、监控告警平台接入（另起 LT-05 可观测性）。

## 验收
- IaC 草案 `validate` 与静态检查通过；清单一致性测试通过；健康端点测试通过；严格 `make check` 通过；人工执行手册齐全。

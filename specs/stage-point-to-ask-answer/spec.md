# 指着元素提问 · 第二阶段：回答 · 规格草稿

- 状态：**草稿，待用户确认第五节**。本阶段从头到尾都是必停项（契约、人设话术、模型调用、计量，可能还有迁移）。
  所以规格确认后拆成几个 PR，每个 PR 首行写 `[NEEDS-HUMAN]`，由人逐个审，见第二节第 7 条。
- 来源：`specs/stage-point-to-ask` 第三节（第二阶段的边界）；用户 2026-11-26“已合并，按建议起草指着元素提问第二阶段的规格”。
- 依据：
  - 插件契约 `teach`（`packages/contracts/openapi/plugin-api.v1.1.yaml`）：
    - `TeachRequest` 有提示等级上限 `allowed_hint_level`、人设与 Prompt 版本、平台给的对话历史；
    - `TeachSegment` 只讲内容，不写关于学生的判断；
    - `TeachResult` 带 `hint_level_used`、AI 身份披露、`referral_triggered`。
  - ADR 04（按数据级别路由；T1 教学对话、T9 内容安全与人设守卫）、ADR 09（L2 及以上只在境内处理）。
  - 计量 0008、0009：`lesson_whiteboard` 按节、只认 `teach`；`ai_active_time` 按分钟、认 `teach` / `grade`。
  - ADR 07 决定 4：渲染器只收已审核 DSL，学生作答只在内存渲染。
  - 阿鸦 `teach` v0 的答案守门（0–3 级提示不得含标准答案，作答提交前最多给到第 3 级）。
  - `specs/quote-verbatim-guard`、`specs/lesson-acceptance-checklist`。
  - CLAUDE.md 规则 3、4、7、11、12、13。

## 一、现状（2026-11-26 核对）
- **第一阶段已有**（`packages/stage/src/question.ts`）：
  - 提问对象 `StageQuestion { dsl_version, cursor, anchor, intent }`，四种意图：为什么、是什么、从哪来、再讲一遍；只能指已经出现的东西，不含学生数据；
  - “再讲一遍”在本地重放；另外三种只在样张页显示占位。
- **契约里没有结构化提问**：`TeachRequest` 只有 `conversation`（每轮 ≤ 4000 字的自由文字）。“作答提交了没有”的字段也没有，阿鸦 `teach` v0 因此一律按“未提交”守门。
- **没有回答通道**：
  - BFF 没有 `teach` 路由；阿鸦 `teach` v0 是确定性的，不调模型；
  - 平台没有存对话记录的表，`conversation` 所说的“平台从自己的存储中取出”还不存在。
- **模型路由与计量的现成件**：
  - 模型路由：T1（教学对话）只收 L0–L2，T9 守卫收 L0–L3；staging 只有合成供应商。
  - 计量：`lesson_whiteboard` 是“按节一次”，`ai_active_time` 是“按分钟”。

## 二、默认做法
分两步：**先 2a“预制答疑”（不调模型）**，再 2b“模型回答”（有守门）。2a 用审过的文字先把交互跑通，风险最小；2b 等人设回归与守门就绪再开。

1. **契约：结构化提问**（必停）
   - `TeachRequest` 增加可选字段 `question`，只在 `mode: lesson` 时出现：

     | 字段 | 内容 |
     |---|---|
     | `lesson_ref` | 已发布讲评课的内容 ID 与版本 |
     | `dsl_version`、`cursor`、`anchor`、`intent` | 与第一阶段的提问对象同形 |

     不收自由文字；有 `question` 时 `conversation` 必须为空。
   - **讲解内容由服务端按 `lesson_ref` 取已发布、已审核的那一版，不收客户端传来的 DSL 或台词**。服务端再用第一阶段的 `validateStageQuestion` 核一遍“只能指已经出现的东西”。
   - `TeachRequest` 同时补 `answer_submitted: boolean`，表示本节讲评的这道题学生提交过没有。阿鸦 v0 的“提交前最多第 3 级”守门因此可以按实情放开（lessons 遗留项）。
   - `TeachResult` 不加字段：回答就是 `segments`（只允许 `text`），照常带 `hint_level_used` 与 `referral_triggered`。
2. **2a 预制答疑：台词稿增加“答疑”**（DSL 与台词稿格式变化，升到 0.3.0，人设话术必停）
   - 台词稿新增可选 `answers: [{ step, intent, line }]`：某一步、某种问法对应一句台词稿里的台词，由人设审核、教研核对内容。
   - 回答只能从这里取，**找不到就不答**。不答时给一句固定的兜底，加“再讲一遍”按钮。兜底文字是新话术，用占位。
   - 版本按 `specs/stage-dsl-versioning` 的五步升：
     - `0.2.0 → 0.3.0` 的迁移只补空的 `answers`；
     - 校验器核对答疑引用的步与台词都存在、问法是三种之一（不含“再讲一遍”）、同一步同一问法只有一句；
     - 答疑台词同样受每句长度、句数与安全检查约束。
   - 计量：答疑不另扣，算在这节课已经扣过的 `lesson_whiteboard` 里；不调模型，没有新成本。
3. **2b 模型回答**（模型调用、人设、计量都必停；只在 2a 上线后另开）
   - **走 T1 教学对话**，数据级别 L2（学生在讲评课里的问答属于对话记录），只路由境内已备案模型（规则 13，ADR 09）。
   - **上下文由服务端组装，只放这一问需要的东西**：
     - 所指元素所在那一步的板书文字与台词；
     - 题面；
     - 意图编码。
   - **指着学生作答槽位时**：只在作答是键盘输入（`response_text` 且来自 keypad）时才带上作答原文。拍照或语音转写的作答属 L3，T1 不收，这种情况只答题图与讲解，不带作答。
   - **输出守门**，按顺序，任一不过就回到 2a 的兜底，不显示模型原文：
     1. 只收纯文字，最多 2 句、≤ 120 字（数字待人设定）；
     2. **不露答案**：作答提交前，输出里不得出现这道题的标准答案或关键步骤结果。口径与阿鸦 `hintRevealsAnswer` 一致，规范化后做包含检查。实际提示等级不得超过 `allowed_hint_level`；
     3. 引用学生原话必须逐字（`quote-verbatim-guard`），否则整句丢弃；
     4. 禁用推断词表不命中，不出现关于学生的判断（与一致性检查同一套词表）；
     5. T9 人设守卫通过；需要转介时置 `referral_triggered` 并走人设规格书的转介话术，不答题。
   - **成本**：
     - 每节课最多问 N 次（默认 10），超出后只剩“再讲一遍”与预制答疑；
     - 模型调用记进现有的模型调用记账，只记元数据，不记问答文字；
     - 计量仍只算这节课的 `lesson_whiteboard`，不另扣 `ai_active_time`，以免学生因为提问被扣时长。这一条见第五节第 3 条。
4. **数据**：
   - 提问与回答**不作证据**，不改掌握与判断，不进画像（第一阶段第五节第 4 条）；
   - 问答文字只在这节课的会话内存里，不落库。要做抽检复核，就得新建表、定保存期，属迁移必停，另起；
   - “哪一步被问得最多”的聚合统计只计数（讲评课内容 ID、步、问法），不带学生 ID，设最小人数门槛（规则 13）。要新表或新视图，另起。
5. **前端**：
   - 样张页之外，讲评课页面把第一阶段的 `onAsk` 接到 BFF 的 `teach`：带上提问对象与 `lesson_ref`，回答显示在字幕区下方；
   - 回答文字只来自 `TeachResult.segments` 或固定兜底，组件不拼接；
   - 等待时用过程状态组件；失败或冷却沿用现有的 `retryableFailure`。
6. **验收**：用讲评课教研验收清单（`evals/lesson-acceptance`）。C 节“提交前不露答案”、D 节“没有关于学生的判断”是必过项，另补一条“答疑不露答案”。人设回归 `make eval-persona` 跑过并附前后对比（规则 7）。
7. **拆成的 PR**，每个都 `[NEEDS-HUMAN]`：

   | 顺序 | 内容 | 必停原因 |
   |---|---|---|
   | ① | 契约：`TeachRequest.question`、`answer_submitted`（插件契约追加，按契约版本规则） | 契约 |
   | ② | DSL 与台词稿 0.3.0：`answers`、迁移、校验、渲染 | 人设话术格式；内容仍是合成占位 |
   | ③ | 阿鸦 `teach`：按 `question` 取预制答疑，核对锚点，守门；BFF `teach` 路由（计量按节、幂等键） | 适配器方法行为、计量 |
   | ④ | 讲评课页面接线与兜底文案占位 | 面向学生的新话术 |
   | ⑤ | 2b 模型回答：路由、上下文组装、五道输出守门、每节次数上限 | 模型调用、人设 Prompt、计量 |

## 三、不做
- 自由文字提问、语音插话与实时语音（`voice_realtime` 另计）。
- 直播态的打断续播：回答期间讲解暂停，答完学生自己点继续。
- 回答里生成新的白板板书：模型不能写 DSL；需要画图的问题，只能由教研在预制答疑里写。
- 问答文字落库、抽检复核台、聚合统计表：迁移必停，另起。
- 道法、语文的讲评课。

## 四、验收
- 2a：
  - 合成讲评课上，指着元素问三种问题之一，得到台词稿里对应的那句预制答疑；没有预制答疑时给兜底与“再讲一遍”；
  - 服务端拒收客户端传来的讲解内容，拒收未来的锚点；
  - 计量只按节扣一次，带幂等键，重放不重扣；
  - 提问不产生证据。
- 2b：
  - 合成供应商下，五道守门各有反例被挡，被挡后显示兜底，不显示模型原文；
  - 带学生作答的提问只在键盘作答时把原文送进 T1，拍照作答不送；
  - 每节次数上限生效；
  - 路由测试断言 L2 请求不出境；
  - 人设回归通过并附前后对比。
- 两步都用讲评课验收清单试跑一遍，记录放教研台账。

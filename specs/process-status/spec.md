# 做题提交与等待时的“动作级过程状态”组件 · 规格草稿

- 状态：**草稿，待人确认第五节**（2026-11-25）。
- 来源：2026-11-25 对 HKUDS/DeepTutor 的界面分析（用户“按建议起草过程状态组件的规格”）。借鉴它“一行状态 + 用时”的过程展示
  （`web/components/activity/`：状态点、动作标签、用时，展开才看明细），但**只取动作级状态**：不展示模型思考、工具名与参数、用量，
  也不展开明细（学生是未成年人；规则 3 判分只来自验证器，过程文字不得暗示判分结果）。
- 必停项：**状态文案是面向学生的新话术（人设，必停）**，本任务只放 `{{TODO_COPY:status.*}}` 占位，人写人审；不改契约、BFF、学习服务、
  计量、判分与掌握计算。

## 一、现状（2026-11-25 核对）
- 三处做题流程在等待时只有一句静态文字，没有阶段、没有用时：
  - 诊断（`apps/web/src/diagnosis/Diagnosis.tsx`）：提交时状态行“正在提交……”，提交成功后还要再读下一题（`api.current`），这一段没有任何提示；
    开始时“正在准备题目……”。
  - 再练、复测（`src/practice/PracticeItem.tsx`、`src/retest/RetestItem.tsx`）：取题时标题“正在准备题目”，提交时状态行“正在提交”。
- 等待可能变长：道法判分要走模型推理（T2），闸门满时排队（`gate_queue_ms`），掌握重算让作答延迟约翻倍（`specs/loadtest-mastery-path-plt22`）。
  学生看到的始终是同一句话，分不清是“还在处理”还是“卡住了”，容易连点或离开。
- 前端与 BFF 之间是一次请求一次响应（server action），**前端看不到服务端内部进行到哪一步**（判分、写证据、重算掌握都在一次调用里）。

## 二、默认做法
1. **组件** `src/shell/ProcessStatus.tsx`（新，客户端组件，三处共用）：
   - 一行：一个形状标记（进行中是空心圆环的缓慢转动，`prefers-reduced-motion` 时不转；不用颜色表达状态，与星图“用形状不用颜色”同一口径）+ 动作标签；
   - 等待超过 **3 秒** 时在标签后显示已等待的秒数；超过 **15 秒** 时多显示一句“还在处理”的占位提示（不给预计时间，不暗示快慢原因）；
   - `role="status"`、`aria-live="polite"`：只在**阶段变化**时播报，秒数放在 `aria-hidden` 的元素里，不每秒打扰读屏；
   - 只接受一个阶段编码（枚举）与开始时刻，组件里没有中文文案，文案从 copy 按编码取；不渲染任何服务端返回的文字。
2. **阶段只用前端真实经历的步骤**，不编造服务端内部阶段：
   | 编码 | 何时 | 三处 |
   |---|---|---|
   | `preparing` | 开始、取题、读下一题的请求进行中 | 诊断（开始 / 读题）、再练与复测（取题） |
   | `submitting` | 作答请求进行中 | 三处 |
   | `next` | 作答已成功、正在读下一题（只有诊断是自动连读） | 诊断 |
   结束（成功、失败、冷却）时组件消失，状态行恢复现有的结果或错误文案。**不加**“正在核对答案”“正在判分”一类阶段：前端看不到这一步，
   写出来就是猜，而且会让学生把等待和对错联系起来。
3. **接入**：三处把现在的 `busy` / `loading` 静态文字换成组件（同一位置），按钮禁用、冷却、宵禁、届别变化等现有逻辑一律不变。
4. **文案**：`STATUS_COPY = { preparing, submitting, next, waited(秒), still }`，全部 `{{TODO_COPY:status.*}}` 占位附中性提示
   （例：`'{{TODO_COPY:status.submitting}} 正在提交'`），并入壳文案的禁语、禁用推断词表扫描；登记进 `todo-by-owner.md` 产品一节。
5. **测试**：
   - 单测：阶段枚举与文案齐全；组件不含中文、不渲染服务端文字；秒数元素 `aria-hidden`；3 秒、15 秒阈值的纯函数；三处接入点（静态检查）。
   - 端到端：再练那一套已有慢作答桩（`SLOW-SYN` 延迟 3 秒，`specs/retry-after-cooldown`），断言提交中出现 `submitting` 状态、约 3 秒后出现秒数、
     结束后组件消失；axe 不退化；诊断与复测的原有用例照常通过。

## 三、不做
- 服务端推送进度（SSE / WebSocket 事件）：要改 BFF 与契约（必停），等讲解（teach）落地、确有多阶段长任务时再议。
- 取消正在进行的提交：server action 中途取消不能保证服务端没写入（作答已判分落库），现有“暂停”在提交完成后可用，不另加“停止”。
- 讲解、点点对话、家长端的等待态；模型思考、工具调用、用量的任何展示。

## 四、验收
- 三处做题流程的等待都有动作级状态，超过 3 秒能看到已等待秒数；不出现服务端内部阶段、思考内容或评价性文字；读屏只在阶段变化时播报。
- `make web-test`（含端到端）、`make check-fast` 通过；BFF、契约、迁移无改动。

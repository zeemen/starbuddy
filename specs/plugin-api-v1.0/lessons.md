## 与 spec 的偏差
1. **sie-#2 改为移除 `forecast`**：spec 写“`forecast` 的 audience 去掉 student、parent”。报告响应看不到请求的受众，schema 无法按受众约束，所以 v1.0 直接移除，预测只由洞察服务 `insight.predict` 提供（只给编排层）。
2. **N4 随 N3 改为必填**：spec 写“描述写明由平台生成”。证据要指回作答，作答就必须带 ID；学习服务早已这样传，实际影响只有异步英语示例。
3. **适配器路径不变**：v1.0 仍用 `/plugin/v0` 路径，以 `contract_version` 协商，迁移期同一路径可接两个版本，避免阿鸦与学习服务同时改路由。
4. **`student_ref` 加小写 UUID pattern**（N13“是否强制”）：`format: uuid` 在缺少 format 插件时不校验，与 N10 同理用 pattern 兜底；列为破坏性变更。
5. **N7 的前缀用例**：请求级规则放在四类请求（grade、diagnose、teach、generate_variation）上；道法只约束题目引用，不约束能力点（待人确认 #5）。
6. **作图语义的结构**：`semantic` 只约束为“操作名 + 最多 8 个参数”，具体操作表随输入通道 spec 定。
7. **幂等键限定为小写 UUIDv4**（安全审查必须改 2）：spec 没写。键会出现在日志与重放路径里，不能带可读信息；BFF 计量本来就只收 UUIDv4。列为破坏性变更。
8. **`paper_image_refs` 也标废弃**：与 `image_ref`、`transcript_ref` 同理（ADR 15）。
9. **候选版只能在测试里用**：共享库选 1.0.0 时还要设 `STARBUDDY_ALLOW_CANDIDATE_CONTRACT=1`，防止服务进程因全局环境变量误用候选版。
10. **没有 `mhchem` 示例**：学科枚举里还没有化学，示例放不进任何学科的请求；约束（可打印 ASCII、禁 `\text` 类命令）已有反例覆盖同样的 pattern（latex）。

## 审查意见的处理（按默认建议）
- **安全审查**：
  - 信号编码改为按下划线分段匹配禁用词根（声纹、语音身份、面部、眼动、虹膜、情绪、心情、情感），`facet_` 不误伤；补 `eye_gaze_ratio`、`facial_tension`、`speaker_match`、`session_mood` 等用例（必须改 1）；
  - 幂等键限定为 UUIDv4（必须改 2）；
  - 重放接口没有记录时封存该 key，晚到的原请求返回 `IDEMPOTENCY_KEY_SEALED`、不执行；必须带 `student_ref`、`usage_id`，不一致与不存在同样 404；写明禁止经网关对客户端开放（必须改 3、建议 2）；
  - 选择题选项、`latex`、`mhchem` 加字符与命令约束（建议 1）；候选版只在测试开关下可用（建议 3）；`paper_image_refs` 标废弃。
- **契约审查**：
  - 重放竞态同上（必须改 1）；
  - 补齐示例：画像上下文、前置路径、知识页面、同族题、作图语义、改名后的核验结果、两个新错误码（错误体示例也纳入校验）；修正画像条目反例的被拒原因，另加取值为自由文本、推断条目不带判断 ID 两个反例（必须改 3）；
  - 清单结论落地：teach 计量资源写进描述（v09-#2）、快照版本写在 @ 后（v09-#5）、待复核不推动门槛（ADR 11），删去 v0.9 残留的 forecast 与“待评审确认”（必须改 4）；
  - 计划请求加前缀规则，变异加“只删某一科子句”；清单 N4、sie-#2 注明偏离 spec；
  - 破坏性变更用例改为先把 v0.9 示例的幂等键换成 UUIDv4，并加对照实例，证明每条拒绝都来自那条收紧。
- **未改，记录**：阿鸦用 ajv 加载 v1.0 时跨文件引用解析不了（契约审查必须改 2），放进第二步的第一项；`insight-service` 放宽 `full_score` 没有升版本号（服务契约仍是 v0.9 草稿，签字时一并定版本）。

## 一、现状
- 端到端的“信任界面全开”那一套 BFF（`apps/web/scripts/e2e.sh` 第 113–136 行，`e2e/trust-on.spec.ts`）**没有接洞察服务**：
  “为什么”页只显示“暂时无法获取”、不出现任何判断；异议提交 503。全站陈述—判断爬取（`e2e/crawl-pages.ts`）访问“为什么”页时用的是
  不存在的判断 ID，所以“为什么”页上**判断的渲染从没被端到端核对过**——包括已推翻、已撤回的判断不出现、待验证的画虚线、家长与学生看到的裁剪不同。
- 假洞察服务（`apps/web/scripts/fake-insight.ts`）已实现 `insight.report` 与 `insight.explain`，但只给首份报告那一套 BFF、只认学生 R1。
- 考试预测与对账卡：BFF 没有可调的契约工具（`services/bff/src/trust/clients.ts` 第 7 行：契约 v0.9 的 `insight.predict` / `insight.reconcile` 只给编排层）。
  **桩补不了**，要先改契约（必停），本任务不做。

## 二、默认做法
1. **假洞察服务**：`fake-insight.ts` 另认周报合成学生（`db/seeds/dev/weekly-synthetic.sql` 的 c1 与五条判断 f1–f5：成立、假设、已推翻、已撤回、到期转待验证），
   `insight.explain` 按契约信封返回；已推翻、已撤回的返回与“不存在”相同的 404（与真实洞察服务一致）。另实现最小的 `insight.dispute`（按契约受理，返回合成的
   dispute_id 与 next_step）。其余工具仍 501。只用合成数据、只听 127.0.0.1、令牌每次随机生成（与现有桩同法）。
2. **接线**：信任界面全开的 BFF 加 `BFF_INSIGHT_URL` 指向一个新起的桩实例（与首份报告那一个分开，互不影响），前端的 `why` 开关照旧打开。
3. **端到端断言**（`e2e/trust-on.spec.ts` 改写“为什么”一条、新增几条）：
   - 学生与家长打开 f1（成立）、f2（假设）的“为什么”页：结论带 `data-claim-id`，状态与受众裁剪符合 `explainForAudience`；异议按钮出现，提交后走到异议状态页；
   - f5（待验证）画虚线；f3（已推翻）、f4（已撤回）与不存在的 ID 同一个结果，文字不出现在页面上；
   - 保留一条“读取通道不可用”的用例：桩对指定的合成 ID 回 503，页面显示“暂时无法获取”、不显示异议按钮（原来那条断言的意图）。
4. **爬取**：`crawl-pages.ts` 的“为什么”页另用 f1–f5 的真实 ID 走一遍，进 `claim-binding.ts` 的三条规则（ID 都在桩给出的判断里且状态允许、
   已推翻与已撤回的文字不出现、陈述只出现在带同一 ID 的元素里）。
5. **变异**（`apps/web/scripts/claims-mutation.sh`）：至少三条——“为什么”页渲染已推翻的判断、家长看到只给学生的字段（裁剪去掉）、待验证不画虚线；断言端到端发现。

## 现状（调研结论）
- **单科端到端各自存在，没有跨科联调**：三份 e2e 测试各起一个适配器，学生、种子各自独立；没有“同一学生在三科都有事件、节点查询能汇总”的测试，也没有多学生批量回放。
- **复测链路不存在**：`retest_task` 与复测调度在 KGE-04 第二步；目前只能写入“诊断、批改”两类事件。
- **“20 名内部测试学生”的数据来源未定**：规则 8 禁止真实学生数据进代码、日志、夹具；真实内测需要监护人同意（J 流）与境内试点环境（未就绪）。
- **Gate 0 证据格式未定**：开发计划只写“事件与节点查询记录；星图截图”。

## 设计要点
### 1. 合成联调回放（CI 可跑）
- 20 名合成学生（`tools/e2e-cohort/` 生成器，固定种子）：覆盖年级（七、八、九）、选科组合、作答模式（全对、系统性缺口、刷同题、提示依赖、中断）；
- 一次性 Postgres + 学习服务 + 三科适配器同时启动；按脚本依次：诊断会话 → 批改（客观题、数学步骤、道法采分点、语文 Rubric）→ 复测（KGE-04 第二步前用接口桩，见 #2）；
- 全部经契约接口（规则 1）；适配器不直连库。

### 2. 断言（“同一学生模型”的可测定义）
- 每名学生的证据事件只落在 platform 个人层同一 `student_id` 下，三科事件并存、互不覆盖；各科私有表不存在第二份学生事实（规则 2，按 schema 扫描）；
- 节点查询：按学生查询得到三科节点的证据与掌握（KGE-04 第二步前查证据聚合，之后查 `mastery_estimate`）；
- 判分溯源：每条 grade 结果带 `evidence_ids / confidence / source_version / model_version / human_review_required`（规则 3）；
- 幂等：整轮回放重跑一次，事件与计量零新增；
- 隔离：任一学生的查询不返回其他学生数据；家长只见已绑定孩子（沿用 20_rls_household 口径）。

### 3. Gate 0 证据包（生成器）
- `make gate0-evidence`：跑完联调后导出每名合成学生的“事件计数 × 科目 × 事件类型”表、节点查询结果摘要（节点 ID、证据数、状态）、星图截图（Playwright 对壳内星图页，合成家庭）、运行元数据（提交号、契约版本、适配器版本）；
- 输出只含合成数据与 ID，确定性（截图除外，截图附像素哈希）；标注“合成联调，不是内测结论”。

### 4. 真实内测（本任务只写执行手册）
- 真实 20 名内部测试学生的联调在境内试点环境、监护人同意与用途授权到位后由人执行；本仓只提供执行手册与同一套断言脚本（只读连接），结果只入汇总（#1）。

# 讲解 DSL v0.2：“说 / 画 / 指”配对、台词与板书分开存、迁移阶梯第一级真实迁移 · 规格草稿

- 状态：**草稿，待人确认第五节**（2026-11-25）。
- 来源：OpenMAIC 借鉴分析 v1.1 第八节第 1 条（用户 2026-11-25“已合并，按建议起草讲解 DSL v0.2 的规格”）。
  借鉴 OpenMAIC PBL 讲解白板的叙述协议（`lib/pbl/v3/narration.ts` 把一段讲解拆成“说 / 画 / 指”交错的步骤；`skills/pbl/pbl-explanation/SKILL.md`：
  不连着画两块而不说话、每段话一两句短句、说到哪一处就先指哪一处、整块用聚光、单行用激光笔）。只借规则与结构，不引入代码或依赖。
- 依据：ADR 07（渲染器只接收已审核 DSL、学生作答只在内存渲染）；`specs/stage-whiteboard-step1`（DSL v0.1）；`specs/stage-dsl-versioning`（版本规则与迁移阶梯）；
  CLAUDE.md 规则 3（讲解与人设文本不得覆盖判分）、规则 7（人设话术必停）。
- 必停项：**台词是人设话术**。本任务只定台词的**格式与确定性检查**，样例台词一律是明显的合成占位；真实台词的撰写与审核走人设流程、跑人设回归，另起。
  不改契约（`TeachSegment` 怎么携带台词稿另起，属契约变更）、不改计量、判分与掌握计算。

## 一、现状
- DSL v0.1 只有板书：`write_text`、`write_formula`、`draw_line`、`draw_shape`、`highlight`、`clear` 与切换讲解权的 `speaker`。**没有“说什么”**，也没有“指向”。
- 讲评课（开发计划 2 月）要的是老师边说边写：说一句、写一步、指着某处说。没有这层结构，讲解只能靠另一份不对齐的文字稿，播放、配音、审核都对不上。

## 二、默认做法
1. **台词与板书分开存**：
   - DSL v0.2 只在每一步上**引用**台词编号：`say: "l3"`（或不说）。台词正文不进 DSL。
   - 台词单独成稿：`StageScript = { dsl_version, lines: [{ id, role, text }] }`（新类型，`packages/stage/src/script.ts`）。人设审核、配音预合成都按这份稿走；
     板书可以由教研审，台词由人设审，互不改写（规则 3、7）。
   - 两份合起来才能播放：新的 `validateStagePair(dsl, script)` 核对“引用的台词都在、没有多余台词、每句台词的角色等于说这句时持有讲解权的角色”。
2. **“说 / 画”配对**（借鉴“不连着画两块而不说话”）：
   - DSL 顶层新增 `narrated: boolean`。
   - `narrated: true` 时：凡是有书写或作图动作（`write_text`、`write_formula`、`draw_line`、`draw_shape`）的步骤必须带 `say`；
     不允许连续两步都只有板书动作而没有 `say`（这条已被上一条覆盖，校验器另给明确错误码 `unpaired_board`）。
   - `narrated: false`：无声板书，与 v0.1 相同，任何步骤都不得带 `say` 或 `point`。旧内容迁移过来就是这一种。
3. **“指”**：新动作 `point`，只在 `narrated: true` 时可用，指向的东西在这一步的 `say` 说完之前保持：
   - `{ type: 'point', id, target, mode }`，`mode` 为 `spotlight`（一整块，渲染为目标外接框的粗描边）或 `laser`（单个元素，渲染为目标旁的小三角标记）；
     **只用形状与线宽表达，不靠颜色**（与星图、过程状态同一口径）；
   - `target` 是白板上现存元素的 id，或文档顶层声明的**槽位** id：`slots: [{ id, kind }]`，`kind` 为 `item_figure`（题图）或 `student_answer`（学生作答切片）。
     槽位只声明一块区域（坐标与尺寸），**内容运行时在内存里填充，DSL 与台词稿都不含学生数据**（ADR 07 决定 4）；本期渲染只画空槽位框，
     真实内容的接入随讲评课；
   - 一步最多一个 `point`；有 `point` 的步骤必须有 `say`（先指后说）。
4. **台词的确定性检查**（不是人设审核，只挡格式问题）：
   - 每句 1–60 个码点、最多两个句末标点（。！？），借鉴“一两句短句”；
   - 与板书文字同一套安全检查（不可见字符、HTML、链接与脚本，`src/text.ts`）；
   - 角色只能是本节出场的角色（`teacher` / `buddy`）；台词编号格式同元素 id；一份稿最多 100 句。
5. **版本与迁移**（按 `specs/stage-dsl-versioning` 的五步）：
   - `DSL_VERSION` 升到 `0.2.0`；新增 `schema/stage-dsl-0.2.0.schema.json` 与台词稿 schema `schema/stage-script-0.2.0.schema.json`；锁文件追加 0.2.0 一行；
     `stage-dsl-0.1.0.schema.json` 不改。
   - 迁移阶梯第一级真实迁移 `0.1.0 → 0.2.0`：加 `narrated: false`，其余不动；文字逐字保留（执行器核对）。旧的 v0.1 文档都能无损升级。
6. **播放与渲染**：
   - 播放状态机不变（仍按步前进、后退、跳转）；
   - 白板组件新增：当前步的 `point` 标记；槽位框；当前步台词以字幕显示在白板下方（台词文字从台词稿取，组件不拼接任何文字）；
     字幕区 `aria-live="polite"`，每步播报一次；
   - 样张页 `/dev/stage` 换成一份 v0.2 合成样例（`narrated: true`，含 `point` 与一个空槽位）与合成台词稿（明显占位，如“（合成台词）先看等号两边。”）。
7. **测试**：
   - 校验器：配对规则、`point` 的目标与模式、槽位声明与引用、`narrated: false` 时不得带 `say` / `point`、上限与安全检查；
   - `validateStagePair`：缺台词、多余台词、角色与讲解权不符、台词超长或超过两句、台词含链接；
   - 迁移：v0.1 合成样例经 `migrateStageDsl` 升到 0.2.0，文字逐字保留、`narrated: false`、通过校验；
   - 渲染：SSR 快照（point 两种模式、槽位框、字幕）、无外链、只渲染已校验的 DSL 与台词稿；axe；样张页端到端；
   - 变异：配对规则放过、point 指向不存在的元素、槽位声明缺失、台词角色不核对、字幕拼接台词以外的文字等；
   - `make stage-test`、`make stage-mutation`、`make check-fast`、`make web-test` 通过；零新依赖。

## 三、不做
- 真实台词与人设审核流程（人设必停，另起）；TTS 与配音预合成；
- `TeachSegment` 携带台词稿（契约变更，必停，另起）；讲评课的内容生成、发布闸门与审核台；
- 槽位里真实题图与学生作答的接入（随讲评课）；直播态（学生插话转模型，借鉴第 4 点，另起）；
- 学生指着元素提问（借鉴第 4 点）。

## 四、验收
- v0.2 合成样例在样张页逐步播放：每步写、说、指对齐，字幕与讲解权一致；v0.1 文档经迁移无损升级；非法 DSL 或台词稿被拒；
- 渲染无外链、不落库、DSL 与台词稿都不含学生数据；`make stage-test`、`make stage-mutation`、`make check-fast`、`make web-test` 通过；零新依赖。

2. **旧内容怎么迁移**：加 `narrated: false`，保持无声板书、无损升级（默认）；还是 v0.1 内容一律进重审、补台词后再发布？
3. **“指”能指向什么**：白板上的元素，加上文档声明的题图、学生作答两种槽位；槽位内容运行时在内存填充，DSL 不含学生数据（默认）；还是本期只做白板元素？
4. **台词长度**：每句 ≤ 60 个码点、最多两句（默认，借鉴“一两句短句”）；具体数字请人设与教研定。

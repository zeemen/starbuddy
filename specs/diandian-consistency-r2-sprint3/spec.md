## 设计要点
### 1. 后处理 v0（`evals/persona/diandian/postproc/`，确定性、带版本 `diandian-post@0.1.0`）
- 禁语命中（经 3-F `guard`，只看点点适用的 A–E 类）→ 拦截；拦截后的替代回复**只能取规格里已有的固定句**，规格里没有现成句子的，用占位符 `{{SAFE_REPLY}}` 并在报告里标“替代句待人设负责人提供”（写新话术是必停项）。
- 首轮对话缺 AI 身份披露 → 注入点点规格（继承 V1.0 4.1）规定的披露句（逐字取自规格；若规格只给要求不给原句，同样用占位）。
- 情感信号（按点点规格 4.9 的信号清单做规则近似）→ 确定性转介，转介句同样只取规格原文或占位。
- 统计时**同时报“只 Prompt”与“Prompt + 后处理”两组**，后处理不能掩盖模型差异。

### 2. 修订流程工具
- 修订记录格式 `evals/persona/diandian/revisions/<n>.yaml`：假设、改动对象（Prompt 或后处理）、版本前后、开发集前后对比（列对齐 persona-evaluator 七项）、是否采纳、签字人（留空）。
- `compare.py` 增加 `--revision <n>`：在开发集上按修订前后两个版本各跑 N 次，输出前后对比；任何一项下降或禁语触发率 > 0 → 标“不采纳”。默认最多三次修订。
- 同一版 Prompt 用于所有候选模型；按模型分叉只作为替代方案 R-1。

### 3. 二轮报告
- 在首轮报告格式上增加：修订记录、两组数字（只 Prompt / Prompt + 后处理）、留出集结果（留出集由教研负责人在封存环境跑，规则 14，本仓只收汇总）、验收判定：红线全过 且 每家核心通过率 ≥ 下限 且 最大差值 ≤ 5 个百分点 → “达到验收口径”，否则 → “需选替代方案”；结论由人定。
- 报告只含汇总、用例 ID 与失败样例的合成原文（L0），不含任何真实学生数据。

### 4. ADR 08 决策记录草稿（`specs/diandian-consistency-r2-sprint3/adr-08-decision-record.md`）
- 按旧稿第 5 节格式（结论三选一、依据、范围、替代方案 R-1…R-4、签字栏），但**英语部分标“搁置，待英语方案重定”**；本冲刺只写点点跨模型一致性这一半的决策栏。不改 `docs/adr/08-*.md` 正文与状态。

### 5. 执行手册
- 真实首轮 + 二轮的前提清单与步骤（候选签字 → 供应商登记 → Prompt v0 签字 → 首轮 → 至多三次修订（每次签字）→ 二轮 → 决策记录签字），执行人本地命令、仓库外输出目录、报告提交位置。

## 范围
### 做
后处理 v0（复用 3-F guard）与单测；修订记录格式与 `compare.py --revision`；二轮报告生成（两组数字、修订记录、验收判定）；假供应商下的端到端（三家假候选：一家总合规、一家某类稳定失败、一家随机失败；一次“采纳”的修订与一次“不采纳”的修订）；ADR 08 决策记录草稿；执行手册；变异；lessons。
### 不做
写点点人设层 Prompt v0 或任何修订的实际内容（人设必停项）；写新的安全回复 / 披露 / 转介话术（必停，用占位）；任何真实模型调用、新增供应商；改 `docs/adr/`、`docs/personas/`、`evals/**/gold/`、契约；英语链路评测（英语搁置）。

## 涉及的必停项
- **人设 Prompt**：不写；修订内容由人提供并签字。**禁语表、转介话术**：后处理只实现既有规则，替代句只取规格原文或占位；新增句子另走必停。
- **新增模型供应商 / 出境**：本任务不涉及；真实运行前由人完成 ADR 04 签字与 `vendors.md` 登记。**契约、迁移、计量**：否。

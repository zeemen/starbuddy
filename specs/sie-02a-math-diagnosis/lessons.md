# SIE-02a 数学自适应诊断 · lessons

## 实现要点（服务端与前端；迁移 0027 与 DB 测试已由主会话合入，本任务未改）
### 学习服务（services/learning/learning/diagnosis/）
- `engine.py`：选题规则 `aya-diag-trace@0.1.0`（纯函数、确定性、不用模型）与显式状态机（`State`、`Event`、`TRANSITIONS`）。
  每次都按库里的步骤历史复算（`trace`），历史与规则不一致即 409 `SESSION_INCONSISTENT`，所以暂停续做、重放、换进程都得到同一序列。
  - 起点：建档年级对应的目标节点；上层优先（往下最长强前置链更长的先测），同层按节点 ID；每节点 1 题，答错且有第 2 题时出 1 题 `confirm`，以确认题为准；
  - 答对 → 全部强前置（传递闭包）记跳过；答错 → 直接强前置入待测；无题 → `no_item`，不猜、不往下追；
  - `needs_review` / `not_applicable` 记“不明”：不跳过、不追溯（`partial` 算错）；
  - 断点 = 未通过且直接强前置都通过（含跳过）或无题的节点；只给 KGE-04 / SIE-02b 的候选（`DiagnosisService.break_points`，没有对外接口）。
  - 停止：目标都有结论、或题数 / 用时到上限。自适应阶段给过程观察预留 4 题与 4 × 180 秒；出每道新题前按“这道题最多用多久”预留时间
    （自适应 90 秒、过程题 180 秒），保证累计用时不越过 35 分钟。
  - 过程观察：从断点 → 断点已通过的前置 → 其余未通过节点（都没有时取通过的目标）里各取一道本次没出过的题，最多 3 道 `process` + 1 道 `explain`；
    题不够时最后一道改为 `explain`。
- `source.py`：`KnowledgeServiceSource` 经知识服务 `node.path`（direction = up，只走强前置）与 `item.search` 取图与题；
  `FixtureSource` 是测试环境的合成夹具（只取强边）。两者对同一张图给出相同的前置、闭包、层高与题目顺序（单测对照，假知识服务按契约形状应答）。
- `presenter.py`：题面提供者接口 + 测试环境的合成题面（`SyntheticPresenter`）。出口白名单只有题型、题面、选项键与文字；夹具加载时拒绝任何多余字段（答案、解析）。
  非 test 环境：`Settings.from_env` 与构造函数各拦一道。
- `service.py` / `store.py` / `api.py`：`/internal/v1/diagnosis/sessions[...]`（开始 / 续做、当前题、探针、作答、暂停、放弃），接口文档
  `services/learning/openapi/diagnosis-internal.v0.yaml`。只写 0027 两张表、既有的证据 / 作答 / 判分（经 grade 写入流程）与复核队列。
  - 判分只来自阿鸦验证器：作答走 v1 写入路径 `IngestService.ingest("grade", {request, ingest}, "1.0.0")`（channel = keypad，
    证据等级按 attributes 默认推导为 A），请求键由（会话、序号、n）派生、UUIDv4 形态；同一内容重放不再判；
    判分成功、步骤没推进（进程在两段之间中断）时，重放作答或取当前题都按已记录的判分推进，不判第二次；上一次确定失败才换 n（最多 8 次）。
  - 作答幂等键记到 `diagnosis_step.answer_key`：同键重放回原结果；键不同、内容相同也回原结果；键不同且内容不同 409 `ANSWER_CONFLICT`。
  - 用时封顶：记入步骤与作答表的用时 = min(上报值, 暂停前已记 + 现在 − max(出题时间, `resumed_at`))；判分前与作答键一起定下（重试时指纹不变）；
    续做（开始请求遇到未结束的会话）把 `resumed_at` 记为现在。
  - 作答发生时间取探针写入时间（没有探针取出题时间）：重试时请求指纹不变，2-L 关联作答的时间窗也成立。
  - 过程题、讲解题的书写原文记为一条 `response_text` 证据（学生原文，不评分，`evidence_kind` 为空，准入固定 `pending_review`），
    证据 ID 在步骤记为已作答之前写到 `diagnosis_step.work_evidence_id`；步骤作答后以 `process_observation` 进统一复核队列。
  - 合成题面另核库名 `starbuddy_(dev|test)*`（与种子一致），并要求开候选契约（`STARBUDDY_ALLOW_CANDIDATE_CONTRACT=1`）；启动时核对。
  - 取当前题的学生 ID 走请求头 `x-student-ref`，不进 URL（放在 query 里 400）。
  - 会话记 `usage_id`；计量在 BFF（ADR 06）。

### BFF（services/bff/src/diagnosis/）
- 学生端接口见 `openapi/diagnosis.v0.yaml`；只认学生本人（家长、其他学生、不存在同一个 403，未登录 401，与 2-L 事件接口一致），会话归属再经 0027 的 RLS 核一次。
- 计量沿用 0009 / 0015 的函数：开始以学生身份预留 `diagnosis_full`（method = diagnose），学习服务确定拒绝 → 释放，结果未知 → 503 且不释放
  （同一键重试找回同一笔预留与同一个会话）；已有未结束的会话时续做，不预留；**第一道题判分成功即结算**（之后每次作答再结算一次，幂等）；
  放弃时只有还没答过题才释放，答过题按已结算处理；续做当场结束也结算（S10）。
- 宵禁：续做、取题（会话进行中时）、探针、作答先以学生本人读 `platform.student_time_guard`，按 `meter_in_curfew` 同一口径判断；
  宵禁中请学习服务把会话置为暂停，回 402 `reason = curfew`。时钟用 `deps.now`（与计量时钟同一时间轴；端到端用 `STARBUDDY_DEV_METER_CLOCK=daytime`）。
- 探针：BFF 以学生身份调 `insight.record_confidence_probe`，幂等键由（会话、序号）派生（uuidv5）；同一步已有探针（23505）时按派生键请学习服务
  找回那一条（`probe_key`），并发提交只留一行；作答落库后调 `insight.link_probe_attempt`（尽力而为）。
- 前端视图按白名单裁剪：没有题号、节点、答案、选题理由、对错、额度占用。

## 与 spec 的偏差
1. **题面**：合成题面的题号借用阿鸦内容包里已登记的 28 道题（二次函数与压轴专项，作验证器判分的槽位），题面是占位文字，节点与边是合成的
   （`fixtures/quad-synthetic.json`，14 个节点、15 条强边、5 条弱边）。夹具不带答案；合成学生的答案取自阿鸦内容包（验证器自己的数据）。
   所以“夹具含答案”没有照做：答案只在验证器一侧，这样题面提供者无论如何都带不出答案。
2. **过程题书写原文的存放**：插件契约的作答只能是 text / choice 之一，最终答案要单独给验证器判，书写原文就只能由学习服务自己记成一条学生原文证据。
   0027 的审核台详情函数只列判分的证据 ID，看不到这条原文（按判分请求键能找到）。见待人确认 #9。
3. **学习服务的诊断内部接口**没有进 `packages/contracts`（本任务不改契约），先放 `services/learning/openapi/diagnosis-internal.v0.yaml`。见待人确认 #10。
4. **暂停、放弃的幂等锚点是（会话、序号）**，请求里的幂等键只做格式核对；作答另按请求的幂等键记到步骤（S5）；开始用请求的键
   （会话与计量预留都按它）；探针的写入键由（会话、序号）派生（S3），请求里的键只做格式核对，同一步只认第一次。
8. **诊断作答的 purpose**：契约 `IngestContext.purpose` 只有 practice / retest / transfer_check，没有“诊断”；按缺省 practice 写，
   证据的 evidence_kind 因此是 independent。要单独标诊断，需契约加枚举值（见待人确认 #13）。
5. **用时**：客户端上报（每题 0–7200 秒，暂停时交当前题已用秒数、续做接着算），服务端按墙钟封顶（审查处理 S1）。
   测试里用“把出题时间往前挪”模拟真实用时（只在测试库，绕过 0027 的续做时间只增守卫）。
6. **端到端的计量时钟**：`apps/web/scripts/e2e.sh` 在一次性测试库里把 `platform.meter_now()` 挪到当天白天（做法同 BFF 测试夹具），否则夜里跑会撞宵禁拿不到预留。
7. **目标节点**：试点只配了九年级（夹具）；教材进度还没有参与选目标（建档的进度字段接入另起）。知识服务没有“按主题 / 进度列节点”的工具，
   知识服务来源的目标先由配置给出（`LEARNING_DIAGNOSIS_TARGETS`）。

## 经验
- 选题每次按历史复算，比把“待测队列”存库简单得多，也天然支持暂停续做与重放；代价是地图或年级在会话中途变了就只能判“不一致”。
- 判分请求的指纹里有作答时间：时间必须是确定的（探针写入时间或出题时间），否则同一作答重试会被当成“同键不同内容”。

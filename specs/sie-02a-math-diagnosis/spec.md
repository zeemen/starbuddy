## 现状（调研结论）
- **没有编排层**：ADR 03 说编排要从零建；学习服务的 diagnose 只支持“一次提交一批作答”的同步调用，没有“出一题、收一题、再选下一题”的会话。
- **契约里没有取题面的方法**：插件 API 与知识服务都不返回题干（KGE：题干不进 kge 库，留在各科内容里），前端无法经平台拿到要展示的题目。这是自适应诊断的硬缺口（待人确认 #2）。
- **题库与地图范围很小**：数学地图目前只有二次函数一个主题（24 个节点），已导入主题 35 题，且多数节点题目少于 3 道（KGE-02 覆盖矩阵：24 个节点里 15 个有主考点题）。“数学基线”在试点期只能覆盖这个主题。
- **过程观察没有落脚点**：阿鸦 diagnose 只支持 intake / gap_test；过程题的判分必须来自验证器或 Rubric（规则 3），数学过程 Rubric 还没有；“讲给老师听”需要语音链（英语 / ASR 选型在 3-I，未定）。
- 掌握状态、证据权重、五道门槛都在 KGE-04（冲刺 4）；判断与首份画像在 SIE-02b。本任务之前没有任何对学生可见的诊断结论。

## 设计要点
### 1. 诊断会话（学习服务内，显式状态机，ADR 03）
- 状态：`created → probing → awaiting_answer → grading → selecting → (process_tasks) → finished | paused | abandoned`；每一步幂等（请求带幂等键），可暂停、跨天续做（“可分次”），总时长按实际作答时间累计，上限 35 分钟（可配置）。
- 会话与每一步的记录存 platform.*（学习服务是过渡期唯一写个人层的服务）：新表 `platform.diagnosis_session`、`platform.diagnosis_step`（迁移 0027 草稿，由人执行），只存选题决策与引用（题目 ID、节点、作答 ID、探针 ID、选题理由码、算法版本），不存题干、不存任何推断性描述。
- 作答照旧经学习服务 ingest 写证据（客观记录），判分只来自阿鸦验证器（规则 3）；探针照 2-L 写 `insight.confidence_probe` 并在作答后 `link_probe_attempt`。
- 计量：诊断属消耗类请求，按规则 4 带 usage_id 与幂等键，开始预留、成功结算、失败回滚（沿用现有计量函数，不改规则）；是否对首周基线免计由人定（待人确认 #6）。

### 2. 选题：沿前置追溯断点（确定性规则，算法版本入库）
- 起点：按建档的年级与教材进度，取当前学段应掌握的目标节点（试点：二次函数主题的 kp 节点）。
- 每个节点出 1 题（同节点有两题时，第一题错后可再出一道确认）；
  - 答对 → 该节点记“诊断通过”，**它的强前置节点都跳过**（高置信节点跳过）；
  - 答错 → 经知识服务 `node.path` 取强前置，向下追溯，直到找到答对的节点（断点）或没有更下层前置；
  - 节点没有可用题目 → 记“无题可测”，不猜。
- 顺序：先测前置图的“上层”节点（覆盖面大），同层按节点 ID 排序，保证可复算；不使用任何模型。
- 停止：所有目标节点都得到“通过 / 断点 / 无题可测”之一，或用时到上限，或题数到上限（默认 20 题，待人确认 #4）。
- 本任务**不算掌握度**：诊断只产出证据与“断点候选”列表（供 KGE-04 掌握计算与 SIE-02b 生成判断）；不对学生、家长展示任何诊断结论（规则 11）。

### 3. 过程观察任务
- 诊断结束后从断点附近节点选 2–3 道题，要求“写出全过程”（键盘输入或拍照走现有输入通道，拍照 C 级不进学生模型，ADR 15）。
- 判分：只判最终答案（阿鸦验证器）；过程部分**不自动评分**（没有数学过程 Rubric），整段作答进统一复核队列，由教研看（复核原因复用已有的低置信 / 抽检，或新增“过程观察”原因——新增原因要改迁移 0023 的枚举，见待人确认 #5）。
- “讲给老师听”：语音链未定，本任务改为文字“用自己的话讲给老师听”（一道），同样进复核队列；语音版随 3-I 结论另起。

### 4. 取题面（契约缺口）
- 默认方案（待人确认 #2）：插件 API 新增只读方法 `present_item`（入参：题目引用、渲染格式；出参：题干、选项、公式与图的引用，不含答案与解析），由适配器从自己的内容库返回；这是契约变更，另起 [NEEDS-HUMAN] PR 修改 `packages/contracts`，本任务在契约签字后再接入。
- 契约签字前：本任务只在测试环境用合成题面（夹具）跑通全流程，不接真实题库。

### 5. BFF 与前端
- BFF 学生端接口：开始 / 续做诊断、取当前题、提交探针与作答、暂停；只认学生本人（家长不能代答），与建档、事件接口的鉴权一致。
- apps/web：做题页随冲刺 4 统一外壳；本任务做诊断组件与**开发环境演示页**（生产构建里不存在，沿用 2-L 的构建时排除做法），含计时、暂停、探针（复用 `ConfidenceProbe`）。文案过禁语检查；诊断中不显示对错之外的任何评价，结束页只说“完成了，老师会看你的过程”，不给结论。

### 6. 35 分钟验收怎么测
- 自动化：合成学生（按预设掌握图作答，每题用时取合成分布）跑完整会话，断言在题数上限内结束、找到的断点与预设一致、累计用时 ≤ 35 分钟、暂停续做后结果不变。
- 人工：一名测试学生（合成账号，由项目成员扮演，不用真实学生数据）在演示页走完一次，记录用时；属于人的验收（待人确认 #7）。

## 验收标准（可测试）
- [ ] 合成学生在二次函数主题上跑完诊断：断点与预设掌握图一致；答对的节点其强前置全部跳过；无题节点标“无题可测”；题数与用时在上限内；同样输入两次运行选题序列逐字节相同。
- [ ] 会话可暂停、跨天续做，重放任一步不重复写证据、不重复扣额度；计量预留 / 结算 / 回滚与幂等测试通过。
- [ ] 每题前有探针，作答后关联；判分只来自验证器；过程观察作答进复核队列；诊断不产生任何对学生、家长可见的结论。
- [ ] 迁移 0027：只有学习服务能写会话，学生只能读自己的会话状态（不含选题理由），家长读不到；DB 测试、变异、快照、攻击面检查通过。
- [ ] 演示页不在生产构建里；组件 axe 无违规、文案过禁语检查；严格 `make check`、安全审查、契约审查通过。
- [ ] 一名测试学生 35 分钟内完成数学基线（人工验收，契约签字、真实题库接入后执行；不在本任务的自动化通过条件里）。

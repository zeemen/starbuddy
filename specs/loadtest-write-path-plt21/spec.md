## 背景
PLT-20 的再练 / 复测作答在本机栈只走到 BFF 票据校验（派生票据 → 422，计次之前），因为本栈不起知识服务、没有合成地图、没有能判合成题的适配器。2 倍峰值下最重的写路径（取题 → 作答 → 判分 → 证据落库 → 掌握更新 → 计次）因此未被测到。

## 范围（`tools/loadtest`，必要时 `tools/loadtest/fixtures/`）
1. **合成地图与题**：在一次性库里经现有导入器或种子脚本装入一份合成地图版本（已发布）与少量合成题（准入 A 级），复用仓库现有合成夹具，不新建个人层数据。
2. **假知识服务**：进程内或本地端口的假实现，只提供学习服务取题所需的读工具（`item.similar` / `item.search` 等，以 learning 的实际调用为准），响应形状以 `packages/contracts` 知识服务 OpenAPI 校验；或经评估直接起真知识服务（只读，读一次性库）——两者择一，优先真服务（少一份替身口径）。
3. **合成判题**：让 grade 对合成题给出确定性结果，优先复用现有适配器的合成题判分路径（如阿鸦 SymPy 合成题）；不新增判分规则，不改适配器契约。
4. **到期条目**：种入合成学生的再练队列与到期复测条目，使 next 返回 ready 与真票据。
5. **驱动器**：再练 / 复测作答走真票据；“预期结果”中派生票据一项在写路径可用时自动停用（真路径占比应为 100%）；报告新增写路径各环节耗时与证据 / 计次一致性核对（作答次数 = 计次增量 = 证据行增量，零泄漏）。
6. **测试**：种子与假服务的单测；写路径一致性核对纯函数；本机 small 档实跑一次，样例更新。

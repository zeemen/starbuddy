# WeKnora 技术验证计划 · v0.1

- 日期：2026-11-03，Claude 起草，待用户确认。
- 目的：ADR 16 第 4 节写明“WeKnora 本体的能力尚未核实，第 3.2、3.3、3.5 节都依赖这些能力，plan 阶段须先做技术验证”。本计划逐项核实这些能力，给出每项“通过 / 有条件通过 / 不通过”，不通过的给出退路。验证结论用来定三件事：
  - 知识服务契约草案（`item.search`、`item.similar` 改由 WeKnora 支撑，新增标准知识检索工具；必停）；
  - WeKnora 的部署规格（纳入 staging 集群规格重估，LT-03 待人确认第 20 条）；
  - 中台需求单（`zhongtai-requirements.md`，issue zeemen/weknora-data-factory#2）的修订，尤其是附录 A.1 的元数据字段与 ZT-03、ZT-04。
- 依据：ADR 16（已采纳）；`spec.md` 决定记录第 1–22 条；中台需求单 v0.2；WeKnora 官方文档（2026-11-03 初读，见第二节）。
- 本计划不改代码、契约与迁移；验证用的探针代码另起任务包，放 `tools/weknora-probe/`（暂定）。

## 一、范围与底线

**验证对象**：WeKnora v0.9.0（2026-10-29 发布）。验证期间锁定这个版本，升级另行评估。

**底线**（任何一项都不放宽）：
1. **只用公共资料或合成数据**，不用任何真实学生数据（规则 8、13）；不用教研金标准与留出集（规则 14）。
2. **只用测试知识库**（ADR 16 第 3.4b 节），不碰生产知识库。
3. **数据不出境**；外部模型只用 `docs/compliance/vendors.md` 里**已批准**的境内供应商。批准前不调用 DeepSeek、百炼、百度，第一阶段用验证环境里自部署的开源模型（见第三节）。
4. **不接触生产环境**（规则 9）；验证环境用完即销毁，不留数据。
5. 不在仓库、日志、报告里写任何凭据；探针脚本只从环境变量读地址与密钥。

**不在本计划内**：中台本身的验收（按需求单走）；知识服务契约的正式定稿；生产部署。

## 二、文档初读结论与已知风险（2026-11-03）

以下来自 WeKnora 官方仓库的 README、`website-docs/04-api`、`docker-compose.yml`、`.env.example`、`LICENSE` 等页面；只是文档说法，**全部要在验证中实测**。

| 方面 | 文档说法 | 对 ADR 16 的影响 |
|---|---|---|
| 许可证 | MIT；第三方组件 opencc（Apache-2.0）、anydoc（MIT）、wails（MIT） | 规则 10：可引入，仍要逐项核对镜像内依赖 |
| 技术栈与组件 | Go 后端 + Python docreader（gRPC）+ Vue 前端；Compose 默认起 frontend、app、docreader、postgres（ParadeDB，PG17 + BM25 / 向量扩展）、redis；可选 minio、neo4j、qdrant、milvus、elasticsearch、opensearch 等；有 Helm chart（K8s ≥ 1.25） | 能进 ACK；默认检索引擎依赖 ParadeDB 扩展 |
| 资源 | 建议起步 4 核 / 8 GB（docreader 含 LibreOffice、Playwright，较吃内存） | 计入集群规格 |
| 对象存储 | `STORAGE_TYPE` 支持 oss | 可用已建的 OSS |
| 模型 | 类型有对话、Embedding、Rerank、视觉、ASR；支持 OpenAI 兼容接口；内置 `aliyun`（DashScope，含 dashscope-embeddings、dashscoperank）与 `deepseek` | 与 ADR 16 第 3.6 节一致：百炼即 DashScope |
| 换嵌入模型 | 要重建索引；知识库已有文档时不能改 `embedding_model_id` | 模型要在建库前定好；换模型等于新建库再全量导入 |
| 鉴权 | `X-API-Key`；API Key 按能力（如 retrieve、ingest、manage_kbs）授权，可限定知识库白名单，默认拒绝 | 知识服务可以只拿“检索 + 测试库或生产库”的只读密钥，符合“StarBuddy 不持有管理凭证” |
| **过滤** | 检索接口 `knowledge-search`、`hybrid-search` 只能按 `knowledge_base_ids`、`knowledge_ids`、`tag_ids` 过滤，**标签之间是“或”**；**没有按任意元数据过滤**；切块上没有元数据 | **高风险**：ADR 16 第 3.2 节要求按学科、年级、省份、出版社、版本、学期等多维“且”过滤 |
| **自定义元数据** | 文档级 `custom_metadata`，**最多 20 个字段**，每个值不超过 1000 字符，整体覆盖写 | 需求单附录 A.1 列了约 30 个字段，放不下 |
| **更新语义** | 没有按外部 ID 覆盖写；重复上传返回 409；手工录入的内容可以整篇替换（`PUT /knowledge/manual/:id`）；文档级没有版本历史（只有切块级修订） | ZT-03、ZT-04 的“幂等、按版本回滚”要由中台自己维护映射与版本 |
| 纯检索 | `POST /api/v1/knowledge-search` 不经大模型，返回带分数的结果；混合检索（向量 + 关键词）、重排可开关 | 知识服务可以只用检索接口，不用问答 |
| **查询留存** | 会话与消息会落库，还会建索引，**没有关闭开关**（只能删除）；被拒绝的请求进审计日志（默认保留 90 天）；`[LLM Usage]` 日志行带提示词前缀 | **高风险**：ADR 16 第 3.5 节要求学生提问在 WeKnora 侧不落库、不留日志 |
| **默认外联** | Langfuse 追踪的默认地址是境外 SaaS（配了密钥才启用）；有 WeKnora Cloud 托管解析与托管模型；网页搜索、数据源同步、IM 渠道、MCP、Agent 等功能 | 全部要确认关闭，否则可能出境 |
| 解析 | 内置解析不做文字 OCR、不识别 PDF 表格结构；可选 MinerU、PaddleOCR-VL 等引擎；切块会保持 `$$…$$` 公式完整 | 中台交付的是结构化正文，WeKnora 的解析能力不关键；公式要验证不被切断 |
| 示例配置 | `.env.example` 里有示例数据库与 Redis 口令；`JWT_SECRET`、`SYSTEM_AES_KEY` 需要生成（丢失后加密字段无法恢复） | 部署规格里必须替换并纳入密钥管理 |

## 三、验证环境

**建议**：在已建的 staging VPC 里临时开一台 ECS（建议 8 核 / 32 GB），用 Docker Compose 起 WeKnora v0.9.0，只开内网，验证结束即释放。
- 理由：staging 集群暂缓（LT-03 决定记录第 18 条），ECS 便宜、能当天起停；数据库先用 Compose 自带的 ParadeDB，阿里云 RDS 的兼容性单列一项（V05）。
- 模型分两步：
  - **第一阶段**（供应商批准前）：同一台机器上自部署开源模型。嵌入用 bge-m3（Ollama 或 TEI），重排用 bge-reranker（TEI；文档说重排不支持 Ollama）。不调用任何外部模型。
  - **第二阶段**（合规负责人批准 `bailian`、`deepseek` 后）：换成百炼嵌入与重排、DeepSeek 对话，重跑第二阶段的项目。
- 开 ECS 要花钱，也是新建云资源，按 LT-03 的流程：先给你 plan 摘要，你确认后再建，用完由你确认释放。（待人确认第 1 条）

**测试数据**：
- 合成夹具：复用 `evals/kge-compile/fixtures`（合成地图、合成页面快照、12 题合成金标），再按需求单附录 A.1 补一批合成题目与教材小节（多省份、多出版社、多版本，故意制造“同名不同版”的干扰项）。
- 公开资料：选一册公开教材的一章、一份公开试卷，用来测公式表格与真实篇幅。按决定记录第 6 条不设授权检查，但仍只放测试库。
- 中台交付样本：中台完成需求单 P0 后，用它交付到测试库的样本复验（需求单第三节第 2 条）。

## 四、验证项

每项写明：要核实什么、怎么测、通过标准、不通过的退路。标 ★ 的是决定 ADR 16 做法能否成立的关键项，最先做。

### A. 基础与合规

**V01 许可证与依赖**（规则 10）
- 测：核对 WeKnora 仓库 LICENSE 与第三方声明；对 app、docreader、frontend 镜像生成 SBOM，列出许可证。
- 通过：没有 AGPL、SSPL 或 LGPL 这类需要另行评估的组件；有的列出来由人决定。
- 退路：不引入对应的可选组件（例如不启用某个解析引擎）。

**V02 默认外联与功能关闭** ★
- 测：在只放行内网的安全组下启动；抓包或看出口日志，确认没有任何公网请求。逐项确认关闭：Langfuse、WeKnora Cloud 托管解析与托管模型、网页搜索、数据源同步、IM 渠道、MCP、Agent、Docker 沙箱、自动打标、长期记忆、知识图谱（Neo4j）。
- 通过：空闲、导入、检索三种情况下都没有出网请求；关闭方式能写进配置并且可以核查。
- 退路：在网络层封死出口（安全组与 NAT 白名单），并在部署规格里列出必须设置的配置项。

**V03 鉴权与最小权限**
- 测：建一个只有“检索”能力、只限测试库的 API Key，确认它不能写入、不能删、不能读别的库、不能管理模型与成员；无密钥、错密钥被拒绝。
- 通过：知识服务用的密钥只能检索指定的库。
- 退路：在知识服务与 WeKnora 之间加一层只放行检索接口的网关。

### B. 部署与运维（数据开发团队负责运维，ADR 16 第 3.4b 节）

**V04 资源与容量**
- 测：按真实资料量估算切块数（初一到高三、各省各版本教材，加试卷与教辅），用合成数据灌到估算量的 10% 与 100%，记录内存、CPU、磁盘与导入耗时。
- 通过：给出集群规格与存储规格的建议值（计入 staging 集群规格重估）。

**V05 数据库与检索后端** ★
- 测：先用默认的 ParadeDB 跑通；再确认阿里云 RDS PostgreSQL 是否支持 ParadeDB 的扩展。不支持时，评估三条路：自建 ParadeDB（容器或 ECS）、阿里云 Elasticsearch / OpenSearch、Milvus。
- 通过：选定一种既在同一 VPC、又有人能运维的后端；备份恢复方式明确。
- 退路：自建 ParadeDB，由数据开发团队负责备份。

**V06 只开内网与升级回滚**
- 测：只暴露给知识服务（安全组与 NetworkPolicy 的写法）；从 v0.9.0 升到下一个小版本再回退，数据是否完好。
- 通过：有升级与回退手册，回退不丢数据。

### C. 元数据与过滤（ADR 16 第 3.2 节）★

**V07 多维“且”过滤** ★（最高风险）
- 背景：文档初读显示检索只能按库、文档 ID、标签过滤，标签之间是“或”。
- 测三种做法，各用合成的“同名不同版”干扰集，看会不会跨版本混用：
  1. **按维度分库**：每个“学科 × 学段年级 × 省份 × 出版社 × 版本”组合一个知识库，学期、考试年份等再用标签。量出库的数量、跨库检索的效果与性能、管理成本。
  2. **知识服务先算出允许的文档清单**：知识服务按自己的索引（由中台交付清单 ZT-08 同步而来）算出符合条件的 WeKnora 文档 ID，再用 `knowledge_ids` 检索。量出清单很长时（上千、上万个文档）的接口限制与延迟。
  3. **组合标签**：把常用组合做成一个标签（例如“数学·八上·江苏·苏科版·2024”）。量出标签数量与维护成本。
- 通过：至少一种做法在干扰集上 **0 次跨版本混用**，且 P95 延迟满足 V14。
- 退路：都不行时，回到 ADR 16 第 2 节重新评估（例如知识服务检索后再过滤并补足条数，代价是召回下降），由人决定。

**V08 元数据承载量**
- 测：`custom_metadata` 的 20 个字段上限、上传时 `metadata` 与 `custom_metadata` 的关系、元数据能否在检索结果里返回。
- 通过：确定附录 A.1 哪些字段放元数据、哪些用库或标签表达、哪些只放在 StarBuddy 侧（中台交付清单），据此修订需求单附录 A.1。

### D. 写入、更新与回滚（ADR 16 第 3.3 节，需求单 ZT-03、ZT-04）

**V09 稳定 ID 与更新**
- 测：用手工录入接口写入（中台交付结构化正文），确认：重复写入的行为（409）、整篇替换（`PUT /knowledge/manual/:id`）后检索结果立即反映新内容、删除后检索不到、批量删除与清库的权限。
- 通过：中台能维护“中台内容 ID ↔ WeKnora 文档 ID”的映射，用“替换”实现更新，用“删除”实现下线，做到幂等。
- 退路：按“新建 + 删除旧文档”实现更新，代价是 WeKnora 文档 ID 会变，要同步更新 StarBuddy 侧的映射。

**V10 按交付版本回滚**
- 测：交付版本 v1 → v2（新增、修改、下线各若干）→ 回滚到 v1，核对文档数、内容摘要与检索结果。
- 通过：回滚后与 v1 逐条一致；回滚可以由中台在 30 分钟内完成（按估算量）。
- 退路：两个生产库轮换（新版本导入备用库，验证后切换知识服务指向），回滚就是切回。

### E. 检索接口与质量（ADR 16 第 3.4、3.4a 节）

**V11 纯检索接口**
- 测：`knowledge-search` 与 `hybrid-search` 的请求与返回字段；向量、关键词、重排的开关；阈值与条数参数；返回里能否拿到 WeKnora 文档 ID、切块 ID、分数与自定义元数据；查询为空、超长、不命中时的行为。
- 通过：知识服务能拿到足够信息填统一信封（`evidence_ids` 为空、`source_version` 带知识库版本与内容 ID、`confidence` 由分数映射）。

**V12 检索质量对照**
- 测：在 `evals/kge-compile/compare_retrieval.py` 里加一条“WeKnora 路径”，与现有的“页面优先”“切块检索”用同一份金标比较：正确率、要点覆盖率、同题讲法一致性、上下文成本。第一阶段只用合成金标跑通流程；真实结论等教研金标（只能教研写，`evals/*/gold/`），按 KGE V1.1 第九章口径，**结论由人定**。
- 通过（暂定）：正确率不低于现有切块检索，一致性与成本不明显变差。

**V13 搜题与相似题**（`item.search`、`item.similar`）
- 测：题目按节点 ID 与过滤维度检索（节点 ID 怎么表达：标签、元数据还是分库，依 V07、V08 的结论）；相似题用题干语义检索，在合成题目族上量“同族题排进前 5”的比例。确认返回内容能做到只给引用与标签、不给题干答案（现契约的口径），或按契约草案返回。
- 通过：搜题的过滤结果与现有 SQL 实现在同一合成夹具上逐条一致；相似题前 5 命中率给出基线，由人定门槛。

**V14 性能**
- 测：单次检索 P50 / P95 / P99 延迟，含与不含重排；并发 10、50、100；数据量 10% 与 100% 两档。对照 PLT-20 的 SLO。
- 通过：P95 在知识服务的预算内（以 PLT-20 的 SLO 为准；没有定的给出建议值）。

**V15 编译页同步**（ADR 16 第 3.4a 节）
- 测：用编译器的合成页面快照导入测试库；签字页面按“页面 ID + 版本”替换；被扣下的页面（`held_pages`）不导入；页面检索结果能回到 `page.get` 的页面 ID。
- 通过：同步脚本幂等，重复运行结果不变。

**V16 公式与表格**
- 测：含 LaTeX 公式与 Markdown 表格的合成题、公开题，导入后检查切块边界不切断公式和表格，检索结果原样返回。
- 通过：抽查 20 道题全部完整。
- 退路：中台交付时按题或按小节切好，WeKnora 侧关闭再切块（如果支持）。

### F. 个人数据与查询留存（ADR 16 第 3.5 节）★

**V17 检索查询是否落库或留日志** ★
- 背景：文档初读显示会话与消息会落库且没有关闭开关；`[LLM Usage]` 日志带提示词前缀；被拒绝请求进审计日志。
- 测：只调用纯检索接口（不建会话），检索后检查：数据库各表（会话、消息、审计、用量、切块访问记录）有没有查询文本；app 与 docreader 的日志、Redis、追踪里有没有查询文本。分别在“默认日志级别”“调试关闭”两种配置下测。
- 通过：纯检索接口不在任何地方留下查询原文；或者留下的地方可以配置关闭。
- 退路（按代价从低到高）：
  1. 知识服务转发前先去掉个人信息（ADR 16 第 3.5 节已写的退路），再加上日志级别与保留期配置；
  2. 定时清理相关表与日志（数据开发团队运维），并写进部署规格；
  3. 给 WeKnora 打补丁关掉记录，需要长期维护，最后才考虑。
  - 无论选哪条，都要合规负责人确认后才算通过。

**V18 结果不回写**
- 测：检索与问答之后，知识库内容、切块、标签、自动生成的摘要都没有被改动。
- 通过：检索前后知识库内容的摘要一致。

### G. 模型（ADR 16 第 3.6 节；第二阶段，供应商批准后）

**V19 百炼嵌入与重排**
- 测：用 `aliyun`（DashScope）配置嵌入与重排；记录向量维度、单次与批量延迟、费用估算；确认“建库后不能换嵌入模型”，并演练换模型的流程（新建库、全量导入、切换）。
- 通过：选定具体的嵌入、重排模型与维度，写进部署规格与中台需求单。

**V20 DeepSeek 对话与切换**
- 测：用 `deepseek` 配置对话模型；换成另一家已批准的供应商（例如百炼）只改配置；确认 StarBuddy 侧只用检索接口时，问答功能可以不配模型。
- 通过：切换不改代码、不影响已有知识库。

## 五、阶段与顺序

## 六、产出

1. **验证报告**：`specs/kb-weknora-integration/weknora-validation-report.md`，逐项给出结论、证据（命令、截图或日志摘录，均不含凭据与个人数据）和退路选择。
2. **知识服务契约草案的输入**：过滤怎么表达、`item.search` / `item.similar` 的实现方式、信封字段怎么填。契约变更另起任务包，必停。
3. **WeKnora 部署规格**：组件、资源、检索后端、必须设置的配置项（关闭外联与日志）、密钥项、备份与升级，交给数据开发团队。
4. **中台需求单修订**：附录 A.1 的元数据怎么放（元数据、分库、标签各放什么），ZT-03、ZT-04 的更新与回滚方式。
5. **探针脚本**：`tools/weknora-probe/`（暂定），只读环境变量，可对测试库重复运行，后续可以并入契约测试。

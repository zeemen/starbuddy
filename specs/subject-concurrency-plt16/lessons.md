## 交付
- BFF 进程内闸门 `src/gate/subject-gate.ts`：按学科独立的并发上限 + 有界 FIFO 队列 + 排队超时（上限 10 秒）+ 每生每科“在处理 + 排队”上限（默认 2）；名额只释放一次，finally 中释放；请求方断开时排队中离队、入闸后计量前复查。
- 接入点：诊断开始（预留前）、取当前题 / 探针 / 作答；再练与复测的取题与作答（宵禁之后、计次与预检之前）。排队与拒绝判断只发生在计量之前；已入闸请求持有名额直到处理结束。
- 已计量的重试绕过闸门（再练同票据已计次、复测 counted、诊断开始同幂等键已有预留），日志记 `bypassed`，不再计次、不另预留。
- 被拒：503 `SUBJECT_BUSY` + `retry-after`；前端作答被拒按“提交太快”处理（留票据、原样重发），取题被拒按“稍后再试”。
- 配置 `config/concurrency.json`（每科 8 / 16 / 2000ms / 2s、每生 2、`single_instance`）；非 dev / test 环境未声明单实例时不建闸门并告警。
- 诊断六条路由新增每会话限流桶 `diagnosis.session.minute`（每分钟 60）。诊断重试加总时限 45 秒。
- 观测：访问日志记学科码、闸门结果（admitted / queued / rejected / bypassed）、排队时长分档、被拒原因，不含学生 ID。
- loadtest：单列 429 与 503 SUBJECT_BUSY、闸门汇总、可选开启再练与复测场景。
- 测试：BFF 单测与集成；bff-mutation 360 个全部发现（闸门组 33 条）；web-test 通过；loadtest 64 项。

## 审查意见的处理（按默认）
- 安全阻断：单个学生约 24 个并发即可让整科对所有人 503 → 每生每科上限、诊断补限流。
- 契约阻断：作答被拒前端丢票据，与“上游结果未知”重叠时可能同题扣两次 → 作答被拒留票据；已计量的重试绕过闸门。
- 采纳：单实例显式声明、排队超时上限、断开离队、诊断重试总时限、OpenAPI 503 与 retry-after、措辞修正、问题码一致性与学科码集合断言、注释改正。

## 与 spec 的偏差
1. spec 字面“闸门不包住已预留 / 已计次之后的段”与“包住转发”矛盾；实现为“排队与拒绝判断只在计量之前，名额持有到处理结束”，否则限不住上游并发。
2. 为不破坏既有变异锚点，接入点把闸门之后的部分拆成 `*Admitted` 函数。
3. 新增每生上限、绕过、断开离队、诊断限流桶（审查后的默认处理）。

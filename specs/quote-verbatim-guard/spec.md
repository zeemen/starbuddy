## 一、现状（2026-11-25 核对）

起草时核对了现状。先说结论：**现在没有任何一处会出现引语**，这层检查是为“模型开始写衔接语”和讲评课预先装好的。

- **现在所有对学生、家长可见的文字都不是模型写的。**
  - 档案页（`learning/mastery/profile.py`）：判断模板渲染句，加上人审过的固定衔接短语。
  - 首份报告（`insight/report.py`）：同上。
  - 周报（`insight/weekly.py`）：同上，衔接短语还是占位。
  - 月计划（`insight/monthly.py`）：同上。
- 一致性检查的第 0 条 `connective_unapproved` 要求衔接语逐字出自固定短语表。所以今天哪怕有人把引语塞进衔接语，也会被这一条挡住。
- **模型写衔接语的接口已经留好**：档案页有 `ConnectiveSource`（`profile.py`），按 KGE V1.1 的设计，模型以后只写排序与衔接语。
  - 到那时第 0 条要换成别的规则：固定短语表做不到逐字列举模型的输出。
  - 现有的第 2–6 条（程度不升级、不新增结论、无数字、无人设语言、禁用推断）都**管不到引语**。
  - 所以模型可以写出“你说过‘我就是学不会’”这种话：程度词、结论词都不命中，引语却是编的或改过的。
- **学生原话在哪里**：只在证据原文里，即 `platform.evidence_event.payload.text`。原文有三种：
  - `response_text`：键盘输入的作答；
  - `ocr_transcription`：拍照识别的作答；
  - `asr_transcription`：语音识别的作答。
- **谁能读原文**：学习服务（`starbuddy_learning`，有 SELECT 权限）能读。洞察服务按设计**不读证据原文**（README：只用 0028 授予的列）。
- **其他自由文字都不是学生原话**：
  - 学生自述（`insight.self_report`）是字段白名单里的结构化值；
  - 异议里的“那次只是失误”没有文字列；
  - 家长目标备注（`insight.guardian_goal.note`）是家长的话。

## 二、默认做法

1. **引语必须结构化标出，不能藏在自由文字里**
   - `consistency.Section` 新增 `quotes: tuple[Quote, ...]`，默认为空，现有调用方不用改。
   - `Quote = { key, evidence_id, text }`。
   - 衔接语里只用占位 `{q:<key>}` 表示“这里放一段引语”。显示时由渲染程序加引号，模型或拼接方不写引号。
   - 检查时：
     - 对衔接语里占位以外的部分，照常跑第 0–6 条；
     - 全文禁用推断检查连同引语一起查。
2. **新增阻断条件**（追加到 `check_page`，任何一条不过就阻断）：

   | 编码 | 条件 |
   |---|---|
   | `unmarked_quote` | 衔接语的自由文字部分出现引号类字符：`“ ” ‘ ’ 「 」 『 』 " ' ＂ ＇ ﹁ ﹂ ﹃ ﹄`。引语只能走结构化标出 |
   | `quote_placeholder` | 占位与 `quotes` 对不上：用了没声明的 key、声明了没用、同一 key 用了两次、key 格式不对 |
   | `quote_too_long` / `too_many_quotes` | 一段引语超过 30 个码点、为空，或一节超过 1 段引语 |
   | `quote_not_cited` | 引语的 `evidence_id` 不在同一节所引判断的证据里。引语必须是这条判断的依据，不能随便挑一句作答（`ClaimView` 新增 `evidence_ids`，默认为空） |
   | `quote_unverified` | 原文核对没有通过：不是该生的证据、证据种类不允许、证据已删除或在“数据有误”异议处理中、原文里找不到这段文字（逐字，见第 3 条）、原文服务不可用 |
   | `quote_audience` | 引语出现在家长版里。周报已经规定“家长版不含逐句对话”，引语不扩大家长能看到的范围 |

   阻断后的降级与现在一样：
   - 档案页：`blocked_fallback`，去掉全部衔接语，只留模板句；
   - 首份报告、周报：照现有口径不出（withheld），只留阻断编码。

   这对应 OpenMAIC 的“整条丢弃”。只删引语、保留衔接语不行：去掉引语后，剩下的衔接语可能读不通，或者语义变了。
3. **“逐字”的口径**
   - 两边都先过 `consistency.normalize`：NFKC 规范化，再去掉空白与不可见字符。此外不做任何归一，不忽略标点，不做同义、简繁或拼音匹配。
   - 规范化后，引语必须是原文的连续子串。
   - 原文只认作答原文这一处。
4. **原文核对放在学习服务，洞察服务看不到原文**
   - 规则引擎只依赖一个接口：`QuoteSource.verify(student_id, quotes) -> {key: ok | 原因编码}`。
   - 学习服务内（档案页）的实现直接查库，只查 `evidence_event`。
   - 洞察服务的实现调学习服务的新内部接口 `POST /internal/v1/quote/verify`：
     - 复用现有的洞察服务令牌 `LEARNING_INSIGHT_CLIENT_TOKEN`，与 `/internal/v1/verification` 同一套鉴权、超时与 Host 规则；
     - 只回每段引语“通过 / 原因编码”，**不回原文、不回位置**；
     - 这个接口不在契约里（与验证任务接口同类）。
   - 防止拿这个接口反复试探原文：
     - 每次最多 8 段引语，每段 ≤ 30 码点；
     - 只接受该生自己的证据 ID；
     - 不存在、不属于该生、种类不允许，回同一个编码 `not_found`；
     - 日志只记计数与编码，不记引语文字（规则 8）。
   - 原文服务超时或不可用时**一律按不通过处理**（fail closed），报告照第 2 条降级，不重试拖延生成。
5. **证据种类**
   - 默认只认 `response_text`，即学生自己打的字。
   - `ocr_transcription`、`asr_transcription` 是识别结果，可能把学生没写的字当成原话；拍照入口的规格（`specs/photo-paper-intake`）也把照片证据定在 B 级以下。所以默认不允许引用，见第五节第 2 条。
6. **本期接到哪里**
   - 规则引擎与两侧的 `QuoteSource` 实现都做好。
   - 首份报告、周报、档案页的检查调用都带上 `QuoteSource`，`quotes` 一律为空，所以三处输出逐字节不变。
   - 引语怎么出现在输出里（报告 JSON 的形状、`RenderedStatement` 是否加字段、前端怎么显示引号）属契约变更，必停，等第一个真正生成引语的功能（模型衔接语或讲评课）一起定。
   - 这期不加任何能产生引语的功能。
7. **测试**（全部用合成数据，规则 8）
   - 规则引擎单测，覆盖每个新编码：
     - 正例：逐字子串、全角半角与空白差异通过；
     - 反例：改一个字、换标点、简繁不同、拼接两段原文、引语来自别的学生、来自不在所引判断里的证据、OCR 或 ASR 证据、证据已删除、证据在“数据有误”异议中、原文服务超时；
     - 现有第 0–6 条的用例全部照常通过。
   - 性质测试：对任意原文，取随机连续子串都通过；子串里任意替换、插入、删除一个非空白字符后都不通过。
   - 学习服务接口测试：鉴权（BFF、编排层令牌都被拒）、上限、`not_found` 的统一口径、响应里没有原文、日志里没有引语文字。
     库上测试用合成证据，走现有 `pg` 测试夹具。
   - 洞察服务：`QuoteSource` 的 HTTP 实现（超时 → 不通过）；三处检查调用带上 `QuoteSource` 后输出逐字节不变（快照）。
   - 变异测试，各加几条，断言都能被发现：
     - 子串比较改成“去标点后比较”；
     - 跳过 `quote_not_cited`；
     - 超时改成通过；
     - 家长版不查 `quote_audience`；
     - `unmarked_quote` 的引号表少一个字符。
     加在 `services/learning` 与 `services/insight` 现有的变异脚本里。
   - 要通过：`make check-fast`、`make check`（含学习服务、洞察服务单测与契约测试）、`make insight-mutation`、学习服务变异。

## 三、不做
- 让模型写衔接语或报告文字：另起，要过人设与 SIE 负责人审核。第 0 条（固定短语表）怎么换，也在那时定。
- 引语在报告、周报、档案页输出里的形状，以及前端显示：契约变更，必停，随第一个生成引语的功能另起。
- 讲评课台词里引用学生作答：台词稿是预审内容，按 ADR 07 不含学生数据（`specs/stage-dsl-v0.2`）。
  直播态的现场台词若要引用作答，要在台词稿里加引语占位，属 DSL 格式变化（升版本）。随借鉴第 4 点与讲评课第二步另起，到时复用本规则引擎。
- 引用家长的话（家长目标备注、家长观察）：不属于“学生原话”，本期不允许任何引用。
- 用模型判断“没有引号的转述”，例如“你说你学不会”这种不加引号的转述：确定性规则查不出来，以后可以追加模型辅助检查，只能增加阻断。
  本期由第 0 条固定短语表兜底，也写进 lessons 的已知局限。

## 四、验收
- 上表六种情形都被阻断，并按现有口径降级或不出。
- 逐字子串（只差全角半角或空白）通过，改动任意一个非空白字符都不通过。
- 洞察服务拿不到证据原文。学习服务接口不回原文，不属于该生的证据与不存在的证据回同一个编码，日志里没有引语文字。
- 现有档案页、首份报告、周报、月计划的输出逐字节不变，现有一致性用例全部通过。
- 第二节第 7 条列的检查全部通过；零新依赖；契约、迁移、RLS 无改动。

## 五、待人确认（括号里是默认；第 1–4 条请 SIE 负责人定）
1. **“逐字”的口径**：只做 NFKC 与去空白，标点必须一致，不做简繁与同义匹配（默认）；还是标点也忽略？
   忽略标点会让“对。”与“对？”等同，意思可能相反。
2. **能引用哪类原文**：只引用键盘输入的作答（默认）；还是学生在拍照入口确认过识别结果之后，OCR 与语音转写也可以引用？
   后者要等拍照入口的“学生确认”工序落地。
3. **家长版能不能有引语**：不能，与周报“家长版不含逐句对话”一致（默认）；还是家长版可以引用，但只限孩子在作答里写的字？
4. **一段引语的长度与数量**：每段 ≤ 30 码点、每节最多 1 段（默认）；具体数字请 SIE 负责人与教研定。
   另外，数学作答几乎都含数字，现有第 4 条“衔接语不得含数字”只管占位以外的文字，不管引语。这样处理算不算放宽了第 4 条，请一并确认。
5. **原文核对不可用时**：一律不通过、按阻断降级（默认）；还是这次生成改期重试？

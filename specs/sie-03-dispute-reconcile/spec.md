## 现状（调研结论）
- **异议只有入口没有流程**：0023 能把判断异议送进复核队列（`profile_dispute`，只能“转洞察服务”结案），但洞察服务没有 `insight.dispute`，也没有 `dispute` 表；验证题需要 KGE-04 第二步的复测 / 验证任务（`platform.retest_task` 待建）。
- **预测与对账全无**：考试范围与日期没有录入口；`insight.predict / reconcile` 未实现；预测依赖“节点掌握 × 地区考情权重 × 题型”，掌握估计要等 KGE-04 第二步，题型来源待定（KGE-04 #4）。
- **触发规则全无**：没有 `intervention_log`，也没有评估任务。
- **导出与删除**：没有统一的导出与删除；各表的级联删除分散在各迁移；档案页（KGE-04 第二步）与判断账本、洞察表、行为事件、诊断、会话等都需要覆盖；0010 的 `insight.claim` 删除语义（推翻与撤回保留用于审计）与“删除覆盖全表”要对齐。

## 设计要点
### 1. 异议三路（`insight.dispute`）
- 入口：学生本人、已绑定家长，对自己可见的判断提出；三种类型：
  - **我其实会**（i_know）：判断转“待验证”，24 小时内经 KGE 验证任务安排 2 道无提示验证题（含 1 道变式）；支持原判断 → 原判断撤销并上调（由 KGE 重算后生成新判断）；不支持 → 展示新证据、维持；
  - **我是粗心**（careless）：不改判断；记录为学生自述（self 来源，规则 6），与错因归档分开存，触发一次同节点练习；不贴“粗心”标签（七科合同第 5 条：“粗心”全平台禁用于对学生的评价）；
  - **数据有误**（data_error）：进统一复核队列（复用 0023 `profile_dispute`），教研核实后若事实更正 → 依据推断行更正 → 相关判断撤回并重算（100%）。
- 新表 `insight.dispute`（迁移草稿）：学生、提出人、判断、类型、状态、验证任务引用、结果、时间；写入只经洞察服务；学生 / 家长只读自己提出的与关于自己的。
- 异议不得产生任何新的评价性陈述；回应文案走模板（必停，人写人审）。

### 2. 考前预测冻结与对账卡（`insight.predict` / `insight.reconcile`）
- 录入：学生或家长录入考试（范围节点、日期、满分），写 `insight.exam_record`（0022 已有，必要时补列，迁移草稿）。
- 预测：`Σ 范围节点 × 掌握 × 地区考情权重 × 题型` 估分数区间（默认 80%，证据少则宽）；七八年级 100 分制与九年级 120 分制分开；只比较相对区间，不造精确能力分。**依赖 KGE-04 第二步**：之前用合成掌握行验证。
- 冻结：考试当天零点（上海时区）由定时任务冻结存档，冻结后不可改（库层守卫）。
- 对账卡：成绩上传后生成：区间内 / 外、偏差来自哪些节点、平台据此改了什么；偏差归因固定四方向（题型迁移、时间不足、计算失误、此前诊断偏乐观）；只由判断渲染，每句带判断 ID（规则 11）。

### 3. 触发规则 v1
- 新表 `insight.intervention_log`（迁移草稿）：规则键、动作、引用的判断 ID、结果引用、时间。
- 规则（SIE 第七章）：提醒（节点到复习时间、验证题待做 → 放入今日计划，不单独推送）、证据化鼓励（只基于判断账本里的具体进步，不做空泛表扬）、降负（连续中断 ≥ 3 天或连错后退出率上升 → 缩短任务、插入熟悉题、询问原因，不追加任务）；参数配置位待签字。
- 输出只是“动作建议”给编排层与今日计划（4-H H4）；文案模板必停。

### 4. 导出与删除（`insight.export` / `insight.erase`）
- 覆盖清单：用一份机器可读的“个人层表清单”（从 schema 自动发现所有带 student_id 或经外键关联学生的表 + 显式登记的例外），测试断言清单与库一致（新增表不登记就失败）。
- 导出：家长发起、按学生；JSON 包（各表按列白名单，不含其他学生、不含审核员身份、不含内部推断参数），经 BFF 下载；导出本身记审计。
- 删除：家长发起、二次确认、冷静期（默认 7 天，可撤回）后执行；按清单在一个事务里删除个人层全部行与档案页（KGE-04 第二步的表一并登记）；公共层与聚合统计不受影响（规则 13）；删除回执（不含被删内容）。推翻与撤回的判断在删除时同样删除（审计保留只到删除请求为止，#4）。
- 执行身份：一个只授删除函数的 SECURITY DEFINER（属主 authz），由调度器在冷静期满后调用。

### 5. 禁用推断 0
- 所有新文案模板、异议回应、对账卡、触发动作说明过 SIE-00 禁用推断词表检查（阻断）；新增测试覆盖。

## 待人确认
1. **依赖顺序**：默认先做不依赖 KGE-04 第二步的部分（异议“数据有误”与“粗心”、删除与导出、触发规则框架），“我其实会”的验证题与预测在 KGE-04 第二步落地后接真实数据，之前用合成与接口桩。

3. **删除冷静期与时限**：默认 7 天冷静期、到期后 24 小时内执行；按合规方案调整。
4. **推翻与撤回判断的审计保留**：默认随删除一起删除（删除优先于审计）；另一个选择是保留去标识的计数用于模型评估（需合规确认，规则 13 的聚合门槛）。
5. **导出格式**：默认 JSON（机器可读）+ 一份简要说明；是否需要人可读的 PDF 另议。
6. **预测区间**：默认 80% 区间；学生版只显示区间与对账结论，家长版另附置信度说明。
7. **触发规则参数**：连续中断天数、退出率阈值等由 SIE 负责人与教研签字；签字前只生成动作建议、不下发。

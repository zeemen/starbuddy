## 一、现状（2026-11-17 核对）
| 服务 | 连接池 | 取连接等待上限 | 语句超时 | 事务开着闲置的超时 |
|---|---|---|---|---|
| BFF（`services/bff/src/main.ts:185`） | `pg.Pool`，max 10 | 无（缺省一直等） | 无 | 无 |
| 学习服务（`services/learning/learning/app.py:261` 及两个专用池） | asyncpg，max 10 | asyncpg 缺省 60 秒 | 无 | 无 |
| 洞察服务（`services/insight/insight/store.py:83`） | asyncpg，max 10 | 缺省 60 秒 | 无 | 无 |
| 数据库角色与参数组 | — | — | 迁移与 IaC 里都没设 | 只有 0052 的一个函数在事务内设 60 秒 |

后果：数据库一卡（锁等待、慢查询、连接被占满），请求就挂住。BFF 的 HTTP 层 30 秒后断开客户端，但处理函数还在等数据库，
分学科闸门的名额也一直占着，同一科后面的请求全部 `503 SUBJECT_BUSY`。连接池被挂住的连接占满后，连健康检查之外的所有请求都会排队。

## 二、默认做法
1. **只管处理请求的连接池**；调度器、命令行任务、迁移执行器、审核台的一次性脚本不改（它们有长查询，例如分区维护与留存清理）。
2. **BFF**（`pg.Pool`）：
   - 取连接等待上限 `connectionTimeoutMillis: 3000`：池满时 3 秒拿不到连接就失败，走已有的 500 / 503 路径，不排队到天荒地老。
   - 语句超时 `statement_timeout: 10000`（毫秒，连接级）与客户端兜底 `query_timeout: 12000`。
   - 事务闲置超时 `idle_in_transaction_session_timeout: 15000`：事务开着却不发语句（例如处理函数在等别的东西）超过 15 秒，库端断开，锁与连接都放出来。
3. **学习服务、洞察服务**（asyncpg）：`command_timeout=10`（客户端），`server_settings` 加 `statement_timeout = 10s`、
   `idle_in_transaction_session_timeout = 15s`；取连接用 `pool.acquire(timeout=3)`（只改请求路径上的取连接，专用池按同一口径）。
4. **数值放在代码里的一处常量**（每个服务一处，注释写来源），不新增环境变量。理由是新增变量要改部署清单 `deploy/config/env-inventory.yaml` 与首次部署手册，而现在没有按环境调的需要。
   要调时再改成变量（见待人确认第 2 条）。
5. **闸门名额**：不另做看门狗。名额在处理函数结束时归还，而处理函数里的数据库调用有了上面的超时，最长占用时间就有了上界
   （BFF 自己的数据库调用：取连接 3 秒 + 语句 10 秒；调学习服务的那几条路由另有已有的 45 秒重试总时限，`src/practice/service.ts` 的 `RETRY_BUDGET_MS`）。在 lessons 里写明这个上界，并用测试验证。
6. **失败时的表现**：超时按各服务已有的“数据库出错”路径处理（BFF 回统一的 500 / 503，学习服务回已有的 500 `INTERNAL`），
   不新增错误码与文案。日志只记 `event` 与错误类别（如 `query_canceled`、`pool_acquire_timeout`），不记 SQL 与参数。

## 三、测试
- BFF：`tests/db-timeouts.test.ts`
  - 连接池配置钉住三个数值。
  - 真实库上 `SELECT pg_sleep(…)` 超过语句超时会被取消。
  - 池满时取连接 3 秒内失败。
  - 闸门名额在数据库超时后被归还：同一科的下一个请求能拿到名额。
- 学习、洞察服务：池的配置钉住；真实库上 `pg_sleep` 被取消；超时走已有错误路径。
- 计量：`make bff-test`、`make learning-test` 里的计量幂等测试照常通过；另加一条用例，验证预留中途语句超时后事务整体回滚、同一幂等键重试按既有规则处理。
- BFF 变异：去掉语句超时、去掉取连接上限、去掉事务闲置超时，各一条。

## 四、不做
- 调度器、命令行、迁移、审核台一次性脚本的连接（有长查询，另评估）。
- 数据库参数组（RDS）层面的全局 `statement_timeout`：要在控制台或 IaC 里改，属运维（见待人确认第 3 条）。
- `stats()` 的生产出口、前端按 `retry-after` 退避（PLT-16 的另两条后续项）。

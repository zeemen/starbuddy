## 16px 可辨的阈值与实测（spec 验收要求记录在这里）
- **星内部**：像素中心在五角星多边形内，而且离边的距离大于“半个描边 + 0.5 CSS px”，按几何计算，不从截图推断。
  - 同一个几何内缩，DPR 1 下剩 14 个设备像素，DPR 2 下剩 48 个；
  - 另断言内部像素 ≥ 10 × DPR²，太少时比例没有意义。
- **被填充**：与星框外底色的灰度差 > 12（0–255）。
- **任意两态之间**：灰度差 > 12 的像素 ≥ 20 × DPR²。
- **实测**（chromium-1194，本容器）：

  | 环境 | 未亮 | 半亮 | 亮 | 保持 | 最小两态差（像素） |
  |---|---|---|---|---|---|
  | 浅色 DPR 1 | 0.00 | 0.50 | 1.00 | 1.00 | 33（半亮 ↔ 亮） |
  | 深色 DPR 1 | 0.00 | 0.50 | 1.00 | 1.00 | 33 |
  | 浅色 DPR 2 | 0.08 | 0.54 | 1.00 | 1.00 | 122 |
  | 深色 DPR 2 | 0.00 | 0.54 | 1.00 | 1.00 | 129 |

- **半亮保持 0.55 不透明度**：测试达标，没有改成不透明。

## 实现中的决定与对 spec 的偏差
1. **星空的结构**：spec 写的是“每片星空是一个 `role="img"` 的 SVG”。
   - 实现是 `role="img"` 的网格容器（`aria-label` 为摘要），里面每颗星一个 `aria-hidden` 的小 SVG。
   - 这样容器变窄时可以用 CSS `auto-fill` 按宽度折行，星始终保持 16px；单个 SVG 缩放后星会小于 16px。
   - 宽屏时 `max-width` 取接近正方形的列数（阿鸦 31 列，744px）。`layout.ts` 提供排序与坐标这两个纯函数。
2. **未亮描边的浅色占位**：spec 说视觉负责人给色值之前暂用鸦青 50% 不透明度，但实测对宣白只有 2.95:1，仍然不到 3:1。改用鸦青 55% 叠在宣白上的纯色 `#7F8490`（3.37:1）。深色主题按 spec 默认。
3. **Playwright 锁 1.56.1**，而不是 spec 起草时查到的 1.63.0。
   - 原因：与开发容器预装的 chromium-1194 一致，本地不用下载浏览器。
   - `@axe-core/playwright` 自带的 `playwright-core` 用 overrides 统一到 1.56.1，否则类型冲突。
4. **sharp**：用仓库内的占位包 `apps/web/vendor/no-sharp` 顶替（根依赖 `file:` 加 `overrides: { sharp: "$sharp" }`）。
   - 锁文件里只有一条指向占位包的链接，没有 `@img/*`，也不会下载 libvips；
   - 占位包被 require 时直接报错，不会悄悄走 LGPL；
   - spec 的字面要求是“锁文件里没有 sharp”，现在有一个同名占位包，由 `license-check` 核对它只能是这个占位包（待人确认 #10）。
5. **Next.js 遥测**：Next 默认会把匿名遥测发往境外。所有脚本、Makefile、CI 都设了 `NEXT_TELEMETRY_DISABLED=1`（ADR 09）。
6. **知行的六种 state**：spec 同时写了“知行 4 个合成能力点”和“每个学生阿鸦、知行各覆盖六种 state”，两者矛盾。
   - 按待人确认 #9 的默认保留 4 个点，覆盖未亮、半亮、亮、亮·保持四种显示结果；
   - 六种 state 由阿鸦覆盖。
7. **开发身份桩多加了一个条件**：请求本身也必须来自 loopback，不只是服务监听 loopback。
8. **`/dev/session` 用相对地址跳转**：按 Host 头拼出的绝对地址会把 127.0.0.1 换成 localhost，cookie 因此丢失；这也避免了信任 Host 头。
9. **“JSON Schema 测试”**：BFF 没有 JSON Schema 校验依赖。集成测试逐层断言键的集合与 OpenAPI 的 `additionalProperties: false` 一致，另外全文扫描敏感字段名。
10. **构建产物外链检查的口径**：只查会被浏览器自动加载的写法（CSS `url()` / `@import`、`src`、`srcset`、`<link href>`、脚本里的 `fetch` 与 `Worker`）。
    - `<a href>`、XML 命名空间、React 报错里的文档链接不算；
    - 运行时由端到端测试“所有请求同源”兜底。
11. **BFF 的源码变异**：`bff-mutation` 原来只做数据库函数变异。新增的源码变异把 `services/bff` 复制到临时目录再修改源码，工作区不受影响。

没有阻断。4 条建议都已处理：
- A：种子用未准入的证据写了 `transfer` / `retain`，违反 `mastery_estimate` 表注释的不变量。已在种子文件头注明，这只是原型演示，真实学习服务（4-C）必须拒绝。

- C：种子加了环境保护，执行方必须显式设置 `starbuddy.allow_synthetic_seed=on`，否则直接报错。原因：合成的知行能力点会出现在该库每个知行学生的星空里。

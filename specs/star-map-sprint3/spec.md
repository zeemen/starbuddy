## 目标
一名学生（或已绑定的家长）打开星图页，能看到这名学生**每个已选学科一片星空**。每颗星对应平台的一个 `skill_node`，按平台 `mastery_estimate` 的当前记录显示为未亮、半亮、亮三态之一（“保持”层加外圈）。星在 16px 下三态仍可区分。

验收场景：同一个合成学生同时有阿鸦（数学）和知行（道法）的掌握记录，两片星空显示在同一页上。

本冲刺是原型：数据链路要真实，从平台库经 BFF 到前端，并受 RLS 约束；登录、导航、点亮动效的触发时机都留给 4-H。

## 设计要点

### 1. 数据来源与接口
**链路**：浏览器 → `apps/web`（Next.js 服务端组件或 route handler）→ BFF → Postgres（`starbuddy_bff` 身份，RLS 生效）。
- 浏览器不直连 BFF，也不直连数据库、学习服务。
- 前端只拿 BFF 返回的展示数据，不自己推算掌握状态（规则 2：不做第二真相源）。

**BFF 读模块** `services/bff/src/star-map/`：
- `getStarMap(pool, accountId, studentId)`：在 `withAccount` 事务里执行一条只读查询：
  - 取学生的 `subject_enrollment`，默认只取 `active`（待人确认 #7）；
  - 对每个在读学科，取该学科全部 `skill_node`（范围见待人确认 #8）；
  - `LEFT JOIN` 取 `mastery_estimate`，条件是 `is_current AND student_id = $student`。
- 没有掌握记录的能力点按 `unseen` 处理。
- 查询不到学生（未授权与不存在同样处理）→ 返回“未找到”，不区分两种情况，不泄露学生是否存在。
- 事务设为 `READ ONLY`。

**HTTP 层**（本冲刺最小实现，用 `node:http`，不引入框架，与阿鸦 `adapters/aya/src/server.ts` 同一做法）：
- `GET /bff/v0/students/{student_id}/star-map`：
  - 成功返回 200；未登录返回 401；未授权与不存在都返回 404。
  - 响应头带 `Cache-Control: no-store`。
- **身份来源（开发桩）**：没有登录系统，本冲刺用一个开发专用的身份桩，只在同时满足下面两个条件时生效：
  - 环境变量 `STARBUDDY_DEV_AUTH=1`；
  - 只监听 loopback。

  桩从请求头 `x-dev-account-id` 读账号。任一条件不满足时，这个请求头一律忽略，请求按未登录处理（401）。4-H 用真实会话替换它（待人确认 #3）。

**响应结构**（v0，放在 `services/bff/openapi/star-map.v0.yaml`，不进 `packages/contracts`，见待人确认 #2）：
```
{ student_id, generated_at,
  skies: [ { subject, enrollment_status,
             stars: [ { skill: "<subject>:<local_id>", label_code, display: "unlit"|"half"|"lit", retained: bool, needs_verification: bool } ],
             summary: { unlit, half, lit } } ] }
```
- **不返回** `p_mastery`、`confidence` 原值、`evidence_ids`、`algorithm_version`：
  - 星图只表达三态，不暴露“差 0.03 就亮”这类数值；
  - 按数据最小化原则，证据下钻属于周报（5-H）。
- `needs_verification`：由 `confidence` 按阈值折算，含义见第 2 节。
- `summary` 只是本人各态计数，**不含**任何跨学生统计。

### 2. 三态映射（4-C 之前的默认规则，待人确认 #1）
视觉规范“星形符号规范”写的是：三态对应掌握门槛的“理解、执行 / 稳定、迁移”三段，“保持”用亮星外圈表示。据此：

| `mastery_estimate.state`（is_current） | 显示 | 外圈 |
|---|---|---|
| 没有记录 / `unseen` / `understand` | 未亮 `unlit` | 否 |
| `execute` / `stable` | 半亮 `half` | 否 |
| `transfer` | 亮 `lit` | 否 |
| `retain` | 亮 `lit` | 是 |

- **只按 `state` 映射，不看 `p_mastery`**。门槛判定是学习服务（4-C，由教研配置）的职责，前端和 BFF 不重算。这样 4-C 上线后本映射不用改，“刷同题点亮”也只需要在 4-C 防住。
- **复测失败退回半亮**（视觉规范）：这由 4-C 写一条新的 `stable` 记录实现，星图自然跟随，不需要特殊处理。
- **不确定**：完整方案第二章要求“证据不足时显示‘不确定 / 待验证’”。默认 `confidence < 0.5` 时置 `needs_verification = true`，阈值见待人确认 #1。
  - 星的三态不变，只在列表视图和详情里加文字“待验证”。
  - 16px 的星上不加额外符号，避免与三态混淆。
- **映射放在 BFF 一处**（`src/star-map/display-state.ts`），学生端、家长端、周报共用。前端只认 `display` 与 `retained`。
- **4-C 之前的风险**：4-C 之前库里的 `transfer` / `retain` 只可能来自合成数据。所以原型页和截图一律带“原型 · 合成数据”水印，避免被当成真实星亮。

### 3. 渲染与 16px 可辨
**星形符号组件** `apps/web/src/star/Star.tsx`：
- 纯 SVG。几何取视觉规范图 2b 的五角星顶点，归一化到 `viewBox 0 0 24 24`。
- `stroke-linejoin: round`，对应视觉规范“转角圆角半径 = 1 线”。
- 输入是 `display`、`retained`、`size`。

| 态 | 描边 | 填充 |
|---|---|---|
| 未亮 | 石灰 | 无 |
| 半亮 | 鸦青 | 右半星光金，用 `clipPath` 裁出右半，不另画多边形 |
| 亮 | 鸦青 | 星光金全填充 |
| 保持 | 同“亮” | 外加一圈细描边圆 |

**颜色与线宽**：
- 颜色取自视觉规范第三章，写进 `apps/web/src/star/tokens.ts`。正式的家族令牌文件交付后替换（待人确认 #5）。
- **线宽**：视觉规范的“1 线 = 角色身高 1/48”是给角色定的，直接用到 16px 的星只有 0.33px，看不见。默认按图 2b 的比例（描边 2 / 星高 84）缩放，下限 1.5 CSS px（待人确认 #4）。
- **16px 可辨**：视觉规范要求“靠填充比例，不靠颜色深浅”。三态的区分依据是星内部被填充的面积：约 0、约 1/2、约 1。自动测试见验收标准。
  - 半亮按图 2b 用 0.55 不透明度。如果 16px 灰度测试不达标，默认改为不透明，并请视觉负责人确认（待人确认 #4）。

**星空布局** `apps/web/src/star/layout.ts`：
- 纯函数，输入是星列表，输出是坐标。同一输入永远得到同一布局，这是截图测试的前提。
- 默认按 `local_id` 排序后，排成紧凑网格。星位中心间距 24px，星本身 16px。
- 平台没有分组或星座字段。阿鸦的 cluster 只在其内容包里，前端**不读**适配器内容包（规则 1），所以原型不做星座分组（待人确认 #8）。
- 阿鸦的 959 颗星约排成 31 列 × 31 行（744px 见方）。手机宽度下按容器宽度折行，纵向滚动；不做缩放手势。
- 页面按学科分节，每节一片星空。节标题是学科中文名：阿鸦 → “数学”，知行 → “道法”（待人确认 #9）。
- 页面底色随主题，用宣白或深色底：
  - **不画装饰性星点、光斑、粒子背景**；
  - 星光金只出现在半亮、亮星的填充上。视觉规范规定它是唯一奖励色，禁止装饰性使用。

**动效**：
- 组件提供“点亮”一次性发光：描边外发光 0 → 6 线宽 → 0，1.2 秒，不循环。
- 本冲刺**不触发**点亮动效。“什么时候算新点亮”需要记录上次查看时间，属于 4-H 或 4-C。只在符号样张页演示。
- `prefers-reduced-motion` 下，发光改为静态描边变色（视觉规范第五章）。

**深色主题**：视觉规范没有给星的深色规格（待人确认 #6）。默认：
- 鸦青描边改为宣白 60% 不透明，与角色描边规则一致；
- 未亮星的石灰描边不变（对鸦青底 4.46:1）。

### 4. 隐私与家长视角
- **授权只在数据库**：BFF 不自己判断“这个家长能不能看这个学生”，完全依赖 RLS（`can_read_student`）。这样与 2-E 和 schema 的授权只有一处。
- **家长视角**：
  - 已绑定的有效家长看到的星图与学生本人相同，完整方案第二章写的是“学生与家长分别看到星图”；
  - 家长页不出现任何角色形象（视觉规范第六章“家长端”），不出现任何话术；
  - 绑定被撤销（`status = 'revoked'`）后立刻看不到；
  - 同一家长的两个孩子分别请求，互不混入。
- **不做比较**：
  - 没有同伴、班级、平均线；
  - 没有“星数排行”（视觉规范禁止项）；
  - 不显示与上周的差值。点点 §4.13 只允许一种本人纵向比较，而且那是点点的话术，不是星图 UI 的内容。
- **不把非学科维度画成星**：只渲染 `skill_node`。学习力、家庭维度不进入本接口。
- **缓存与存储**：学习者模型属于 ADR 09 的 L2 数据。
  - 接口 `no-store`；前端不写 `localStorage` / IndexedDB；
  - 本冲刺**不注册 Service Worker**，PWA 离线缓存留给 4-H 并单独评估；
  - 截图与测试一律使用合成数据（规则 8）。
- **日志**：BFF 只记路由、状态码、耗时与 `student_id` 的哈希，不记星图内容。
- **静态资源**：不加载境外字体或 CDN（ADR 09 第 4 条），字体用系统字体栈。构建产物里检查不出现外部资源域名。

### 5. 可访问性
- 视觉规范的要求是“不用颜色单独承载信息”。三态靠填充比例区分，另外每颗星都有文字状态。
- **每片星空**：
  - 是一个 `role="img"` 的 SVG；
  - `aria-label` 是摘要，例如“数学星空：亮 12 颗，半亮 30 颗，未亮 917 颗”；
  - 959 颗星不逐个进入 Tab 顺序。
- **列表视图**：每片星空旁边有“以列表查看”开关，列表是真实的 `<table>`，列为：能力点编码、状态文字（未亮 / 半亮 / 亮 / 亮·保持）、是否待验证。键盘与读屏用户通过它读取每颗星。
- **16px 的星不做单独点击**：触控目标达不到 44px。逐颗的详情放在列表视图里；星的详情浮层留给 4-H。
- **对比度**：
  - 星的轮廓与底色的对比度要 ≥ 3:1（WCAG 1.4.11）。浅色主题下石灰描边只有 2.88:1，默认处理见待人确认 #6。
  - 文字对比度 ≥ 4.5:1。
- **其他**：`prefers-reduced-motion`、`prefers-color-scheme`、200% 缩放下不出现横向滚动；页面语言设为 `lang="zh-CN"`。

## 验收标准（可测试）
- [ ] **开发计划验收**：端到端测试（Playwright）以合成学生 S1 的开发身份打开 `/star-map/S1`，页面上同时有“数学”和“道法”两片星空。每片星空里各态星的数量（按 `data-display` 属性计）等于种子数据按第 2 节映射得到的期望值。截图存档，可以作为 Gate 0 星图截图的原型版本。
- [ ] **三态映射**：单测覆盖 `mastery_state` 的六个取值加“无记录”，一共七种输入，每种都有断言。已被取代的记录不参与：种子里 S1 的某个能力点历史上是 `transfer`，当前是 `stable`，显示必须是半亮。
- [ ] **不返回敏感字段**：接口响应的 JSON Schema 测试断言没有 `p_mastery`、`confidence`、`evidence_ids`、`algorithm_version`。
- [ ] **授权**（BFF 集成测试，一次性 Postgres，走真实 RLS）：
  - 学生本人 200；
  - 已绑定家长 200，内容与学生本人一致；
  - 兄妹之间互看 404；
  - 另一户家长 404；
  - 绑定撤销后 404；
  - 停用的学生账号 404；
  - 未登录 401。
  - 404 的响应体与“学生不存在”逐字节相同。
- [ ] **开发身份桩关得住**：没有 `STARBUDDY_DEV_AUTH=1`，或者监听地址不是 loopback 时，带 `x-dev-account-id` 的请求得到 401。有测试。
- [ ] **16px 可辨**（像素测试）：
  - 用 Playwright 在 DPR 1 与 DPR 2 下各渲染三态和保持态，尺寸 16px，浅色、深色两种主题；
  - 转成灰度后，计算星内部的填充像素比例：未亮 ≤ 0.1，半亮在 0.35–0.65 之间，亮 ≥ 0.85；
  - 任意两态之间的灰度像素差异都超过阈值（阈值在 lessons 记录）。
- [ ] **视觉回归**：符号样张页和星图页（合成数据，固定布局）在浅色、深色、reduce-motion 三种环境下截图，与已提交的基线比较，差异像素比例 ≤ 0.1%。
  - 基线首次提交要有视觉负责人签字，记录在 lessons；
  - 截图在固定版本的容器和浏览器里生成，页面不用网络字体，避免字体差异。
- [ ] **星光金不作装饰**：静态检查 `apps/web/src` 下星光金色值只出现在 `src/star/tokens.ts`，并且只被 `Star.tsx` 引用。
- [ ] **可访问性**：
  - axe-core 在星图页、样张页无 serious 或 critical 问题；
  - 列表视图的行数等于星数，状态文字与 `data-display` 一致；
  - 星空 `aria-label` 的计数与 `summary` 一致。
- [ ] **不缓存、不外链**：
  - 接口响应带 `Cache-Control: no-store`；
  - 构建产物（`.next/`）里找不到 `http(s)://` 外部资源域名（白名单只有空集合）；
  - 源码里没有 `localStorage` / `indexedDB` 调用，也没有注册 Service Worker。
- [ ] **许可证**：`license-check` 通过，锁文件里没有 `sharp`、`@img/sharp-libvips-*`，也没有任何 GPL、AGPL、LGPL 包。
- [ ] 严格模式 `make check` 通过；CI 跑 `web-test`。`web-visual` 在 CI 里跑，还是只在本地跑，按待人确认 #11 定。

## 待人确认
1. **三态映射与“待验证”阈值**（4-C 之前的默认规则）：
   - 默认按第 2 节的表：无记录 / `unseen` / `understand` → 未亮；`execute` / `stable` → 半亮；`transfer` → 亮；`retain` → 亮加外圈。只按 `state`，不看 `p_mastery`。
   - `confidence < 0.5` 时标“待验证”，只在列表与详情显示文字。
   - 另一个选择：4-C 之前一律不显示“亮”，防止被误读。默认不这样做，改用“原型 · 合成数据”水印。
2. **BFF ↔ 前端接口定义放在哪里**：
   - 默认 `services/bff/openapi/star-map.v0.yaml`，属于服务内部接口，不算契约；
   - 另一个选择是 `packages/contracts/openapi/`，与 learning-internal 并列，属于必停项。
3. **开发身份桩**：
   - 默认用 `STARBUDDY_DEV_AUTH=1` 加仅 loopback 加请求头 `x-dev-account-id`，4-H 删除；
   - 另一个选择是本冲刺先做最小的真实会话（短信验证码可以打桩），但这会把 4-H 的登录提前，超出原型范围。
4. **16px 的线宽与半亮的不透明度**：
   - 默认描边按图 2b 比例缩放，下限 1.5 CSS px；
   - 半亮按图 2b 用右半填充、不透明度 0.55。灰度测试不达标时改为不透明，由视觉负责人确认。
   - 视觉规范的“1 线”是否适用于星，请视觉负责人明确。
5. **符号资产与令牌来源**：
   - 默认本冲刺按图 2b 自绘 SVG，颜色写在 `apps/web/src/star/tokens.ts`；
   - 角色轨交付正式三态 SVG 与家族令牌文件后替换，替换时重做视觉基线。
   - 交付时间和交付方待定。
6. **对比度与深色主题**：
   - 浅色主题下，石灰描边对宣白只有 2.88:1，不到 3:1。默认把未亮星的描边色加深到 ≥ 3:1（由视觉负责人给色值）；在此之前，原型暂用鸦青 50% 不透明度作占位。
   - 深色主题下，默认鸦青描边改为宣白 60%。
   - 保持层外圈：默认 1px 鸦青（深色主题用宣白 60%），与星的间距 2px。这些都需要视觉规范补一条。
7. **哪些学科显示**：
   - 默认只显示 `subject_enrollment.status = 'active'` 的学科；
   - 另一个选择：`paused` 的学科也显示，但标“已暂停”，因为进展属于学生。
   - 没有选科记录的学生显示空状态文案“还没有选科”。
8. **一片星空包含哪些能力点、怎么布局**：
   - 默认包含该学科**全部**已登记的 `skill_node`，不按课程版本或年级筛选。现在阿鸦的课程版本是 `draft`，BFF 读不到版本行，而 `skill_node` 没有年级字段，也无从筛选。

   - 历史与道法同属 `zhixing`，平台没有字段能把它们分成两片星空。默认本冲刺只有“道法”一片；历史的分法（加子学科字段，或 local_id 前缀约定）留给教研与 4-H。

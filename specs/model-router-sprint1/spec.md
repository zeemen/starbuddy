# 冲刺 1-F：模型路由骨架（任务类型 × 数据级别、主备熔断、调用账本）

状态：**草稿，等人确认后才开始实现**。确认人、日期：＿＿＿
任务包：开发计划 v2.0 冲刺 1（W3–W4）E / F / I 行的 F：“模型路由骨架”，验收“可按配置切换供应商”。
关联：
- ADR 04（模型路由，草稿待签字）正文第 3 节与增补“按任务类型路由”（用户 2026-09-28 决定：生产与试点不出境，含 L0、L1）；
- ADR 09（数据驻留：L0–L3 定义、供应商登记）、ADR 06（计量账本）、ADR 15（输入通道与非大模型服务准入）；
- 《底层大模型选型建议 V1.0》九类任务 T1–T9；
- 下游：`specs/diandian-consistency-r2-sprint3/`（待人确认 #10：评测经路由调用）、`specs/persona-governance-sprint3/`（守卫经路由调用、只处理 L0）。

## 目标
平台里任何模型调用都只经一个路由入口：调用方声明任务类型与数据级别，路由按配置选主备模型、做超时重试与熔断，返回可追溯的 `model_version`，并留一条只含元数据的调用记录。
换供应商只改配置；任何配置、任何熔断路径都不会把请求发到境外。

## 现状
- `services/`、`adapters/`、`packages/` 里没有任何模型调用或路由代码；四科原产品各自持有 Key 与 BaseURL（ADR 04 §1.3），迁入不在本任务。
- `docs/compliance/vendors.md`（ADR 09 第 6 条）还不存在。
- 计量预留、结算、回滚在 BFF（0008、0009），计量 v2 的 `usage_ledger` 由 `specs/metering-v2/` 定。

## 设计要点

### 1. 位置与接口
- 放 `services/learning/learning/model_router/`（Python）：编排状态机在学习服务（ADR 01、03），点点与后台任务也从这里出；不开独立服务。
- 调用接口（进程内）：
  `route(req) -> Result`，其中 `req` 有：
  - `task`：T1–T9 之一，也就是教学对话、解题判分推理、识题手写、作文批改、口语评测、语音交互、检索、后台批量、内容安全与人设守卫；
  - `data_class`：L0–L3；
  - `subject`；
  - `prompt_template` 与 `prompt_version`；
  - `messages`；
  - `usage_id` 与 `idempotency_key`；
  - `deadline_ms`，可选。
  
  `Result` 有：
  - `output`；
  - `model_version`，格式为 `model:<供应商>/<模型>@<快照版本>`；
  - `source_version`，即 prompt 模板与版本；
  - `provider_attempts`，记录每次尝试的供应商与结果；
  - `usage`，即 token 或分钟数。
  
  插件 API 不变：任务类型由编排层按插件方法推出（ADR 04 增补待人确认 #3 默认）。
- 缺少 `usage_id`、`idempotency_key` 或 `prompt_version` 时直接拒绝（规则 3、4）。本任务只把它们传给供应商并写进调用记录，预留与结算仍由调用方经计量接口完成。

### 2. 配置与校验（启动时，失败即不启动）
- 路由表 `services/learning/config/model_routes.yaml`，按环境分节（dev、test、staging、pilot、prod）：
  - 每个任务配主选与备选，备选可以没有；
  - 每个供应商登记：`vendor_id`、驻留地（domestic / foreign）、协议类型、BaseURL 与 Key 的**环境变量名**（仓库里不放值）、白名单状态。
- 本仓库只提交 dev 与 test 两节。供应商只有：
  - 本地假供应商 `fake-a`、`fake-b`（测试用 HTTP 桩）；
  - 一个“OpenAI 兼容协议”的通用适配器。它是代码，不是具体供应商，没有 URL 与 Key 的值。
  
  staging、pilot、prod 三节留空，由人按白名单流程填写，属必停项。
- 启动校验，任何一条不满足就拒绝启动：
  - pilot、prod 两个环境不能出现驻留地为 foreign 的供应商（用户决定 2026-09-28），也不能出现白名单状态不是 approved 的供应商；
  - 每个 L2、L3 可达的任务，主选和备选都必须是 domestic；
  - 模型名必须是锁定快照：带日期或版本号，不接受 `latest` 或无版本的别名；
  - 主选与备选的厂商或平台不能相同（ADR 04 增补第 3 条）；
  - T7 检索的向量模型不配备选。
- dev 与 test 环境允许 foreign 供应商，但只接 L0 请求（ADR 09 第 5 条）。路由层按请求的 `data_class` 再过滤一次，这是运行时的第二道防线。

### 3. 运行时
- **选择**：按任务取主选与备选，先剔除数据级别不允许的，再剔除熔断打开的。
- **超时与重试**：
  - 每个任务配超时和最大重试次数；
  - 只重试可重试的错误（超时、429、5xx），同一供应商重试用同一个 `idempotency_key`；
  - 总时长不超过 `deadline_ms`。
- **熔断**：
  - 按供应商加任务计连续失败次数，达到阈值后打开，冷却期过后半开，放一个请求试探；
  - 打开期间切到**同一数据级别允许的**备选；没有可切换的，就返回 `ROUTE_UNAVAILABLE`，绝不回落到不允许的供应商（ADR 04 第 6 条）。
- **结果**：返回真实的 `model_version`，不写死 `"routed"`。供应商返回的模型标识与配置不一致时，按配置记录并标记差异（这种情况进日志告警）。

### 4. 调用记录（只元数据）
- 每次调用写一条记录，只有这些字段：
  - 任务类型、数据级别、学科；
  - `usage_id`、`idempotency_key` 的哈希；
  - 各次尝试的供应商、模型版本、耗时、状态；
  - token 或分钟数、成本估算；
  - `source_version`、时间。
- **不记录**提示词、对话原文、作答内容与素材（ADR 04 增补第 6 条），日志也不记这些。
- 本任务只定义记录接口，实现结构化日志与内存两种落地。落库表 `platform.model_call_log` 随计量 v2 的 `usage_ledger` 一起做，见待人确认 #2。

### 5. 本任务不做
- 接任何真实供应商、填任何 Key，也不写 staging、pilot、prod 的路由（必停项：新增第三方或模型供应商）。
- 把四科原产品的模型调用迁到路由层：迁移要重跑人设回归与判分评测（ADR 04 增补第 10 条），各科另起任务。
- 主备双模型判分不一致转人工（判分逻辑，必停项），以及 T9 守卫与危机转介的内容。
- 计量预留与结算、流式输出、ASR、TTS、发音评测等非文本协议：本任务只留任务类型，没有适配器。
- `docs/compliance/vendors.md` 的内容：只建模板和一条“未登记任何供应商”的说明，由合规负责人填写。

## 范围
### 做
1. `model_router` 包：数据类型、配置加载与启动校验、选择、超时重试、熔断（可注入时钟）、调用记录接口，以及 OpenAI 兼容通用适配器与假供应商适配器。
2. `services/learning/config/model_routes.yaml`：dev 与 test 两节，只含假供应商。
3. 测试（pytest，本机 HTTP 桩，不联网）：
   - 配置校验的反例：pilot 或 prod 出现 foreign、`latest` 别名、主备同厂、L2 可达任务配了 foreign、未登记供应商，各一条；
   - 同一请求改配置后走另一家；
   - 主选连续失败触发熔断，切到备选，冷却后半开恢复；
   - 没有可用备选时返回 `ROUTE_UNAVAILABLE`；
   - 缺 `usage_id`、`idempotency_key` 或 `prompt_version` 时拒绝；
   - 调用记录与日志不含提示词和输出原文；
   - **性质测试**：随机生成路由表、故障序列与请求，断言在 pilot 和 prod 下任何请求都不会到达 foreign 供应商，在 dev 和 test 下 L1 及以上的请求不会到达 foreign 供应商（ADR 04 第 3 节第 8 条，增补后扩到所有级别）。
4. 变异测试：去掉驻留地过滤、去掉启动校验、熔断后不过滤数据级别、允许 `latest` 别名，各一条，测试都要能发现。
5. `make` 目标 `model-router-test` 并入 `make check`。
6. `docs/compliance/vendors.md` 模板；ADR 04 的“实现状态”一行；lessons。

## 验收标准（可测试）
- [ ] 同一请求只改路由配置，就会发到另一家供应商，返回的 `model_version` 随之变化（v2.0 验收“可按配置切换供应商”）。
- [ ] pilot 和 prod 下，任何数据级别、任何熔断或重试路径的请求都不会到达 foreign 供应商（性质测试）；dev 和 test 下，只有 L0 请求可能到达 foreign 供应商。
- [ ] 违反第 2 节任何一条的配置都不能启动（反例逐条）。
- [ ] 熔断打开、半开、恢复可测；没有允许的备选时报错，不回落。
- [ ] 缺 `usage_id`、`idempotency_key` 或 `prompt_version` 时拒绝；结果带真实 `model_version` 与 `source_version`。
- [ ] 调用记录和日志不含提示词、对话原文、作答内容；变异测试全部被发现。
- [ ] 严格 `make check` 通过；安全审查、契约审查意见处理完。

## 涉及的必停项（见 CLAUDE.md）
- 新增第三方服务、模型供应商或数据出境路径：**本任务不新增**。只提交假供应商和一个没有地址、没有 Key 的通用协议适配器；真实供应商进路由表另起 PR。
- migrations、RLS、计量、contracts、人设 Prompt：否（调用记录落库见待人确认 #2）。
- 如果按待人确认 #2 选择本任务就落库，那就涉及迁移，PR 首行要写 `[NEEDS-HUMAN]`。

## 待人确认
1. **位置**：放在学习服务里做成进程内模块（默认），还是现在就起一个独立的“模型网关”服务？默认理由是编排在学习服务，而一个独立服务要多一套鉴权与部署。
2. **调用记录落库**：默认本任务只做日志与内存两种落地，`platform.model_call_log` 随计量 v2 的 `usage_ledger` 一起设计，避免两张账本口径不一。另一个选择是本任务就建表（迁移草稿）。
3. **dev 与 test 是否允许 foreign 供应商接 L0**：默认允许，只接合成数据（ADR 09 第 5 条、ADR 04 增补待人确认 #2 未决）。另一个选择是 dev 也不出境，那就只剩假供应商。
4. **通用适配器**：默认只写“OpenAI 兼容协议”一种。阿鸦现在用的 DeepSeek、DashScope 都兼容这种协议，但本任务不填它们。Anthropic 或其他协议的适配器暂不写。
5. **熔断参数默认值**：连续 5 次失败打开，冷却 30 秒，每个任务的超时（T1 对话 20 秒、T2 判分 60 秒、T8 批量 120 秒，其余 30 秒），重试 2 次。以后按真实供应商再调。
6. **判分任务要不要把主备都调一遍，对比结果**：默认本任务不做，只留 `dual_run` 配置位，默认关闭；不一致转人工属于判分逻辑（必停项），随判分 spec 定。

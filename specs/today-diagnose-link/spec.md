## 一、现状（2026-11-25 核对）——起草时发现的情况，先说清楚
- “去做”链接只在跨科有序列表里有（`src/today/OrderedTaskList.tsx`，开关 `STARBUDDY_TODAY_ORCH`；按科的 `TaskList` 没有链接）。地址由 `goHref` 决定：
  复测条目 → 复测页，再练条目 → 再练页，**其余（计划任务）→ 科目页**。诊断类任务因此跳到科目页，数学科目页上才有诊断入口（`specs/diagnosis-student-entry`）。
- **数学的今日计划现在不会出现“诊断”任务**：阿鸦适配器的 plan 对 `unseen` 节点不排任务（`adapters/aya/src/methods/plan.ts` 第 114 行
  “unseen 不排任务（应先诊断）”），只排 `practice`。
- 会出现“诊断”任务的是**道法与语文**：知行（`adapters/zhixing/src/core/plan.ts` 第 88 行）与文砺（`adapters/wenli/src/adapter.ts` 第 665 行）对没评估过的单元排
  `diagnose`。但这两科的诊断不是数学自适应诊断（学生端诊断页只有数学，`DIAGNOSIS_SUBJECTS = ['math']`），道法科目页目前是“即将开放”占位。
- 结论：按原建议（诊断类 + 数学 + 开关开 → 直达）实现后，**当前的今日计划里不会有任何一条链接变化**；它只在阿鸦开始给数学排诊断任务之后才起作用。

   道法、语文的诊断任务仍去科目页（那两科没有学生端诊断页）。
2. **测试**：`tests/today-orch.test.ts` 补用例：诊断 + 数学 + 开关开 → 诊断页；开关关 → 科目页；诊断 + 道法 / 语文 → 科目页；

## 三、冲突与需要人决定的事项

默认做法写在每条后面。

**决定记录（2026-09-27，用户）**：
- #1：v2.0 **没有**安排调整后的英语方案。3-D 继续搁置；v2.0 里的英语任务（ADP-英语-01、I 流的境内 ASR 与音素评测盲测、语音分钟计量、阶段 1 · 2 月的译林图谱能力视图接入）都不执行，等调整后的英语方案另起 spec。点点跨模型一致性（I 流里与英语无关的部分）照常。
  Gate 0 里与英语相关的两处——硬条件一“四科写入同一学生模型”中的英语、软条件“开口成章 ≥ 4/6”——本仓库不为它们准备证据，`/gate-check` 标为“英语搁置，需人定口径”，由 Gate 0 评审决定。
- #10：团队按**标准模式**。寒假封测数学 + 道法；数学、道法切片都在 Gate 0 过门；冲刺 1–4 的 K 流按标准范围写 spec。
- #2–#9、#11、#12：按下列默认做法执行。

1. **英语：搁置还是按 v2.0 接入？**
   2026-09-26 的决定是“英语课程重大调整，原先的产品开发先搁置”（`specs/adapter-echo-sprint3/lessons.md`）。v2.0（9 月 27 日）仍排了 ADP-英语-01（冲刺 3：grade 异步、diagnose、report）、I 流的 ASR 盲测与语音分钟计量、Gate 0 软条件“开口成章 ≥ 4/6”，并写明英语“不建 KGE 骨架，以译林图谱映射为能力视图接入”。
   - 默认：**3-D 保持搁置**，不写英语代码。v2.0 的英语安排是否就是“调整后的英语方案”，由产品负责人确认。
   - 连带：Gate 0 硬条件一“四科写入同一学生模型”与软条件“开口成章 ≥ 4/6”的口径。
2. **ADR 编号**。v2.0 把 09–12 分给星图定义、编译层 Git、判断账本唯一写入方、任务包格式；本仓库 09、10 已是数据驻留、境内托管。
   - 默认：已有编号不动，新增四份顺延为 11–14（`docs/adr/README.md` 已登记为“待起草”）。
3. **个人层表放哪个 schema**。KGE 数据模型把 attempt、evidence_event、mastery_estimate 放在 `kge.*` 个人层；SIE 说与它们“共用”；本仓库它们已在 `platform.*`（0004、0005），并被 RLS、计量、星图、渗透测试引用。
   - 默认：留在 `platform.*`，kge / insight 只放新增对象；在 W2 的 Schema v0.9 评审上决定，写进 ADR 02 的补充。迁移属于必停项。
4. **星的定义与已合并的 3-H 星图**。3-H 每颗星是一个 `platform.skill_node`（阿鸦 959 个节点）。v1.1 规定星 = 知识节点、能力坐标为能力视图，并新增“待验证虚线”（来自 `claim.status`）。
   - 观察：阿鸦登记进 `skill_node` 的 959 个节点就是阿鸦知识图谱的节点（`adapters/aya/content/pack.json`，K / S / M / P / C 五类，32 个专题；盘点时记为 939 个，去重实数 959，见 `specs/adapter-aya-sprint1/lessons.md`），按 KGE 第七章更接近 knowledge_node（其中 P 类可能对应易错节点，要教研确认）；“100 能力点”才是 v1.1 所说的能力视图。
   - 默认：3-H 代码不动。等 ADR“星图统一定义”与 KGE-01 骨架落地后，另开任务把星图的数据来源换成 knowledge_node，并加能力视图侧栏与待验证虚线（v2.0 冲刺 3-H 的验收项）。
5. **evidence_event 缺 evidence_kind 与 map_version**。v2.0 冲刺 1-C 的验收要求“含 evidence_kind、提示等级、地图版本”。提示等级在 `platform.attempt.hint_level_used`，不在 evidence_event 上；另两项都没有。注意 evidence_event 已有的 `kind` 列是载荷类型（response_text、verifier_trace 等 8 种），与 KGE 的 `evidence_kind`（independent / hinted / transfer / delayed_retest）不是一回事，加列时不能复用这个名字的语义。
   - 默认：并入 kge schema v0.9 草案一起评审，不单独出迁移。
6. **purpose_grant（用途分项授权）**。v2.0 放在 B 流 PLT-01，SIE 放在 insight schema。
   - 默认：跟随 #3 的决定；在合规顾问给出用途分项方案前不建表。
7. **判断账本与现有表**。`platform.guardian_report`（0006）与 SIE 的 `guardian_report` 同名，需核对语义是否一致；SIE 的 `self_report` 表（目标、痛点、偏好、兴趣）在仓库里没有对应，`platform.attempt.self_report` 只是作答把握度列，不要混用；各科已有的结论性表述按 v1.1 5.5“不迁移旧结论，只存档”。
   - 默认：SIE-00 字段字典起草时逐列核对，差异写进该 spec 的待人确认。
8. **冲刺 4 四份 spec 的前提变了**。4-C（掌握 v0）在 v2.0 里是 KGE-04，前提是 KGE-01 骨架（W3–W4）与 KGE-02 原子层（W5–W6）；4-H 的星图、4-G 的审核台同样依赖 K 流。四份 spec 都是按 v1.0 写的。
   - 默认：四份 spec 保留，状态改为“按 v2.0 待重审”，各自新增“开发计划 v2.0 的影响”一节（已加）。人确认第三节各项后再逐份改写，不在本 PR 改设计正文。
9. **已完成工作怎么记账**。v2.0 的 W1 在国庆后，本仓库已按 v1.0 完成冲刺 0–3 的大部分平台工作（第二节“仓库已有”）。
   - 默认：视为提前交付，按 v2.0 的完成定义补齐缺口（如 evidence_kind），不重做。
10. **团队模式（标准或精简）**。精简方案：寒假只做数学；道法切片与知行人设迁移移到 2 月；英语阶段 0 只做异步批改接入；Gate 0 的切片条件降为“数学切片过门”。这决定冲刺 1–4 的 K 流范围。
    - 默认：按标准方案写 spec，精简方案生效时再缩。
11. **KGE-00 盘点的数据源**。v2.0“本周就做”第 4 项要“获取四科库的只读权限”跑盘点脚本。本会话只有 `legacy/` 下的只读代码副本，没有任何一科数据库的访问权限，也不应连接非本机数据库（CLAUDE.md 规则 9）。
    - 默认：盘点脚本按“给人运行”的方式写：只读、只输出计数与结构，不输出任何学生数据；由人在有权限的环境里运行并回传报告。
12. **任务包与 spec 的关系**。v2.0 以“任务包”（目标、输入契约、验收测试、禁改范围）下发；本仓库以 `specs/<任务>/spec.md` 起草。
    - 默认：一个任务包对应一个 spec 目录，spec 首行写任务包编号；格式在 ADR“任务包格式与人审点”里定稿。

2. **选科模型（规格 §5；必停项）**：
   - 规格：核心包（语数英，不可拆）加选修槽 0 / 2 / 4 / 全部；
   - 仓库：`meter_subject_limit` 按“可同时开通科目数”（v2.0 蓝图的 1 / 2 / 4 / 7）判断。
   - 两者不兼容，而且核心包含英语，英语目前按决定 #1 搁置；规格又写“未上线科目不售卖”。
   - 默认：不改代码。需要人先定：
     - 英语搁置期间，核心包怎么卖（只含语数、英语上线后补入，或基本档暂不开售）；
     - 规格 §13 第 2 项“核心包是否可拆”。
   - 定了再改计量 spec 与 `plan_feature`。
3. **九科与学科编码（规格 §5）**：
   - 仓库的 `platform.subject` 是产品命名空间（wenli / aya / zhixing / echo），不是学科；
   - 规格按语、数、英、物、化、道、史、生、地九科建模，并带上线状态（planned / beta / live）与适用年级。
   - 默认：
     - 新增学科目录表（学科码、老师、上线状态、年级、是否核心），与产品命名空间建映射，不改现有枚举的语义；
     - 生物、地理按规格 §13 第 3 项“未立项”处理，不建老师角色（人设属必停项）；
     - 随下一版计量 spec 一起评审。
4. **计量单位（规格 §4、§7；必停项）**：
   - 规格的计量项：
     - 有效时长：按秒累计，静默 90 秒停表；
     - 实时语音分钟、白板讲评课、完整诊断、整卷模考；
     - 上传次数：一个文件一次，PDF 每 4 页一次，24 小时内同哈希不重复扣；
     - 存储总量、按需深度报告。
   - 仓库的 `resource_type` 有 diagnosis_screen、diagnosis_full、mock_exam、mistake_analysis、lesson_whiteboard、voice_realtime、ai_active_time，没有上传、存储与深度报告。
   - 默认：下一版计量 spec 对齐编码与折算规则，保留已实现的预留、结算、释放、过期与账本推导余额（与规格 §8 的三条关键约束一致）。
   - 学时结转 20% 属于规格 §13 第 5 项待拍板，不实现。
5. **单日上限、宵禁、单一活跃 AI 会话、设备上限（规格 §7、§12.2）**：
   - 这些是新的服务端规则，也回应《人工智能拟人化互动服务管理暂行办法》的时长保护：
     - 单日上限默认 60–180 分钟，家长可调低；
     - 22:00–6:00 默认不提供 AI 互动；
     - 两端合并计时，APP 退后台 30 秒停表；
     - 学生最多 3 台设备，监护人最多 5 台。
   - 默认：并入下一版计量 spec 与 PLT-01 修订；计时以服务端为准。
6. **账号与家庭（规格 §2；必停项：RLS 与权限策略）**：
   - 规格：
     - 一个家庭 1 位主监护人（付费人）、最多 2 位协同监护人，协同监护人不能下单、选科、导出删除；
     - 学生可以没有手机号，用“家庭码 + 4 位 PIN”登录，连错 5 次锁定 15 分钟；
     - 后台人员按岗位 RBAC，查看学生数据写审计日志；客服看订阅、不看学习证据。
   - 仓库：
     - `guardian_student_link` 按家长逐一绑定学生，没有主 / 协同角色；
     - 只有家长账号有联系方式；
     - 没有学生登录方式与审计日志表。
   - 与规则 5（按档案授权、不按手机号关联）一致。
   - 默认：PLT-01 修订时加家庭内角色、学生 PIN 登录与锁定、后台审计，附 RLS 测试与渗透测试用例；协同监护人上限与权限按规格写成待人确认。
7. **支付与预收费（规格 §6、§12.3；必停项：第三方服务、计量与权益）**：
   - 渠道：微信支付、支付宝、苹果 IAP；
   - 学期、学年一次性收费有预收费监管风险：线上学科类培训一次不得超过 3 个月或 60 课时；
   - 规格把价格承诺与扣款计划拆开。
   - 默认：
     - 取得书面法律意见前不接任何支付渠道；
     - 数据模型先按规格把 `price_lock` 与 `billing_schedule` 分开，下一版计量 spec 起草；
     - 对外文案统一用“AI 陪练时长”，不用“学时 / 课时”。
8. **原图保存期限冲突**：
   - 规格 §7 写“原图在完成识别后 90 天可按家长设置自动删除”；
   - 技术蓝图 v2.1 §7 建议“批改完成后保留 30 天用于申诉”。
   - 默认：取较短的 30 天，由法务定（第七节 #4）。
9. **手机 APP（规格 §12.6）**：
   - 规格：React Native（Expo）；pnpm + Turborepo 单仓，含 `apps/mobile`、由 OpenAPI 生成的 `packages/api-client`；
   - 以下都是新增第三方与原生模块：
     - 苹果 IAP 自建服务端校验；
     - 微信、支付宝 SDK；
     - 国内厂商推送；
     - 自建热更新。
   - 隐私弹窗必须先于任何 SDK 初始化。
   - 仓库现状：`apps/web` 是 Next.js（PWA），`services/bff` 用 npm。
   - 默认：
     - 另起 spec（PLT）引入 `apps/mobile` 与单仓工具，先核许可证（规则 10）；
     - 第三方 SDK 各走一次必停项确认；
     - BFF 的 OpenAPI 作为两端唯一接口来源，与本仓库“契约先行”一致。
   - 在此之前不改仓库结构。
10. **模型供应商与路由（选型建议 §1–§3；必停项：新增模型供应商）**：
    - 与 ADR 04（按数据级别路由）、ADR 09（数据驻留）、ADR 10（境内托管）方向一致；
    - 新增三点：
      - 按任务类型 T1–T9 路由，路由键变为“任务类型 × 数据级别”；
      - 锁定带日期的快照版本；
      - 调用账本关联计量账本。
    - 已有契约的 `ModelVersion`（`model:<供应商>/<模型>@<版本>`）能承接快照版本。
    - 默认：
      - 起草 ADR 04 增补（只起草，不签供应商）；
      - 百炼、方舟、讯飞的接入等合同与备案 / 登记路径确认后再做；
      - 生产链路不出现境外模型（规则 13 已要求个人层只用境内已备案模型）。
11. **四科迁出 Anthropic 与人设回归（选型建议 §6；规则 7）**：
    - 提示词换模型后要在新模型上重跑人设与判分评测；
    - 任何人设 Prompt 变更都要跑 `evals/persona` 并附前后对比，属于必停项。
    - 默认：迁移按科另起任务，先建南京中考评测集（选型建议 §7）；评测集的金标部分由教研标注，构建方只读。
12. **拟人化互动服务的合规要求（选型建议 §1）**：未成年人模式、时长提醒、防沉迷、情感依赖识别。
    - “情感依赖识别”与规则 12（不推断持续的情绪状态）有张力。
    - 默认：只在会话内由内容安全守卫（T9）识别并处置，不写入判断账本、字段字典或任何画像视图；危机信号转人工与监护人通知（与点点规格书 4.9 同一口径）。
    - 需人与合规顾问确认。
13. **不按会员等级换判分模型（规格 §4 注、选型建议 §3）**：各档教学与判分质量一致，路由不按等级选模型。
    - 默认：写进 ADR 04 增补与计量 spec 的约束。现有契约没有按等级区分的字段，保持。

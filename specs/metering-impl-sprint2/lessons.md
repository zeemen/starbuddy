## 待人确认
1. **spec 需要具名补签**（见“确认记录”）。本 PR 首行写 `[NEEDS-HUMAN]`：涉及迁移、RLS、计量逻辑、新角色、新依赖、新表。
2. **基础会员与试点额度会无限续期**：
   - trial 每 30 天自动续期，也就是永久免费的基础会员，这是否符合产品意图？
   - 试点在名单的 `ends_at` 之后结束，名单由谁维护、试点结束后是否自动转为基础会员，都待定。
3. **家长能否限制孩子选科**：现在学生本人和已绑定家长都能选科、暂停，与 schema v0.9 相同。
4. **过期后同 key 重试会在没有预留的情况下执行一次**（N17）：学习服务会接管之前失败过的 key 并重新执行。现在由指标 `reexecuted_without_reservation` 暴露，要彻底堵住，需要学习服务提供只查询的重放接口（契约变更）。
5. **学习服务的 5xx 语义**（N18）：BFF 已按“5xx 一律结果未知”实现。学习服务对提交阶段出错返回 500 `INTERNAL`（`retryable: false`），建议改成 `retryable: true`，并在契约里写明。这是学习服务和契约的改动，不在本 PR。
6. **BFF 超时与学习服务等待时长不匹配**（契约守护 M7）：
   - BFF 的超时：grade 15 秒、diagnose 35 秒；
   - 学习服务遇到同 key 执行中的请求会轮询等待，最长 95 秒；
   - 所以 BFF 通常先超时，然后同 key 重试，在学习服务那边多出一个等待者。

   要么让学习服务的等待上限小于 BFF 的超时，要么 BFF 遵循 `retry-after`，需要一起定。
7. **多个额度桶各自不够、合计够时返回“额度不足”**：一笔预留只落在一个桶上，返回的 `remaining` 是合计数，前端展示要注意。附加权益上线前再定是否拆单。
8. **没有有效订阅就不能选科**：注册流程必须先开通基础会员。`all_launched` 在没有任何已发布课程时等于 0。
9. **结算数量由 BFF 决定**：数据库只校验 0 到预留数之间。以后的 BFF 接口绝不能让前端决定结算数量，也不能让前端直接结算或释放。
10. **pgcrypto**：
    - 从 PG13 起是 trusted 扩展，有建库权限就能启用，不需要超级用户（spec 待人确认 #3 的说法不准确）。
    - 如果目标库已经在别的 schema 装过 pgcrypto，迁移直接使用它，并把该 schema 的 USAGE 授给 authz 和 bff；回滚时不会收回这项授权。

## 实现中的发现
- **授权断言被别的原因顶替**：“家长不能替孩子结算”一开始是因为 BFF 没有 `meter_usage_id` 的执行权限才失败的，授权检查根本没被测到。所有函数授权断言都已改用 `t.throws_like` 核对 `not permitted`。
- **复看的 advisory 锁曾被误删**：理由是“同学生同资源已经被额度桶锁串行化”，但在周期边界上，新旧两组额度桶互不阻塞（契约守护 M3），已恢复。
- **“结算不先锁额度桶”的变异无法被发现**：过了过期时间就不能结算之后，结算和过期任务不会再同时修改同一笔预留，所以现在先锁额度桶只起防御作用，保证全局加锁顺序一致。这条变异已从 BFF 变异集中删掉，这里记下原因。
- **“过期任务加锁后不重查状态”同样测不到了**：原因同上，也已删除。重查的代码保留。
- **TS 的规范化**：
  - Python 按码点排序键，JS 默认按 UTF-16 码元排序，两者在 U+FF5E 与 emoji 之间结果不同，已有向量覆盖；
  - `1e21`、`2^53` 这类值在 JS 里是整数、在 Python 里是浮点数，表示不同，TS 直接拒绝超出安全范围的整数；向量里去掉了这类值。
- **变异测试并行化**：每个变异各起一个一次性 Postgres，用 `DBMUT_JOBS` 控制并发数，默认等于 CPU 核数。原来串行约 15 分钟，会超出 CI 的 20 分钟时限。
- **一次性 Postgres 抽成 `db/tests/pg-ephemeral.sh`**：db-test、BFF 集成测试、BFF 变异测试共用。

# LT-01 上线测试 · 部署打包（W1，specs/launch-test-2026）

2026-10-19 起由 Claude 推进。目标：让全部服务能以容器形式在境内 staging 部署，配置与密钥注入规范统一，迁移可在副本上演练与执行，**不含任何真实凭据、不连接任何真实环境**（规则 9）。零迁移内容变更、不改契约、不改业务逻辑。

## 范围
1. **生产镜像**：BFF（services/bff）、学习服务（已有 Dockerfile，复核）、洞察服务、知识服务、调度器、三科适配器（aya、zhixing、wenli）、前端（apps/web，Next.js standalone）。要求：多阶段构建、非 root、只读根文件系统可运行、健康检查端点、锁定基础镜像版本、无构建期密钥、`.dockerignore` 排除 .env / 测试夹具 / legacy。
2. **配置与密钥规范**：`deploy/config/README.md` + 每个服务的环境变量清单（名称、用途、是否密钥、缺省值、哪些只允许 dev/test）；生产 / staging 启动时拒绝合成配置与开发开关（复用各服务已有校验，缺的补上并测试）。
3. **编排草案**：`deploy/compose/staging.yaml`（本机可起的全栈，用于验证镜像与依赖顺序）与 `deploy/k8s/` 或云厂商无关的清单草案（Deployment / Service / 探针 / 资源限制 / 出网白名单注释）；不绑定具体云厂商。
4. **迁移执行器**：`deploy/migrate/`——按序执行 db/migrations、记录版本表、支持“副本演练”模式（先在快照副本上 up → 校验 → down → up）、执行前打印将执行的迁移清单并要求显式确认参数；不内置任何连接串。
5. **功能开关矩阵**：`deploy/flags/staging.yaml`——按上线测试范围（数学、道法、语文批改；今日计划、诊断、再练、复测、星图、信任界面、周报、对账卡、审核台；模考、月度计划、讲评白板、知识缓存保持关），并有测试核对矩阵中的开关名都真实存在。
6. **验证**：本机用 compose 起全栈（合成数据、假模型供应商），跑现有 release-walkthrough 或端到端走查一遍；镜像构建与扫描脚本（不联网下载新依赖之外的东西）；make 目标 `deploy-check`（构建 + 静态校验 + compose 冒烟）接进 check 或单列（若过慢则单列并说明）。

## 不做
- 真实云资源、真实密钥、域名、证书、ICP；真实模型供应商接入（LT-02）；改业务逻辑与迁移内容。

## 验收
- 全部镜像可构建、非 root、健康检查通过；compose 全栈在本机合成数据下走查通过；迁移执行器副本演练模式在一次性库上通过；开关矩阵测试通过；严格 make check 通过。

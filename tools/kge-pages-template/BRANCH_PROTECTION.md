# 页面仓库分支保护设置清单（执行人逐条设置并截图留档）

依据：KGE V1.1 第八章“主分支保护，CI 程序体检不通过不能合并；教研只通过合并请求网页界面或最简审核台修改，不在本地直接提交”；
第四章分级发布闸门；ADR 12（草稿，托管平台待 #1、审核类别待 #2）。

| # | 设置 | 要求 | 核对 |
|---|---|---|---|
| 1 | 保护分支 | `main` 受保护，禁止直接推送（含管理员） | ☐ |
| 2 | 强制推送与删除 | 禁止对 `main` 强制推送、禁止删除 `main` | ☐ |
| 3 | 必须通过的检查 | CI 任务“kge-lint”（`main` 的 `ci/lint.sh`，见第 14 条）必须通过才能合并；检查失败或未运行都不能合并 | ☐ |
| 4 | 检查基于最新 | 合并前分支必须基于最新 `main`（过期的合并请求要先更新再跑体检） | ☐ |
| 5 | 审核人数 | 默认至少 1 人批准；合并请求说明写明“审核人数：2”（高风险、全量重编，阶段 0 中风险同）时至少 2 人批准（平台支持按标签或路径设规则时用 `risk:high` 标签） | ☐ |
| 6 | 作者不能自批 | 提交者的批准不计入审核人数 | ☐ |
| 7 | 新提交撤销批准 | 批准后再有新提交，已有批准作废 | ☐ |
| 8 | 编辑方式 | 教研账号只经网页界面或审核台改页面；不发本地推送凭据给教研账号 | ☐ |
| 9 | 机器人账号 | 编译器的推送账号只能推 `compile/*` 分支、只能开合并请求，不能批准、不能合并 | ☐ |
| 10 | 合并方式 | 只允许普通合并或压缩合并，保留合并请求编号（页面版本与提交号的映射按 ADR 12） | ☐ |
| 11 | 仓库可见性 | 私有；成员只含编译层相关教研、执行人、机器人账号 | ☐ |
| 12 | 个人信息 | 页面仓库只放公共层页面；作答、笔记、错因、学情档案页永远不进入（规则 13），体检的个人信息模式检查必须开启 | ☐ |
| 13 | 代码所有者与路径规则 | 启用 `.github/CODEOWNERS`（GitLab 放根目录或 `.gitlab/CODEOWNERS`）并打开“要求代码所有者审核”：`ci/`、`.github/`、`.gitlab/`、`.gitlab-ci.yml`、`snapshots/`、`lexicon/`、`CODEOWNERS` 的任何改动必须由**平台负责人**批准；教研与机器人账号不是这些路径的所有者 | ☐ |
| 14 | 体检的信任边界 | CI 里 `ci/lint.sh`、地图快照 `snapshots/current.yaml`、人设词表 `lexicon/lexicon.json`、上一审核版一律取自 `main` 的检出；合并请求头部只提供 `pages/`（样例见 `ci/*.example`）。合并请求里对 `ci/`、`snapshots/`、`lexicon/` 的改动不参与本次体检，只能靠第 13 条审核 | ☐ |
| 15 | 合并请求任务不带凭据 | 体检任务不引用任何 secrets 或受保护变量；检查工具取固定版本的预构建只读制品（`ci/install-tools.sh` + `ci/kge-tools.pin`，核 sha256，pip `--require-hashes`），不在任务里用令牌拉 StarBuddy 仓库。GitLab 的 `CI_JOB_TOKEN` 无法去掉：作业令牌访问范围限定为本项目、不加白名单 | ☐ |
| 16 | GitHub 触发器 | 只用 `pull_request`（不向合并请求暴露 secrets，`GITHUB_TOKEN` 只读）；**不得**用 `pull_request_target` 检出或运行头部代码；平台支持时改用组织级规则集的“必需工作流”（放在受保护的中心仓库）。GitLab 同理：平台支持时把 CI 配置文件指向受保护的中心项目或用流水线执行策略 | ☐ |
| 17 | 固定版本 | 工作流里每个 action 固定到完整提交 SHA、镜像固定到 sha256 digest（样例中的 `0000…` 是占位，启用前必须替换）；检查工具版本只在 `ci/kge-tools.pin` 改，改动走第 13 条 | ☐ |
| 18 | 地图升版的顺序 | 先合并只改 `snapshots/current.yaml` 的请求（平台负责人审核），再合并编译器随之开出的重编请求；两者之间其他页面请求会因 `map_version` 与 `main` 的快照不一致被阻断，知识服务对落后的页面回 404（`page.get` 只服务与已发布地图版本一致的页） | ☐ |

低风险合并窗口（每页每天最多发布一次）由编译器分组保证；平台侧不需要额外设置，但不要开“自动合并所有通过检查的请求”之外的绕过规则。
